# Motion 目标 布局与控件接入

本文拥有[Motion 系统](overview.md)的目标能力、无 Actor 执行、内容视口和业务宿主接入。
运行身份、终态和资源释放由[播放协议](playback-and-lifecycle.md)定义。

## 无 Actor 目标

PlayAsync 接受真实 Control。目标不需要继承专用基类、实现通用 Actor 接口或额外包装 ContentControl。
内容承载留在真实模板，单次执行状态是内部运行数据，不成为视觉节点。

纯视觉动效优先复用已有 Panel、Border、ContentPresenter 等节点。需要隔离应用变换、独立裁剪或占位时，
模板静态提供职责明确的边界；运行中不重挂载内容或改变逻辑父子关系。
既有命名节点及 Semantic Part 专用 Style 必须按真实树拓扑同步，不能改用 code-behind 样式赋值绕过。

Motion 不统一设置 ClipToBounds。阴影、装饰、溢出与内容视口的裁剪链各有 owner；绘制和命中使用同一几何合同。
目标的默认测量、布局对齐和输入不能因原生/合成路径不同而产生隐式差异。

## 执行能力选择

| 职责 | 路径 | 选择前提 |
| --- | --- | --- |
| 平移、缩放、旋转 | UI 线程逐帧写入目标 CompositionVisual 的 Translation / Scale / RotationAngle / CenterPoint | 客户端值即当前呈现值；完成由运行时钟判定；命中经合成回读 |
| 透明度与类型化属性 | 带所有权的 Animation 优先级属性写入 | 可撤销覆盖，绑定与主题继续更新 |
| 自然内容展开、侧栏占位 | 原生进度与布局能力 | 几何、裁剪、命中和父布局正确 |
| 普通状态外观过渡 | ControlTheme 原生 Transition | 资源绑定、状态初始化与过渡声明保持明确 |

路径在准备时确定，应用不必选择后端。未知能力不能静默视作支持；缺口进入能力验证或明确错误路径。
不能可靠读取呈现值、完成或处理命中的合成组合，不得仅为速度进入合成路径。
运行中跨后端切换必须满足完整交接，不能让两个 transform 来源互相遮蔽。

每次播放由 MotionFrameDriver 直接订阅框架全局动画时钟（与 Avalonia Animation 相同的时钟与首帧语义），
不再经由 Animation、关键帧和进度属性；不建立第二套周期计时。平台提供呈现时间预测时（当前仅 Wayland 适配器），
每个脉冲按“该帧预计上屏时间”采样：目标仅在渲染器开始绘制含上次提交内容的帧之后推进一个刷新，其余脉冲不写入；
空闲渲染器在起始时连画两帧导致的首帧重复，以一次起点顺延吸收（仅首次推进，至多 2 个刷新），不用后续跳帧追赶。
采样时间单调；不提供预测时使用脉冲时间。播放期间若某一帧没有写入（延迟段、数值不变），
驱动仍请求一次合成提交，避免 MediaContext 退回不对齐刷新的 16ms DispatcherTimer。
变换通道不使用 RenderTransform：UI 同步只写 Offset/Size/Opacity/TransformMatrix，不覆盖上述合成通道，
因此逐帧不触发 InvalidateVisual 或绘制指令重录。每个合成通道每个 visual 只有一个所有者；替代请求直接接管共有通道，
旧请求释放时只把仍属于自己的通道恢复为首个动效前的基线。
合成批次已提交、已处理、已绘制与动画结束是不同事件，完成能力需在验证状态中独立登记。

## 布局能力

Core 定义自然内容、占位和视口所需的独立布局能力合同，具体布局原语属于 AtomUI.Controls。
第三方布局实现通过该公开能力接入，不依赖 Desktop 友元或内部 Actor。普通 Control 不默认支持布局通道。
当前公开合同为 `IMotionLayout.BeginLayoutMotion(Direction, bool expanded)`，返回可释放的 `IMotionLayoutLease`；
租约以 `SetProgress(double)` 接受时间进度。第三方继承与编译 AXAML 消费已验证，NativeAOT 消费仍需专项验证。

内置实现为 `AtomUI.Controls.Primitives.ContentViewport`，继承 ContentControl，保留 ContentTemplate 与延迟物化。
它只负责布局能力，普通透明度和变换播放不需要这个视口。

布局原语的职责是测量内容、报告占位、约束实际视口和排列完整内容。它不承担一般 Motion、业务事件、Follow 或后台任务。
没有能力时拒绝布局通道，不能替换为视觉缩放而改变占位、文字和点击区域。

## 内容几何

自然内容使用正常展开时的有效宿主约束，单位为 DIP，不使用每帧缩小的视口作为排版宽度。
内容按自然尺寸排列，动画改变占位和实际 Bounds/视口；交叉轴遵守原模板约束。
自然尺寸受内容、字体、padding、边框、宿主约束、方向和嵌套内容尺寸变化影响，失效按布局轮次合并。
动画视口自身变化不自动构成自然测量约束变化；宽度真实变化导致换行时，必须重新排版。

期望占位与实际视口分别处理：固定父布局可能分配大于 DesiredSize 的空间，实际命中边界仍必须受进度约束。
Margin、Min/Max、完整内容边框及间距属于各自原有 owner，不通过改根控件尺寸或补偿边框制造终态。

以主轴可见长度 v、完整内容长度 L 表示，Down/Right 内容起点为 0，Up/Left 起点为 v-L。
启用布局舍入时先取得实际像素视口，再由同一尺寸计算尾边锚点，避免独立舍入导致反向时文字跳动。
自然内容、占位和真实视口共享进度；透明度与尺寸共享时间基准。内容变更时从当前呈现值重定向，保留原截止时间。

同一手风琴切换由业务 owner 同步提交旧项关闭与新项打开；视口在同一动画帧开始交换空间，不等待新项完成才关闭旧项。
有限反向使用新请求的有效时长；同一请求内动态目标变化不通过重启时长无限延长父动画。

由隐藏状态开始展开时，显示隐藏 owner 在设置 IsVisible 前取得首段展开布局租约，并保持准备阶段透明度为零。
播放取得自己的布局租约后再释放准备租约，避免就绪边界之间出现完整自然高度的临时占位。
准备失败时先释放临时透明度与布局租约，再按当前业务目标恢复稳定状态。
定义准备遵守无写入合同；布局目标的展开准备和实际播放准备可以分别执行，不能依赖 Build 的外部副作用。

## 输入与滚动

裁剪必须同时约束绘制和交互。验证保留原有限高、标题、滚动条、嵌套 ScrollViewer、滚动链和内容规模。
viewport、extent、offset 与边界滚动传递仍由原滚动 owner 管理，Motion 不接管滚动选择模型。
不能仅因合成方便而一律禁用入场期间输入；方向、移动与缩放后的实际点击位置需按组件合同验证。

## Popup 与展示准备

Popup 在物理宿主显示前建立完整初始状态，避免目标出现一帧全不透明后再隐藏。
就绪准备使用真实布局/目标事件，不使用固定 Delay。底层未就绪立即 NotReady，owner 可在一次布局后重试或稳定收敛。

离场期间保留宿主；当前离场完成、目标身份仍一致且业务关闭意图有效时才执行 CloseCore。
无法播放时按稳定关闭流程处理，不等待不会到达的动画事件。关闭期间反向打开使旧关闭请求失效。
焦点、遮罩、light-dismiss、业务 Opened/Closed 和销毁仍归 Popup/Dialog/Drawer。

## 既有消费者

| 消费路径 | 必须保持的合同 |
| --- | --- |
| NavMenu | 侧栏真实占位、正文联动、选中路径、子菜单互斥及首尾帧 |
| Collapse/Expander | 自然内容、四方向锚定、标题/边框/间距、滚动和有效完成 |
| TreeView 及派生树节点 | 子项占位、命中、键盘、反向和模板替换 |
| BackTop | 快速显隐可替代，取消不遗留方向 guard |
| Message/Notification | 堆叠布局、有效时长、hover 与卡片生命周期 |
| Dialog/Drawer/Popup | 原点、阴影、遮罩、物理宿主、首帧与业务事件 |

旧布局 Actor 在对应消费者完成几何和输入验证后删除。内置默认轨迹校准与保持外观的性能优化分别记录，
不能将视觉规格变化隐入类名替换或普通整理。
