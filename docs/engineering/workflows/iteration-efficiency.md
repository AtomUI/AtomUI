# 工程任务迭代与收敛

本规范适用于后续研发、修复、主题迁移和验收任务。目标是减少重复工作并持续交付完整结果，不降低测试、AOT、视觉、生命周期或用户审查标准。

## 执行顺序

1. 先核对任务范围、既有实现与批准，建立有限完成清单：真实缺陷、已完成且证据有效、待用户裁决、平台或后续任务归属。每项写清完成判据和实际依赖，不使用无界验收目标。
2. 优先恢复原始复现或已有驱动，保留数据、尺寸、状态及完整历史。新最小模型必须对应一个具体假设，说明唯一变量和判定结果；不能用近似模型的成功替换原失败。
3. 开发期先运行能检错的精确用例。真实功能、状态、键盘/指针/关闭、滚动裁剪和资源退出缺陷优先修复；绘制或平台调查只阻塞对应未通过范围。
4. 同一假设3次无效实验或30分钟无新增可判定证据，停止当前分支并复核假设。用一段简报记录阻塞，推进其他不依赖工作；没有新线索不继续复制模型，不把调查超时当完成或归属批准。
5. 同一依赖组源码稳定后，合并必要的昂贵验证。先模块检查，再按实际风险集中NET8/AOT/渲染/原生宿主验证；同一有效产物参数化运行相关场景，不逐小实验重新发布。
6. 核对验证输入身份：相关源码、依赖版本、目标框架/RID、构建配置、宿主和场景历史。身份匹配且结果有效就复用；变化只触发对应验证，不自发扩大到全量。
7. 完成临时测试、驱动、媒体及专用产物清理，再执行项目要求的精确模块门禁。没有临时编译输入变化且现有程序集身份匹配时可复用该产物，不能使用陈旧程序集冒充清理后验证。
8. 正式文档更新最终行为。每个缺陷/依赖组只保留一份详细证据记录；CSV、总表和任务表同步状态与链接，不重复粘贴全过程。审批集中记录原话、范围和请求ID，其他入口引用。

## 诊断与批准边界

- 成功的模块或字段验证不能自动关闭整个家族；反过来，局部绘制调查也不能无限阻塞其他已授权工作。
- 不同性质的结果分开：性质检查通过、严格像素失败、完整历史兼容、原生输入、其他平台未覆盖，各自按实际证据报告。
- 框架独立反例与真实场景不完全一致时披露差别；没有明确证据/批准不得擅自移动任务归属、扩大容差或删去原失败。
- 原合同确实要求的未通过项继续阻塞对应出口。若只能等待用户裁决，先完成可审查材料，异步申请一次并继续独立工作；不在每个分包后问是否继续。

## 进度与估时

进度只报告已取得的结果、实际剩余及下一项实验/修改将解决什么。避免没有新证据的长篇分析和反复复述流程。

估时依据有限剩余清单，明确哪些是可估的实现/验证，哪些是原因未明的调查。不能用未经核对的“几小时/几天”承诺替代剩余项审计。偏离估计后先调整方法，不能原样追加实验和发布轮次。

本规范与[精确影响验证](affected-verification.md)、[测试价值与生命周期](../development/test-value-and-lifecycle.md)、[AI协作规范](../contributing/agent-guidelines.md)共同生效。用户关于当前分支、worktree、提交、子agent和回归范围的明确约束始终优先。
