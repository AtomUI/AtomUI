# AtomUI 6.2.8 迁移指南

[English](6.2.8-api-changes.md)

6.2.8 修复 DashedBorder 缩放、Windows 10 CSD 顶边与 ImagePreviewer 连续旋转，并放宽 TypeMap 工具链支持范围。
Avalonia 仍为 12.1.4，Release 产品包继续提供 net8.0 和 net10.0。

## 速查表

| 范围 | 6.2.7 | 6.2.8 / 迁移方式 |
| --- | --- | --- |
| 生成式注册组 | 公开 `ControlPackageGroup_*` 类型名包含 6.2.7 程序集标识 | 改为 6.2.8 标识；同步升级包并重新构建预编译消费方 |
| Window Token 枚举值 | 既有自有 Token 槽位未包含新增边框 Token | 名称排序插入两个槽位；重编译自定义主题和资源消费方，并使用具名成员 |
| Browser TypeMap 发布 | 要求 SDK 10.0.300、ILLink 10.0.8 与 WASM tasks 10.0.10 | 默认支持 .NET 10 及后续稳定版本，使用 SDK 选择的工具，保留转换与产物验证 |
| 现代桌面 TypeMap 工具 | 匹配目标框架，最低 10.0.8 | 继续匹配目标框架，最低改为 10.0.0 |
| 构建工具运行时 | 使用 `LatestPatch` 前滚 | 改为 `Major`；后续 SDK 环境不必额外安装原 .NET 10 工具宿主 |
| 控件方法与包布局 | 既有控件方法、包 ID、net8.0/net10.0 与构建资产路径 | 未移除现有控件方法、目标框架或构建资产路径；Window Token 枚举值变化见下文 |

## 重新构建生成式注册消费方

生成器将包含版本的包程序集标识哈希到公开 `AtomUI.Generated.*.ControlPackageGroup_*` 类型名中。
因此，升级包版本会改变生成类型名，即使正式注册方法签名没有变化。引用旧注册组的预编译消费方，
不能只替换 AtomUI DLL 就绑定到新注册组。

1. 将相关 AtomUI 包及显式引用的 Generator 一起升级到 6.2.8。
2. 清理并重新构建消费生成式注册元数据的应用与自定义控件包。
3. 重新发布裁剪与 NativeAOT 应用，使依赖分析使用新注册组。

继续使用正式的 `UseAtomUI` 与包配置入口。不要直接引用生成注册组类型名，也不要将 6.2.7 的预编译注册元数据
与 6.2.8 包集混用。本版不在 6.2.7 基础上增加启动回调或应用资源的迁移要求。

这是相对 6.2.7 的有意二进制不兼容。包 API 比较必须如实报告生成标识变化，不增加兼容性抑制，
也不宣称完整二进制兼容。包布局另行校验。

## 重新编译 Window Token 消费方

新增的 `FrameBorderActive` 与 `FrameBorderInactive` 按名称顺序插入生成的自有 Token 枚举。
现有成员名称仍可使用，但数值发生变化：

| 成员 | `WindowTokenKind` 6.2.7 → 6.2.8 | `WindowTokenKey` 6.2.7 → 6.2.8 |
| --- | --- | --- |
| `FrameShadows` | 3 → 5 | -4 → -6 |
| `FullscreenHeaderFramePadding` | 4 → 6 | -5 → -7 |
| `FullscreenPopoverShadows` | 5 → 7 | -6 → -8 |
| `SystemBarColor` | 6 → 8 | -7 → -9 |
| `TitleBarHeight` | 7 → 9 | -8 → -10 |

请重新构建自定义主题、预编译 AXAML 字典及使用这些枚举的代码。枚举常量会写入编译后的消费方，
只替换运行时 DLL 可能命中错误的资源。继续使用 `WindowTokenKey.FrameShadows` 等具名成员，
不要持久化或硬编码枚举整数。已经存储 Token 数字的应用，须依据原成员名称和上表迁移。
全局 Token 槽位与前三个 Window 自有 Token 槽位保持不变。

## TypeMap 工具链支持

现代 TypeMap 发布默认支持 .NET 10 及后续稳定版本。Browser 发布不再要求固定 SDK 功能带、补丁版本、
链接器完整构建号或 WASM 任务版本。保持 SDK 默认选择的工具链即可，本次调整不要求配置后端路径或兼容开关。

Browser 后端仍校验实际官方链接器身份、Mark/Sweep/Output 顺序、注册 ABI、转换后的映射，以及 AOT 或打包实际
消费的文件。工具版本与文件内容仍进入增量签名。后续版本默认准入，不表示每个后续链接器实现都经过测试；
真实转换、ABI 或产物验证失败时仍会停止发布，需要针对实际不兼容进行适配。

现代桌面裁剪/NativeAOT 仍要求实际工具匹配目标框架，最低版本改为引入 TypeMap 的 10.0.0。
独立的 .NET 8 后端与消费 net8-only 包的桥接仍遵循其文档中的 SDK、运行时和平台限制。

## 控件修复

DashedBorder 保留尺寸与圆角子元素裁剪，在绘制前准备与缩放相关的裁剪。Windows 10 CSD 窗口恢复缺失的一个物理
像素顶边，覆盖高 DPI 与激活/非激活状态。ImagePreviewer 快速连续旋转保持连续。
没有控件方法签名变化；Window Token 消费方须遵循上述重编译要求。
使用自定义 Window 模板的应用应确认仍保留标准绘制装饰覆盖层。

## 包验证结果

相对 6.2.7 的包比较报告 10 条 `CP0001`：`AtomUI.Controls`、`AtomUI.Desktop.Controls`、
`AtomUI.Toolkits.GalleryBase`、`AtomUI.Desktop.Controls.DataGrid` 与 `AtomUI.Desktop.Controls.ColorPicker`
在 net8.0 和 net10.0 上的生成式注册组标识变化。另外报告 20 条 `CP0011`：五个 Window 成员在两种 Token
枚举、两个目标框架上的数值变化，与上述迁移表一致。

这些是已记录的二进制不兼容，API 基线比较失败，不能表述为通过。比较未发现其他 API 不兼容或无法解析引用的
诊断，没有增加 ApiCompat 抑制。20 个包的布局与预期 Release 目标框架均通过独立校验，布局与 6.2.7 相同，
无需修改包布局允许清单。
