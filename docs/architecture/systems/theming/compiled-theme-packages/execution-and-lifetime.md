# 编译主题包：执行与生命周期

> 状态：已收敛为静态声明生成，尚未发布；本次本地范围验证已完成。本文规定生成产物进入现有主题运行时后的状态、缓存和释放边界。
> 它不能替代[运行时语义](../runtime.md)和[验证证据](verification.md)。

## 1. 一次执行的状态模型

```text
显式注册元数据
  → 验证来源/ABI/必要契约
  → 绑定当前冻结 registry
  → 规范化并合并此次有效配置
  → ThemeCompiler 按有效配置执行现有算法或复用有效缓存
  → 构造候选 snapshot 与独立 cold cell
  → 复核 mutation generation / scope stamp / 来源版本
  → CommitCore
  → Publish
  → Complete 与临时状态清理
```

编译包只是 Prepare 的输入/执行方式。ThemeManager 仍拥有唯一有效主题、Catalog、scope graph 和 mutation
执行门；生成工厂不能更新 RequestedThemeVariant、向活动字典写键、订阅资源事件或报告启动成功。

Catalog 为两种来源提供统一的内部定义视图：元数据、类型化默认覆盖、必要契约、来源修订与准备入口。
动态来源可以拥有已绑定定义；编译来源直接拥有已校验程序及当前 binding，不为兼容旧字段再构造 XML 对象图。
根和局部配置合并都消费这个视图，不能让 compiled path 和 XML path 各有一个配置优先级实现。

## 2. 注册与运行时编译

### 2.1 注册与绑定

首次绑定检查包 ABI、契约、平台域、精确 owner/值类型和可访问工厂；静态字面量不再次解析。
包描述符可防御性复制小型元数据，但不创建所有主题值表/资源。绑定得到当前 registry 的位置映射。

绑定 key 包含具体程序/包身份与实际 registry 身份，不能仅用 Theme.Id 或 schema 字符串 hash。
同一 registry 的后续请求复用有效绑定；第二阶段重建 registry 后重新绑定所需控件，不能复用旧 slot。
源 manifest 不能持有这个运行时绑定对象。

### 2.2 有效配置与算法执行

先由类型化赋值入口提供静态默认层，再按共同 Normalizer/Merger 得到有效配置。新提交的动态字符串与
Control identity 正常验证。ThemeCompiler 依据现有缓存身份复用结果，或调用运行时算法计算 Global 值。

为实际已注册控件建立轻量执行入口；首次 Own 查询或需要独立计算的 Control Effective Global 查询才物化控件结果。
全局结果可复用且无控件计算需求时，不恢复全局可变 builder；局部 Global 覆盖与算法模式仍可能要求计算。
输出冻结后进入既有候选提交，来源类型不改变值、优先级、appearance 或结果事件。

### 2.3 静态与动态的一致性

以下情况必须保留差异，不能按“看起来是同一主题”合并：

| 输入 | 必须采用的语义 |
|---|---|
| 根 Inherit=false | 库默认 + 所选 definition；不带应用初始覆盖 |
| 局部 Inherit=false | 纯库默认；不继承父主题/配置 |
| Algorithms=null / 空列表 | 前者继承，后者显式默认算法链 |
| 父 Dark、子仅 Compact | 整体替换为 Light Compact；Dark Compact 需完整声明 |
| Control Global/Custom | 仅影响该控件的计算和 appearance，不修改 context variant |
| 运行时主色变化 | 重新计算依赖的派生值，不只覆盖 ColorPrimary 资源 |
| Motion/Wave 开关 | 共同执行最终规范化，不能复用开关不同的计算结果 |
| 字体描述或明确环境参数变化 | 检查相关输入，不沿用不匹配的计算结果 |

首次控件结果/evaluator 查询失败维持既有查询边界：本次查询失败，不发布部分槽值；输入保留以允许后续重试，不把异常
永久缓存为成功值，也不将已提交根事务倒退为 Failed。构建期静态错误和 ABI 错误则必须更早拒绝。

跨控件 Own 结果查询不属于 evaluator 输入契约。生成代码只依赖声明的全局/本控件输入；运行期应拒绝自身槽的
递归物化，不能用重入缓存查询构造隐式依赖环或线程互等。任意用户回调不得在缓存全局锁内执行。

### 2.4 成本与复杂度边界

设 G 为全局值数量，C 为实际注册控件数量，K 为定义显式引用的契约数量，U 为本次动态覆盖数量，
V 为首次查询控件需要计算的值数量。静态编译移除的是 XML 读取、静态名称与字面量解析，不能把运行时装配声称为常数时间。

- 首次包绑定只验证全局契约并保存控件身份；每个控件首次编译时绑定它的 K 个必要契约。
  全局/控件各自缓存，配置合并和 fingerprint 不枚举控件值；同一程序与 registry 复用有效绑定，新 registry 重新绑定。
- 动态输入仍需验证/合并 U 个覆盖，并构造足以判断结果等价的结构化输入。hash 只加速，不省略碰撞后的比较。
- Global 算法仍在运行时执行，首次构造值表与资源投影需要 O(G) 装配工作；合法复用已冻结结果时可省去对应工作。
- 现有槽表装配保持 O(C) 引用成本；不能以“按需”宣称零控件装配成本，也不能在该循环中运行全部 evaluator。
- 首次需要控件结果时只计算该控件所需 V 个值及必要的 Global 重算；算法复杂度按实际算法/回调单独记录，
  不能把未知第三方 evaluator 视为 O(1)。再次命中查询遵守既有零分配热路径。

## 3. 候选、资源与原子提交

候选 snapshot 和纯值没有 owner。实际 ControlTheme、ResourceDictionary、Binding、Transitions、原生句柄等
由既有资产/宿主工厂在允许线程构造；它们不属于静态默认值，也不作为静态共享对象。

注册编译主题不改变 Token 层与静态资产层的优先级。应用覆盖、局部词法资源、variant 与未知资源 key 回退保持
[资源层契约](../lazy-materialization.md#4-资源层稳定与全局优先级)。生成 writer 不接触真实资源宿主。

Prepare 中确需挂载候选资产时，由现有事务与静态资源表记录“尝试获取”的关系；部分 AddOwner 成功后抛错也要
释放。失败只能清理本次候选新取得的资源，不能重挂载或释放仍属活动查询表的对象。

CommitCore 仅执行预先准备好的无回调引用交换：根、受影响 scope、内部状态和查询表同时生效；
owner attach/detach、属性设置、资源通知和用户代码均不属于 CommitCore。
Publish 才尝试 variant、context、资源和结果通知。每个外部边界隔离异常，继续后续通知；这些通知异常只报告 warning，
不以回滚部分字段伪装成“没有提交”。

生成 snapshot 必须完整服务 Global 查询；控件结果按原惰性边界提供。不能提交一个稍后还要由后台填充的可变数组，
也不能让 Source Generator 在首次资源查询时偷偷注册额外控件。

## 4. 并发请求

注册在启动提交时一次性完成，之后 registry 不再变化。运行期请求取得既有 mutation 执行门后，重新读取当前有效请求、
Catalog 和 scope 基线。当前 registry 不满足定义全部要求时不得提交，限制见[控件要求](overview.md#9-控件要求与启动提交)。

- 排队目录刷新进门后捕获目录、resolver、snapshot 和请求的匹配基线，不能混用旧 Catalog 与新 resolver。
- 在 Commit 前复核请求代际、scope 拓扑/配置 stamp、定义和 binding 修订。过期结果按现有语义丢弃或重新准备。
- Publish 内的主题切换、scope 更新或目录刷新排队；已经完成状态不能被较旧事件覆盖。
- Dispose/关闭优先检查已捕获的启动取消令牌，再检查服务可用性，避免把取消改报为对象已释放故障。

根切换与局部更新仍使用稳定 ThemeContext/Provider。编译路径不为每次请求新增 Provider、静态订阅或独立后台队列。

## 5. 线程与取消

| 工作 | 线程与能力 |
|---|---|
| 应用/scope/当前请求捕获，registry 装配 | 原有 UI/注册线程边界 |
| 运行时纯值计算 | 遵守既有 ThemeCompiler 线程边界；任务数量有界 |
| 任意 resolver/evaluator/资源 factory | 保持其现行允许线程；名称含 compiled 不能充当线程安全声明 |
| Avalonia 资源宿主、属性、主题 variant、发布 | UI 线程 |

调用方取消等待与生产者停止是不同事件。等价请求的 single-flight 生产由当前应用/缓存域拥有，
某一个等待者的 WaitAsync 取消不取消其他等待者或共享生产。

共同取消规则：

1. 取消或 supersede 在捕获、后台工作返回、取得执行门之后以及提交前检查。
2. 应用生命周期取消停止接受新生产；合作式生产尽快退出。不能强制中断任意第三方 C# 回调。
3. 已进入不可回滚 CommitCore/Publish 的提交按既有协议收尾，不能从中间强行释放活动资源。
4. 即使生产者不响应取消，迟到结果也不能提交、回填已关闭缓存或重新建立 owner/订阅。
5. 所有等待者都取消时，允许已有有界纯生产完成并按策略缓存；不得宣称“取消等待已释放生产者全部输入”。
6. 失败或实际终止的生产及时清理 in-flight key，之后允许重试。等待超时/逻辑取消不等于生产已退出；仍在执行的
   回调继续计入生产并发与输入保留预算，不因解除等待就释放配额。不得通过反复超时、移除 key、立即重试制造无界生产。
7. 不可中断回调实际返回前，其栈、闭包和输入可能仍存活；域关闭只能阻止后续使用，不能承诺立即释放这些引用。
   回调返回后在 finally 清理实际生产记录、配额、CTS 与输入。全局锁外执行 factory 和回调。

暂停/关闭状态、缓存域状态和结果状态各有单一 owner。错误传播保留原始原因；清理错误不能覆盖原始异常，
多个清理失败汇总或依现有边界记录，且后续清理仍必须执行。

## 6. 对象所有权与释放

| 对象 | 合法 owner | 释放/退休条件 |
|---|---|---|
| 生成方法、不可变 primitive/blob 元数据 | 定义程序集 | 随程序集生命周期，不捕获运行时对象 |
| package 描述符、实际 Type/委托、registry binding | 应用注册域/当前与合法旧读取视图 | 应用释放或代际不再被使用；进程缓存不得额外保留可卸载包 |
| 动态字节、Reader、临时位置/诊断缓冲 | 本次来源读取/准备 | 成功、失败、取消均关闭流和归还临时缓冲 |
| 规范化值、当前 snapshot、cold cell | 活动 context、合法读取视图、有界 cache | 最后合法引用消失；不依赖 UI teardown 才能回收历史版本 |
| 候选 writer、临时 builder、待挂载表 | 本次 transaction | 成功移交后退休；失败/supersede/cancel 释放候选 |
| ResourceDictionary/ControlTheme/绑定/原生对象 | 单一资源宿主/资产实例 | detach、scope/app Dispose；不放进静态默认值 |
| in-flight Task/CTS/continuation | 应用生产域及等待者 | 生产实际退出后释放记录、配额、CTS 和输入；已取消等待者及时解除自己的回调 |

同一个编译包可以被多个 Application 使用。不可变值数据可共享，带 owner 的对象必须按宿主创建，关闭 A 不得
解绑 B 的资源。共享实例需要不可变性证据；`IReadOnlyDictionary`、readonly 字段或接口名称本身不是深度不可变证明。

静态禁止保存 Application、ThemeManager、ThemeContext、Dispatcher、resolver 实例、provider、活动 snapshot、
Task、异常对象或带可变宿主的资源。生成的静态工厂只能捕获包内常量；手写受信任回调即使保持运行期，也不能被
提升为进程级全局 factory。实际实现无法约束任意外部代码的私有对象图，边界必须在包契约、分析和运行验证中落实。

Type、MethodInfo 和无捕获委托也会持有其程序集。可卸载包的绑定、委托和数据包装只能被所属注册域、活动
context 或合法旧视图持有；不得放入 Core 的进程级强字典。ALC 卸载验证以应用、所有 context 和合法旧视图均已
释放为前提，不承诺活跃消费者仍持有类型时也能卸载。

### 6.1 独立惰性槽

cold cell 只持有本控件 descriptor、精确有效配置和共享不可变 Global 输入，不持有完整 ThemeCompileInput、
整个 Catalog/主题包实例、父 snapshot、应用或 scope。框架冷槽需要的静态程序入口按最小片段提供。

跨快照可共享符合现有身份/appearance/配置规则的独立 cell，不构造 parent fallback 链。
控件 cell 不跨不兼容 registry 复用；全局值复用与其独立判断。

cell 的缓存访问使用弱生命周期句柄。缓存已释放时，纯值物化可以使用自身冻结输入独立计算，不重建应用服务或回填
缓存；不能让一个合法旧视图经 source→整个 control cache 保活其他历史快照。物化成功后释放输入/工厂/source 引用，
仅保留不可变结果；失败保留可重试的最小输入，不保存异常闭包。

不得在 snapshot 中隐藏需宿主或原生生命周期的 lazy factory。此类对象属于资源资产层，宿主已释放后必须拒绝新建。
不能通过“为了旧视图还能首查”强行保活原应用或重新挂载资源。

### 6.2 资源异常清理

继承现有[资源所有权协议](../lazy-materialization.md#41-所有权失败与释放)：

- 挂接尝试发生前就记录释放责任；OwnerChanged/AddOwner 在中途抛错也不能漏清。
- 每个资源及每个事件解除单独尝试，finally 先释放自己的 owner/状态；一个错误不能跳过兄弟资源。
- 已提交资源与候选资源分别管理。释放缓存中的纯值不会调用活动资源的 RemoveOwner。
- 新运行/新 owner 已接管的对象不能被旧执行的 finally 清除；通过实际所有权和代际判断。
- 自定义资源必须履行自身释放协议。框架负责关系解除与错误报告，不承诺能修复外部 RemoveOwner 内部的任意泄漏。

池化数组或 scratch buffer 不能交给已发布快照后立即归还；持久数据必须拥有独立不可变存储或明确的引用计数租约。
首个实现优先普通不可变托管数据，避免为小额分配收益引入共享池租约图。

## 7. 缓存、限额与关闭

新缓存不作为平行长期状态库。编译绑定、source、snapshot 和 control 数据按所属应用管理，
复用现有缓存基础设施并明确自己的 key、预算和退休条件。

| 缓存内容 | key 最低要求 | 计费/失效 |
|---|---|---|
| 读取/绑定结果 | 实际 source digest/修订、程序身份、实际 registry/ABI | 文档、值、必要 source map、diagnostics 与 key；来源或契约变化失效 |
| 编译包绑定 | 包/program 内容身份、具体 registry 身份 | owner/slot 映射及持有的程序元数据；注册演化重建 |
| snapshot 实例 | 完整有效输入、所需 schema/算法身份、结构等价 | key、规范化配置、值表、资源投影、cold source 和 cell |
| 控件结果 | 精确 owner/schema、Global 输入、Control 配置/策略 | Own 值与差量；不克隆整份 Global 数据 |

所有可增长缓存同时具备有限 entry 和估算字节预算；值、key、source map、diagnostics、冷配置/片段引用都参加计费。
预算采用统一配置及保守估算，不能新建未计费的 static “快路径”字典。实际数值限额在实现配置中有唯一来源，
验收须覆盖每个限额边界；缓存预算不承诺限制活动 context、调用者合法视图或任意自定义对象内部图。

编译进程序数据、内存映射/压缩 blob 与已解码托管对象分别记录：零 managed allocation 不等于零二进制/常驻内存。
发布时约束产物大小，运行时约束解码缓存与活动对象；不能用把大数据移入 static blob 的方式隐瞒成本。

应用关闭令不可重开的缓存域进入终止状态：禁止新入口，取消可取消的生产、清除待生产/已完成索引，
释放已结束等待的回调和缓存直接持有的包引用。仍在执行的生产按第 5 节保留有界记录与配额直到实际退出；
晚完成者核对域状态后丢弃结果，并释放自身输入。共享纯值被驱逐不代表立即销毁，只解除缓存的持有，
活动/合法旧视图仍可持有自己的版本。

## 8. 实现边界与后续变更要求

当前实现对应上述约束：

- Core/Gallery 通过生成式主题包接入 PreparedThemeDefinition，旧 syntax-document 特例已删除。
- 标准支持域的 copy/freeze/thaw 使用共享类型化操作；声明类型不受支持时保留动态 codec，不能把具体类型复制成不可赋回的类型。
- 读取和绑定缓存分别限制 256 个 entry / 32 MiB，包含文档、diagnostics、位置与 key；绑定使用真实 registry 身份。
- cold source 弱引用 control cache；已关闭缓存允许合法纯读取视图独立计算，但不得重新填充缓存或恢复资源 owner。
- 生产域默认 64 个 entry / 32 MiB，独立于已完成 LRU。仅新生产估算框架持有的 definition/config/父快照/全局输入，
  命中和等价 join 不重复扫描；取消等待不提前释放仍在执行的生产额度。

具体验证范围与限制见[验证记录](verification.md#8-当前验证状态)。新增 codec、求值器或缓存必须重新证明
输入身份、复制和释放边界，不能由现有内置类型的测试外推任意第三方对象图。
