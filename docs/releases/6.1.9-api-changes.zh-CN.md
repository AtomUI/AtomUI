# AtomUI 6.1.9 API 变更示例

AtomUI 6.1.9 调整了唯一的公共扩展边界：MSBuild 构建工具契约。控件、主题与运行时 API 均未变化——本版本没有移除
任何控件类型、属性或成员。本页给出从 6.1.8 升级时必须完成的迁移。

英文版：[AtomUI 6.1.9 API Change Examples](6.1.9-api-changes.md)。

## 快速对照

| 领域 | 6.1.8 | 6.1.9 迁移 |
| --- | --- | --- |
| 构建工具运行时 | `AtomUI.Build.Tasks` 以 `netstandard2.0` 程序集交付，在 MSBuild 节点内进程内执行 | 构建工具以 `net10.0` 程序集交付，改由 .NET Host 启动的单次进程执行 |
| 构建要求 | 任何能加载 `netstandard2.0` 任务程序集的 SDK | 引用 AtomUI 的项目需要 .NET 10 SDK 才能构建 |
| 任务注册 | `<UsingTask ... AssemblyFile="$(AtomUIBuildTasksAssembly)" />` | `<UsingTask TaskFactory="RoslynCodeTaskFactory" ...>` 编译 `AtomUI.Build.Tasks.Process.cs` |
| 任务调用 | 任务只接收各自的特性参数 | 任务额外要求 `TaskAssembly`，并接受 `DotNetPath` |
| 自定义构建任务覆盖 | `AtomUIBuildTasksSourceAssembly`、`AtomUIBuildTasksShadowKey`、`AtomUIBuildTasksShadowRoot`、`AtomUIBuildTasksShadowDirectory` | 已移除；只需将 `AtomUIBuildTasksAssembly` 指向 `net10.0` 任务程序集 |
| 工具包布局 | `tools/netstandard2.0/AtomUI.Build.Tasks.dll` | `tools/net10.0/AtomUI.Build.Tasks.dll` 及其运行配置与依赖 |

## 使用 .NET 10 SDK 构建引用 AtomUI 的项目

AtomUI 的 MSBuild 集成不再在进程内加载任务程序集。由 SDK 编译的适配器通过 .NET Host 启动单次 .NET 进程来执行
真实任务，因此 Host 必须能运行 `net10.0` 程序集。任何引用 AtomUI 的项目都需要 .NET 10 SDK 才能构建。产品库
目标框架不变——应用仍可面向 `net8.0`。

6.1.8：任何能加载 `netstandard2.0` 任务程序集的 SDK 均可构建。

6.1.9：即使应用面向 `net8.0`，构建机也必须安装 .NET 10 SDK。

## 自定义源码构建：更新构建任务路径覆盖

正常 NuGet 消费方不需要设置构建任务路径。自定义源码构建与测试脚手架若指向仓库任务程序集，必须改为
`net10.0` 输出；影子副本相关属性已移除，不得再设置。

#### 6.1.8

```xml
<PropertyGroup>
  <AtomUIBuildTasksAssembly>$(RepoRoot)/tools/netstandard2.0/AtomUI.Build.Tasks.dll</AtomUIBuildTasksAssembly>
</PropertyGroup>
```

#### 6.1.9

```xml
<PropertyGroup>
  <AtomUIBuildTasksAssembly>$(RepoRoot)/tools/net10.0/AtomUI.Build.Tasks.dll</AtomUIBuildTasksAssembly>
</PropertyGroup>
```

`AtomUIBuildTasksSourceAssembly`、`AtomUIBuildTasksShadowKey`、`AtomUIBuildTasksShadowRoot` 和
`AtomUIBuildTasksShadowDirectory` 不再存在。按内容键控的影子暂存以及 `AtomUI.BuildTasks.ShadowKey.props` 盖章
一并移除：适配器不再在整个构建节点生命周期内持有已加载的任务 DLL，因此不需要影子副本。

## 直接调用任务：补充 `TaskAssembly` 与 `DotNetPath`

在随包 `.targets` 之外直接调用 AtomUI 任务的代码，必须传入任务程序集路径，并可选传入 .NET Host 路径。所有任务
现在派生自统一的隔离基类，其中 `TaskAssembly` 为必需参数。

#### 6.1.8

```xml
<AtomUI.Build.Tasks.CollectAxamlUsageTask
    AxamlFiles="@(AvaloniaXaml)"
    OutputFile="$(IntermediateOutputPath)usage.json" />
```

#### 6.1.9

```xml
<AtomUI.Build.Tasks.CollectAxamlUsageTask
    TaskAssembly="$(AtomUIBuildTasksAssembly)"
    DotNetPath="$(DOTNET_HOST_PATH)"
    AxamlFiles="@(AvaloniaXaml)"
    OutputFile="$(IntermediateOutputPath)usage.json" />
```

注册的任务类型名不变。`<UsingTask>` 注册改为使用 `RoslynCodeTaskFactory` 编译进程适配器
（`AtomUI.Build.Tasks.Process.cs`）；下游消费方通常依赖随包 `buildTransitive` 资产，无需改动。

### 重建兼容边界

不要将 6.1.8 的任务程序集、影子目录或缓存的 `AtomUI.BuildTasks.ShadowKey.props` 与 6.1.9 构建资产混用。清理
过期的工具输出，并针对 6.1.9 包重新构建；不必预先结束 IDE 或关闭节点复用，因为新的执行路径不依赖这两者。
