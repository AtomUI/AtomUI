# AtomUI 6.2.15 migration guide

[简体中文](6.2.15-api-changes.zh-CN.md)

This guide covers upgrading from 6.2.14. See the [Changelog](../../CHANGELOG.md) for the release changes.

## Quick reference

| Area | 6.2.14 | 6.2.15 and migration |
| --- | --- | --- |
| `IForm` | Existing validation entry points | Implement the new options-based async method in custom implementations |
| `AbstractRate.ToolTips` | Available on the shared base | Use Desktop `Rate.ToolTips` or provide tooltips in the custom rating control |
| Control bases and model assemblies | Desktop owns the original implementations and models | Qualify the Desktop text input base, update custom selectors and owner lookups, and scan the shared assemblies for moved model definitions |
| Carousel autoplay | Timer tied to the Desktop control | Pauses while the host is unavailable; use application state to track slides independently of visibility |
| List keyboard focus | Root or inner controls could take focus | Focus goes to the row; update custom themes and keyboard scripts |
| Generated registration | Identities encode the 6.2.14 assembly version | Align the package versions, rebuild generated consumers, and republish trimmed or NativeAOT outputs |

## Form validation contract

Custom `IForm` implementations must implement this method. Existing `Form` instances inherit the implementation from `AbstractForm`.

```csharp
Task<FormValidateReport> ValidateAsync(
    FormValidateOptions options,
    CancellationToken cancellationToken = default);
```

Honor `FieldNames` and `IsSilent`, pass the cancellation token to validators, and return the current values and
per-field results in `FormValidateReport`. Check calls on `AbstractForm` that pass an untyped `default` to `ValidateAsync`.
Use `default(CancellationToken)` to select the existing overload. The example checks one field and preserves visible feedback.

```csharp
var report = await form.ValidateAsync(new FormValidateOptions
{
    FieldNames = ["Email"],
    IsSilent = true
}, cancellationToken);
```

Check tests that assert exact validation text. Validators without explicit messages now use localized defaults,
including the required-field messages used by `FormStringNotEmptyValidator` and `FormNotNullValidator`. Read `FormValidateReport.Fields` or subscribe
to `SubmitFailed` for structured submission failures. Applications that implement `IForm` in a separate assembly
must rebuild it with the new method.

## Rate tooltips

`ToolTips` and `ToolTipsProperty` are declared on `AtomUI.Desktop.Controls.Rate`. For example, change a helper
that sets star tooltips to accept `Rate` as its parameter type. Desktop AXAML can continue to set `ToolTips` on
`Rate`. Custom controls derived directly from `AtomUI.Controls.Commons.AbstractRate` must supply their own tooltip
behavior if needed. Recompile assemblies that access the old base property or field.

## Shared control bases and forwarded types

Desktop Button, Carousel, Collapse, Form, text and numeric inputs, OTP input, Slider, Steps, TabControl and TabStrip
use shared bases. The Desktop-facing compatibility declarations include the existing Form and tab
`DirectProperty` fields. Custom code that inspects the first registration or declaring owner of a shared styled
property should use the property reference exposed by the intended control or base. Rebuild custom controls and
verify their property registration and overrides against the upgraded assemblies.

Form's `NotifySubmit` and `NotifyReset`, FormItem's `NotifyContentAdded` and `NotifyFormItemChanged`, the protected
form and clearing hooks on Desktop `AbstractTextInput`, the protected form hooks on NumericUpDown and Slider, and
`BaseTabControl.RegisterContentPresenter` now override virtual methods declared by the shared bases. Recompile
assemblies that override these hooks so their virtual calls bind to the new declarations. For example, a Desktop
Slider subclass can keep its source-level override of `NotifyFormValueChanged`.

Both `AtomUI.Controls` and `AtomUI.Desktop.Controls` expose a type named `AbstractTextInput`. If a source file
imports both, qualify the name or add an alias.

```csharp
using DesktopTextInput = AtomUI.Desktop.Controls.AbstractTextInput;
```

In custom input themes, review selectors that target the exact parent or sibling of `PART_ClearButton` or
`TextCountIndicator`. The accessory controls now sit inside accessory panels. Update the selector for that
hierarchy or use the dedicated Semantic Part Style where available. Review copied Button and DropdownButton
templates that depend on the previous icon visibility bindings.

The Desktop assembly forwards the legacy CLR names of Button enums, `StepsStatus`, `ICollapseItemData`,
`FormItemLayout`, search and OTP event types, `SliderMark`, and public Cascader, DateViewer, ImagePreviewer
and Upload models. Direct references continue to resolve. Code using `Assembly.GetTypes()` on the Desktop assembly
must scan `AtomUI.Controls.Shared` for DateViewer types and `AtomUI.Controls` for the other forwarded definitions.
Use `typeof(T).Assembly` when the concrete type is known.

## Carousel autoplay

Autoplay pauses when the carousel is detached, hidden or disabled, its motion activity source is inactive, the
window is minimized, or a swipe is in progress. Allow a new autoplay interval after resuming. If the active
slide must advance even while the carousel is unavailable, track the current slide in application state and
update `SelectedIndex` from the application's timer. Disable built-in autoplay when an application timer owns it.

## List keyboard focus

Tab enters the focused row in ListBox, ListView and Transfer, and each arrow press moves one row. In a grouped
ListView, group headers are skipped. Transfer rows expose the checkbox's selection through row interaction
without a separate checkbox Tab stop. The default focus outline is drawn inside the row.

Set focus and assert selection on the item container in keyboard automation. When copying the default theme,
retain the row template focus target and inset focus outline settings. Verify entry via Tab, vertical movement,
and Space for selection in Transfer.

## Generated registration

Generated `ControlPackageGroup_*` identities include the owning assembly version. Update all related AtomUI
package references, including the Generator, to 6.2.15 and rebuild apps and libraries that consume the generated
registrations. Run publish again for trimmed and NativeAOT applications so their generated registration maps
and package group identities match.
