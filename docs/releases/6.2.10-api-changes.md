# AtomUI 6.2.10 migration guide

[简体中文](6.2.10-api-changes.zh-CN.md)

6.2.10 replaces the actor-based motion library with frame-driven motions that play directly on controls, makes
Windows prefer the redirection surface, and lets the shadow area of window-type popups pass input through.
Avalonia remains 12.1.4, and Release product packages continue to target net8.0 and net10.0. No `build/**`,
package layout, SDK or target-framework contract changes in this release.

## Quick reference

| Area | 6.2.9 | 6.2.10 / migration |
| --- | --- | --- |
| Motion namespace | `AtomUI.MotionScene` | `AtomUI.Animations`; the `atom:` AXAML prefix still resolves motion types |
| Motion contract | `IMotion`, concrete `AbstractMotion`, `Run`/`RunAsync(BaseMotionActor, ...)` | Abstract `AbstractMotion` with `Build(MotionBuilder, in MotionContext)`; play with `PlayAsync(Control)` |
| Motion actors | `BaseMotionActor`, `BaseLayoutAwareMotionActor`, `MotionActor`, `LayoutAwareMotionActor`, `IMotionActor` | Removed; animate any `Control`, use `ContentViewport` for expand/collapse and `Motion.*` attached properties for show/hide |
| Motion defaults | `Duration` 300 ms, `Easing` linear, `PropertyValueFillMode` Forward | `Duration`/`Easing` nullable (token `MotionDurationMid` / per-motion default easing), `FillMode` Both |
| Control motion properties | `OpenMotion`/`CloseMotion` typed `AtomUI.MotionScene.AbstractMotion?` | Typed `AtomUI.Animations.AbstractMotion?`; change the `using` and rebuild |
| Template parts | `PART_MotionActor`, `PART_ContentMotionActor`, ... | Renamed per control (see below); update copied ControlThemes |
| Windows composition | `WinUIComposition` first | `RedirectionSurface` first; `AcrylicBlur`/`Mica` need an explicit opt-in |
| Generated registration groups | Public `ControlPackageGroup_*` names include the 6.2.9 assembly identity | Names include 6.2.10; upgrade related packages together and rebuild compiled consumers |

## Motion library

### Namespace

All public motion types moved from `AtomUI.MotionScene` to `AtomUI.Animations`, and the `AtomUI.MotionScene` XML
namespace mapping is removed. `https://atomui.net` already maps `AtomUI.Animations`, so AXAML that uses the `atom:`
prefix keeps resolving motion types; C# needs the new `using`.

```csharp
// 6.2.9
using AtomUI.MotionScene;
popup.OpenMotion = new ZoomBigInMotion();

// 6.2.10
using AtomUI.Animations;
popup.OpenMotion = new ZoomBigInMotion();
```

Built-in Fade, Slide, Zoom, ZoomBig, Move, Expand and Collapse motions keep their class names. Each now has a
parameterless constructor and `(TimeSpan? duration, Easing? easing = null, FillMode fillMode = FillMode.Both)`.
`duration` is no longer optional in that overload, so `new XxxMotion(easing: e)` must pass `null` for the duration.
`MoveXxxMotion.Offset` and `ExpandMotion`/`CollapseMotion.Direction` become nullable settable properties; a null
`Direction` uses the target's `Motion.LayoutDirection`.

### Motion definition and playback

`IMotion` and `MotionSpiritType` are removed. `AbstractMotion` is now abstract with protected constructors and
describes a motion through `Build`; the configure/notify hooks, animation and transition lists and transform helpers
are removed.

| 6.2.9 | 6.2.10 |
| --- | --- |
| `IMotion` | `AbstractMotion` |
| `new AbstractMotion(duration, easing, fillMode)` | Derive and implement `Build(MotionBuilder, in MotionContext)` |
| `ConfigureMotionStartValue` / `ConfigureMotionEndValue(BaseMotionActor)` | `builder.Opacity`, `TranslateX/Y`, `Scale/ScaleX/ScaleY`, `Rotation` channels with `From`/`FromCurrent`/`To`/`KeyFrame` |
| Custom transitions and animations | `builder.Property<T>(property, interpolator)`, `builder.Expand/Collapse(direction)`, `builder.Sequence/Parallel(...)` |
| `RenderTransformOrigin` | `Origin` (`RelativePoint?`) |
| `PropertyValueFillMode` | `FillMode` (default `Both`) |
| `Duration` (`TimeSpan`, default 300 ms) | `Duration` (`TimeSpan?`, null uses the `MotionDurationMid` token) |
| `Easing` (default linear) | `Easing` (`Easing?`, null uses `DefaultEasing`) |
| `Run` / `RunAsync(BaseMotionActor, aboutToStart, ...)` | `Task<MotionResult> PlayAsync(Control target, CancellationToken)` |

```csharp
// 6.2.10 custom motion
public sealed class RiseInMotion : AbstractMotion
{
    public RiseInMotion() { }
    public RiseInMotion(TimeSpan? duration) : base(duration) { }

    protected override Easing DefaultEasing => new CubicEaseOut();

    protected override void Build(MotionBuilder builder, in MotionContext context)
    {
        builder.Opacity.From(0).To(1);
        builder.TranslateY.From(8).To(0);
    }
}
```

Playback runs on the UI thread on any control. Replace `aboutToStart`/`completed` callbacks with code before and after
the await, and inspect the result: `MotionOutcome` is `Completed`, `Superseded`, `Cancelled`, `Detached` or `NotReady`.

```csharp
// 6.2.9: content had to be inside a MotionActor
await new FadeInMotion(TimeSpan.FromMilliseconds(300))
    .RunAsync(motionActor, aboutToStart: () => motionActor.IsVisible = true);

// 6.2.10
target.IsVisible = true;
var result = await new FadeInMotion(TimeSpan.FromMilliseconds(300)).PlayAsync(target);
if (result.IsCompleted)
{
    // ...
}
```

`Motion.IsCurrent(target, result)` tells whether a result still belongs to the target's latest request, and
`Motion.Reset(target)` cancels and restores it. A reversed request continues from the currently presented value.

### Actors, show/hide and expand/collapse

`IMotionActor`, `MotionActorControlProperty`, `BaseMotionActor`, `BaseLayoutAwareMotionActor` and the
`AtomUI.Controls.Primitives` controls `MotionActor` and `LayoutAwareMotionActor` are removed. Motions write compositor
transform channels on the real target, so there is no `MotionTransform` property, `PreStart`/`Completed` actor event
or follow mode. `UseRenderTransform` has no equivalent.

Declare visibility-driven motion with the `Motion` attached properties: `IsVisible`, `Enter`, `Leave`, `IsEnabled`,
`DurationOverride` and `LayoutDirection`. Await completion with `Motion.GetVisibilityTask(target)`.

```xml
<!-- 6.2.9 -->
<atom:MotionActor Name="PART_MotionActor">
    <Border />
</atom:MotionActor>

<!-- 6.2.10 -->
<Panel Name="PART_VisibilityRoot"
       atom:Motion.IsVisible="{TemplateBinding IsActive}"
       atom:Motion.IsEnabled="{TemplateBinding IsMotionEnabled}"
       atom:Motion.DurationOverride="{TemplateBinding MotionDuration}">
    <atom:Motion.Enter><atom:FadeInMotion /></atom:Motion.Enter>
    <atom:Motion.Leave><atom:FadeOutMotion /></atom:Motion.Leave>
    <Border />
</Panel>
```

Replace layout-aware actors with `atom:ContentViewport`, which clips animated content while arranging it at its
natural size. A custom layout host can implement `IMotionLayout.BeginLayoutMotion(Direction, bool expanded)`, which
returns an `IMotionLayoutLease` with `SetProgress(double)` and `Dispose()`.

```xml
<!-- 6.2.9 -->
<atom:LayoutAwareMotionActor Name="PART_ContentMotionActor">...</atom:LayoutAwareMotionActor>

<!-- 6.2.10 -->
<atom:ContentViewport Name="PART_ContentViewport"
                      atom:Motion.IsVisible="{TemplateBinding IsExpanded}"
                      atom:Motion.LayoutDirection="Bottom">
    <atom:Motion.Enter><atom:ExpandMotion /></atom:Motion.Enter>
    <atom:Motion.Leave><atom:CollapseMotion /></atom:Motion.Leave>
    ...
</atom:ContentViewport>
```

AtomUI no longer registers its custom `TransformOperations` animator globally. Application keyframe animations of
`TransformOperations` use Avalonia's default animator.

### Control motion properties

`OpenMotion`/`CloseMotion` and their `*Property` fields on `Popup`, `Flyout`, `FlyoutHost`, `ContextMenu` and
`TreeView` change from `AtomUI.MotionScene.AbstractMotion?` to `AtomUI.Animations.AbstractMotion?`. Assigning built-in
motions only needs the new `using`, but code compiled against 6.2.9 must be rebuilt. Controls pass their duration with
each playback request and no longer change the shared motion's `Duration`.

### Template parts

Applications that copy or override these ControlThemes, or look parts up by name, must update the part names. Templates
that keep the old names lose their motion instead of using the new playback.

| Control theme | 6.2.9 part | 6.2.10 part |
| --- | --- | --- |
| CountBadgeAdorner, DotBadgeAdorner | `PART_MotionActor` | `PART_IndicatorSurface` (`Border`) |
| CollapseItem, Expander | `PART_ContentMotionActor` | `PART_ContentViewport` (`ContentViewport`) |
| OverlayDialogPresenter | `PART_MaskMotionActor`, `PART_SurfaceMotionActor` | `PART_MaskHost`, `PART_SurfaceMotionRoot` |
| DrawerContainer | `PART_InfoContainerMotionActor` | `PART_Surface` (`Border`) |
| BackTopFloatButton | `PART_MotionActor` | `PART_VisibilityRoot` (`Panel`) |
| FloatButtonGroup | `PART_MotionActor` | `PART_MenuSurface` (`Border`) |
| MessageCard, NotificationCard | `PART_MotionActor` wrapper | Removed; the frame is the motion target |
| NavMenuItem | `PART_ChildItemsLayoutTransform` | `PART_ChildItemsViewport` (`ContentViewport`) |
| TreeViewItem, TreeSelectTreeViewItem, TransferTreeViewItem | `PART_ItemsPresenterMotionActor` | `PART_ChildrenViewport` |

The Window theme adds `PART_ContentCacheHost` and `PART_ContentBackdrop` for the overlay content cache. A copied Window
template without them renders overlay animations directly instead of from the cache.

## Windows composition mode

`WithAtomUIDefaultOptions()` now orders Windows composition modes as `RedirectionSurface` → `WinUIComposition` →
`DirectComposition` → `LowLatencyDxgiSwapChain`. Only the redirection surface is composited by DWM in sync with window
geometry, which removes opposite-edge lag and white flashes during live resize. Under it, `AcrylicBlur` and `Mica` are
unavailable and `Transparent` uses the legacy `DwmEnableBlurBehindWindow` path.

Applications that need material effects can configure their own order after `WithAtomUIDefaultOptions()`, accepting the
live-resize lag. Set the other `Win32PlatformOptions` values they rely on in the same object.

```csharp
AppBuilder.Configure<App>()
    .UsePlatformDetect()
    .WithAtomUIDefaultOptions()
    .With(new Win32PlatformOptions
    {
        CompositionMode = [Win32CompositionMode.WinUIComposition, Win32CompositionMode.RedirectionSurface]
    });
```

## Rebuild generated registration consumers

The generator hashes the package assembly identity, including its version, into public
`AtomUI.Generated.*.ControlPackageGroup_*` names, so 6.2.10 changes these names again.

1. Upgrade related AtomUI packages and any explicit Generator reference to 6.2.10 together.
2. Clean and rebuild applications and custom control packages consuming generated registration metadata.
3. Republish trimmed and NativeAOT applications so dependency analysis uses the new groups.

Do not reference generated group names directly or mix 6.2.9 compiled registration metadata with the 6.2.10 package set.

## Behavior changes without API migration

- Window-type popups use `BoxShadowsSecondary`, the same shadow as overlay popups, and their shadow area passes pointer
  input to the content below on Windows, X11, Wayland and macOS. The whole popup passes input through during its
  open/close motion.
- Default motion duration follows the `MotionDurationMid` token instead of a fixed 300 ms; `ZoomInMotion` scales from
  the center.
- Dialogs without a placement target zoom from the panel center (0.2 to 1).
- Drawer and modal-mask animations composite cached window content, so content below the overlay is visually frozen
  for the duration of the animation.
- On Wayland, prepared-frame EGL submission is enabled by default; set the AppContext switch
  `AtomUI.Experimental.WaylandFramePacing` to `false` to opt out.

## Package validation results

Comparison of all 21 release packages against 6.2.9 (net8.0 and net10.0) reports 142 diagnostics and no
unresolved-reference diagnostic:

| Diagnostic | Count | Packages | Cause |
| --- | --- | --- | --- |
| `CP0001` removed type | 78 | `AtomUI.Core` | 39 `AtomUI.MotionScene` types moved or removed (motion library) |
| `CP0001` removed type | 4 | `AtomUI.Controls` | `MotionActor`, `LayoutAwareMotionActor` |
| `CP0001` removed type | 10 | `AtomUI.Controls`, `AtomUI.Desktop.Controls`, `AtomUI.Toolkits.GalleryBase`, `AtomUI.Desktop.Controls.DataGrid`, `AtomUI.Desktop.Controls.ColorPicker` | Versioned `ControlPackageGroup_*` registration groups |
| `CP0002` removed member | 40 | `AtomUI.Desktop.Controls` | `OpenMotion`/`CloseMotion` getters and `*Property` fields whose type moved to `AtomUI.Animations` |
| `CP0008` interface change | 10 | `AtomUI.Controls`, `AtomUI.Desktop.Controls` | `AbstractToggleSwitch`, `AbstractSegmented`, `ComboBoxItem`, `TabControl`, `TabStrip` replace the internal `IStateMotionOwner` with the internal `ITransitionInitializationOwner`; consumers cannot reference either interface |

The other packages report no API difference. These are documented binary incompatibilities: the historical API comparison
fails, no suppression is added, and this release does not claim binary compatibility with 6.2.9. All 21 package layouts
match 6.2.9, with no package-layout allowlist change. As in 6.2.9, the release workflow publishes this documented binary
break without a historical API baseline; the comparison above remains the release evidence, and package identity,
framework and build-asset validation still apply.
