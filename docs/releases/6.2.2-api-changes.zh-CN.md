# AtomUI 6.2.2 API 变更示例

尽管版本号是补丁版本，AtomUI 6.2.2 对目标框架、控件包注册、主题发现、平台元数据及交付的构建资产作出了破坏性变更。本文说明从 6.2.1 升级的方法。应用应先升级 SDK 和目标框架，再升级包；第三方控件包随后必须使用配套生成器重新构建。

English version: [AtomUI 6.2.2 API Change Examples](6.2.2-api-changes.md)。

## 快速对照

| 领域 | 6.2.1 | 6.2.2 迁移 |
| --- | --- | --- |
| 产品目标框架 | 同时提供 `lib/net8.0` 和 `lib/net10.0` | 只提供 `lib/net10.0`。改为面向 `net10.0`，使用 .NET 10 SDK 并重建消费方；Browser 应用面向 `net10.0-browser`。 |
| 注册 ABI | `AotTrimRegistration`、Unit/Plan/Sidecar 管线及生成的 linked-registration 入口 | 使用生成的 TypeMap 注册管线。第三方控件包须用 v6.2.2 生成器重建并重新发布；旧二进制不能通过新 ABI 注册。 |
| 主题发现与 Schema | `ControlThemeProviderAttribute`、`IControlThemeProvider`、旧 owner/reference/string 资产元数据及旧 `ControlPackageRegistration` 构造器 | 使用 `IControlThemesProvider` 与生成的注册；自定义 Schema 描述符需以真实导出 `Type`、Token owner 和语义绑定重建。 |
| 构建集成 | `AtomUI.LinkedRegistration*.props/targets`、`.atomui-link.json` 和 `AtomUI.Generator.LinkedPublish` | 删除对已退役文件的自定义导入和引用；`buildTransitive/AtomUI.Registration.targets` 自动解析当前生成器、worker 与 Browser 后端。 |
| 主题平台元数据 | `AtomUISupportedOSPlatforms`、`AtomUIUnsupportedOSPlatforms` 与项目中的主题路径列表 | 在对应控件或资源 CLR 类型上使用标准 `SupportedOSPlatformAttribute` / `UnsupportedOSPlatformAttribute`。 |
| 生成的 Token API | 未声明 Own Token 的控件资源 key 类型与旧 DataGrid / WindowTitleBar Token 枚举数值 | 替换已删除的 Token key 引用，重建生成 Token 的消费方，不跨版本持久化 Token 枚举数值。 |

## 1. 将应用和类库升级到 .NET 10

产品包目标框架由 `net8.0` 改为 `net10.0`，`lib/net8.0` 已删除。面向 `net8.0` 的项目不能引用 v6.2.2 产品包，构建环境也必须使用 .NET 10 SDK。这是产品 TFM 的变化，不只是 6.1.9 引入的构建工具 SDK 要求。

升级前：

```xml
<TargetFramework>net8.0</TargetFramework>
<PackageReference Include="AtomUI.Desktop.Controls" Version="6.2.1" />
```

升级后：

```xml
<TargetFramework>net10.0</TargetFramework>
<PackageReference Include="AtomUI.Desktop.Controls" Version="6.2.2" />
```

直接引用 AtomUI 产品包的应用和类库均需升级。Browser 应用使用 `net10.0-browser`，并按 [AOT 与裁剪架构](../architecture/foundations/aot-and-trimming.md)中的受支持 SDK 和 linker 组合验证 Browser 裁剪。目标框架变化后重新构建所有消费方二进制。

## 2. 为 TypeMap 注册重新构建第三方控件包

旧 `AotTrimRegistration`、`AotTrimRegistrationPlanRegistry`、`AotTrimControlPackageRegistrationBuilder`、`AotTrimUnitAttribute` / `AotTrimGeneralUnits` 和 `ControlPackageRegistrationEntryAttribute` API 及生成 ABI 已删除。Unit、应用 usage、Sidecar、Plan 和整包回退路径不再读取或执行。仅升级消费应用的包版本，不能让按旧 ABI 编译的第三方包兼容新注册管线。

应用继续调用正常入口，例如 `UseAtomUI()` 和 `UseDesktopControls()`。第三方包应引用 v6.2.2，按照[第三方控件包指南](../guides/theming/third-party-control-packages.md)重建公开包入口与主题 provider，重新发布该包后再构建应用。v6.2.2 生成器会产生包 marker、条件 TypeMap、注册片段和资源工厂；包作者无需手工维护 AOT 控件名单、Sidecar 或发布模式分支。

`UseAllDesktopControls()` 已删除，改用 `UseDesktopControls()`。如果先前用它在裁剪发布中保留只通过动态方式创建的控件，应通过正常的 .NET 裁剪 root 声明这些动态类型，并验证实际发布产物；新版本没有等价的整包注册开关。

当前包模型会一同注册控件、主题资产、语义描述及资源工厂。直接构造 `ControlPackageRegistration` 的自定义代码，除语义描述外还要传入新的 `IEnumerable<ControlThemeResourceRegistration>` 参数；旧构造器已删除。注册在提交前校验整个包；`AddControlPackage` 失败后应新建 builder 重试，不能继续复用失败的 builder。

## 3. 更新主题发现与 Schema 扩展

不再使用的单主题 `ControlThemeProviderAttribute` 和 `IControlThemeProvider` 契约已删除。请实现包级 `IControlThemesProvider`，由生成的注册入口提供资源工厂。`BaseControlTheme` 的独立强类型模板能力保持可用。

`ControlThemeAssetDescriptor` 现在需要 `AssetId`、真实导出主题类型、必需的 Token owner identity 和语义主题绑定。旧 owner/reference/string 构造器及 `OwnerIdentity`、`ReferencedControlIdentities`、`SemanticPart` 属性已删除。`ControlThemeSemanticPartDescriptor` 改用 `Type targetType`，并以 `TargetType` 取代 `TargetTypeName`。手工构造这些描述符的代码必须改用当前签名；优先让生成器从 AXAML 推导。

普通编译时，跨资产 `StaticResource` 必须能证明来源。原先依赖目录推导的资源名应改为正常显式 `ResourceInclude` 或包 Core/provider 导出。旧 `AtomUIPackageSharedTheme` 与 `AtomUIPackageSharedThemePaths` 开关不再提供所有权。包身份应保持稳定，它决定资源与注册作用域。

### 生成的 Token key 与枚举数值

TypeMap 生成器不再为没有 Own Token 的控件生成公开的 Token key、Token resource extension 与 Token holder 类型；这同时包括抽象控件和具体控件。ApiCompat 门禁在 `AtomUI.Controls`、`AtomUI.Desktop.Controls`、`AtomUI.Desktop.Controls.ColorPicker` 中列出受影响名称，例如 `ItemsControlTokenKey`、`AbstractAutoCompleteTokenKey`、`FormValidateFeedbackTokenKey` 及对应的 `*TokenResourceExtension`。引用这些名称的 C# 与 AXAML 必须重建或调整：属于另一控件的值改用受支持的控件 key；自定义抽象需要应用自己定义 Token/资源 key。已删除的 Token key 没有统一的新名称。

新增分页与 caption 几何 Token 后，既有 `DataGridTokenKey` / `DataGridTokenKind` 和 `WindowTitleBarTokenKey` / `WindowTitleBarTokenKind` 成员的数字值发生变化。请以成员名称引用 Token；以整数持久化的值或编译进旧二进制的数字常量必须为 6.2.2 重新生成。发生变化的具体成员记录在 DataGrid 与 Desktop Controls 的 ApiCompat 确认文件中。

## 4. 删除旧构建资产并迁移平台声明

删除对 `AtomUI.LinkedRegistration.props`、`AtomUI.LinkedRegistration.targets`、`AtomUI.LinkedRegistration.SidecarConsumer.targets`、`.atomui-link.json` 和 `AtomUI.Generator.LinkedPublish` 的自定义导入或引用。v6.2.2 包携带 `buildTransitive/AtomUI.Registration.targets`，普通消费方无需手动增加生成器 analyzer。生成器及其依赖位于 `tools/netstandard2.0` 与 `analyzers/dotnet/cs`，worker 位于 `tools/net10.0`，Browser 后端位于 `tools/typemap`；产品程序集位于 `lib/net10.0`。

`AtomUI.Controls` 现在也为直接消费该包的项目携带注册构建资产和工具依赖；重新打包时不要删掉这些 `buildTransitive/` 或 `tools/` 条目。

直接调用 `WindowDrawnDecorationsTheme.axaml` 对应的生成 `CompiledAvaloniaXaml.!AvaloniaResources.Build/Populate` 方法的代码也必须迁移。该主题现在有正常的 internal 资源 CLR 类；`UseDesktopControls()` 会提供包主题注册，自定义资源导入可使用正常的 `avares://AtomUI.Desktop.Controls/Window/Themes/WindowDrawnDecorationsTheme.axaml` URI。不要直接调用 internal 类或编译器生成的方法名。

### 资源平台声明收敛

主题可用平台现在由实际控件或资源 CLR 类型上的标准 .NET 声明决定。自定义 `AtomUISupportedOSPlatforms` / `AtomUIUnsupportedOSPlatforms` 元数据与 `.csproj` 主题路径排除列表已删除。若只有主题资源受平台限制，请标注资源类型，不要禁用仍可复用的控件，例如：

```csharp
using System.Runtime.Versioning;
using Avalonia.Controls;
using Avalonia.Markup.Xaml;

namespace Acme.Controls.Themes;

[SupportedOSPlatform("windows")]
public partial class WindowsOnlyThemeResources : ResourceDictionary
{
    public WindowsOnlyThemeResources() => AvaloniaXamlLoader.Load(this);
}
```

```xml
<ResourceDictionary xmlns="https://github.com/avaloniaui"
                    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
                    x:Class="Acme.Controls.Themes.WindowsOnlyThemeResources">
    <!-- 平台专属主题资源。 -->
</ResourceDictionary>
```

需要独立可用平台范围的 AXAML `ResourceDictionary` 或 `ControlTheme` 应采用正常 `x:Class` 资源身份。第三方包须使用 v6.2.2 生成器重建；不要保留已删除的元数据作为第二份平台清单，生成器不再读取它。此声明迁移不扩大 Browser 支持范围。

## 5. 验证迁移

1. 同步升级 SDK、应用目标框架和 AtomUI 包引用。
2. 使用 v6.2.2 重建第三方控件包，删除旧注册与主题元数据。
3. 删除对旧构建资产的自定义导入和引用，改用显式资源 include 与标准平台声明。
4. 清理过期 `obj` / 生成输出并重新构建，验证正常启动、主题切换及弹层模板。
5. 使用裁剪或 NativeAOT 的应用应重新发布并操作实际使用的控件。Browser 裁剪/AOT 仍需固定的 SDK/工具链；桌面发布接受兼容的后续 .NET 10 补丁工具链。

## 发布门禁审计记录

ApiCompat 以 v6.2.1 为基线报告：目标框架移除 `PKV006` 13 项、类型移除 `CP0001` 186 项、成员移除 `CP0002` 11 项、枚举常量值变化 `CP0011` 136 项。移除的类型包括旧注册/主题发现 ABI、生成的 linked-registration 类型和未声明 Own Token 的控件生成 Token 类型；成员包括上文构造器与属性、`UseAllDesktopControls()` 及生成的 AXAML 入口；常量值变化集中在 DataGrid 与 WindowTitleBar Token 枚举。这些诊断是破坏性变更的预期证据；包验证门禁不再通过 suppression 隐藏它们。

包布局校验在 [v6.2.1 布局允许清单](../../scripts/verification/package-layout-allowlist.json) 中逐项登记 14 个包的 105 条增删路径，覆盖 `lib/net8.0` 移除、旧 linked-registration 资产退役及新的 TypeMap/工具交付。这些确认只表明破坏是有意的，不会让旧二进制或 `net8.0` 消费方重新兼容。
