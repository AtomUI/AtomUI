# CT-18 G2：滚动后静止指针的悬停恢复

本记录只覆盖 DataGrid G2 的一个输入切片，完整 G2／G3 仍开放。此包独立于待审批的 30 文件快照 `946b9540d8a5`，没有 Git 提交授权。

## 合同和前证

保留 640×358 Window、原点 (24,44) 的 592×310 DataGrid、40 行、4×180 列、右冻结列、标题、footer 和双滚动条，正常动效。单选第一行，横向 wheel 到 100、纵向 wheel 到 200，期间不移动指针。实际命中哪一行，就应只有该行显示悬停；选择、几何、冻结和滚动能力保持。

实际 Application／Window 的明暗主题、三档密度及左／中／右指针，共 18 项旧版在最后悬停断言失败；候选全部通过，65.363 秒。初轮 SelectionMode=None、SizeType 类型和编译错误属于驱动准备，未计产品 RED。完整命中链、裁剪、变换、viewport、extent、offset、z-order 和逻辑／视觉祖先均已观察。

当前 Avalonia 12.1.4 的渲染 scene 通知合并可能先观察到中间布局：最终指针缓存落在 Window 模板背后的 Panel，而当前完整命中测试已经是可见 DataGridCell。指针未捕获，源坐标正确。持续渲染或仅等待已提交帧仍复现；布局中立即 Invalidate 无效。稳定后单独重绘 Window 可在不改几何／选择／offset 的情况下恢复，明暗两项通过。

真实 macOS Metal、scale2 的相同场景也复现：旧版选择／横滚四项通过、纵滚两项失败，6.576 秒。候选六项通过，5.787 秒；改用类型化 MouseDevice／RawPointerEventArgs 的独立重跑六项通过，5.849 秒，实际输入源坐标均与预期屏幕坐标一致。事件只送入自有应用的原生输入入口，没有移动 OS 指针。

## 候选边界

`DataGridRowsPresenter.ArrangeOverride` 在最终布局后请求内部 `PointerOverRefresh`。它以 ConditionalWeakTable 按 TopLevel 合并请求，等实际 composition batch 的 Rendered 后，向原始 Dispatcher 投递一次现有窗口重绘，使最终 scene 重新命中。状态只保留窗口弱引用；没有计时器、renderer 订阅、反射、输入捕获修改、尺寸修改或资源上下文创建。

## 生命周期和成本

两项临时检查通过，14.124 秒：1,000 个同窗口请求只增加一次 Window.Render，另一窗口独立增加一次；当前线程分配 680 字节，空闲 300ms 无持续重绘。关闭窗口在 PendingRefresh 状态仍被强持有时可回收，且未创建 ThemeContext。首轮 GC 驱动的 TryGetTarget 局部在 Debug 下跨 GC 保留窗口；改为 NoInlining 观察函数后通过，产品字节未变。

这些数字限定此合并请求检查，不代表整个 DataGrid 的性能验收。隐藏／重新显示和再次请求的第三项检查通过（3项31.436秒）。三 OS、Browser、原生最终像素及完整家族均未验收。
