# Motion 性能与呈现验收

本文拥有[Motion 系统](overview.md)的性能合同。源码与平台证据状态见[验证状态](verification.md)。

## 帧预算与支持矩阵

60Hz 的显示周期约为 16.67ms，120/144Hz 分别约为 8.33/6.94ms。60Hz 设备以贴合满刷新为目标，
高刷设备继续跟随实际刷新率，库不硬编码 16ms 或限制到 60FPS。
这是整帧预算；UI 与渲染流水线各自满足截止时间，不能用 Motion 管理耗时代替业务布局、绘制或 GPU 成本。

性能承诺与最低硬件、系统、后端、DPI/分辨率、刷新模式、内容规模及动画并发一起冻结。
开发机通过不等于支持矩阵通过。尚未冻结的环境不能宣称满足正式 60/120FPS 保证。

## 执行成本

- 能力满足的纯视觉轨迹在合成端执行，Motion 不主动逐帧写布局值或复制双 transform。
- 布局动画只更新必要范围；约束真实变化时正确重排，不滥用缓存或取消内容来规避工作。
- 构建、属性解析和资源求值在准备阶段进行，逐帧不重建关键帧、集合、LINQ 或绑定。
- 同一次运行使用统一时间基准，不为每个通道创建 timer，不逐帧创建 Task 或额外投递 Dispatcher。
- 手工计算仅在确有需求时复用框架 RAF；多个实际消费者需要时按 TopLevel 合并，空闲不请求下一帧。
- 使用单调经过时间求值，不补投递过期更新，不通过固定步长假定 60Hz。
- 启动/收尾分配与稳态分配分别报告；缓存有边界且不持有目标树。
- 持续反馈有明确可见性/视口策略；有限离场不能因暂停而永远不完成。

## 初始预算

下表是实现的初始验收目标，需在最低设备/负载冻结时复核，不是当前已取得的性能结果。

| 项目 | 目标 |
| --- | --- |
| Motion 自身运行管理 | 20 个内置视觉动画并发时 P99 ≤ 0.5ms/帧，框架插值/布局/绘制另列 |
| 稳态主动分配 | Motion 自身 0B/帧目标；同时报告框架、进程总分配和 GC |
| 额外逐帧 Task/Dispatcher 投递 | 0 |
| 纯视觉效果主动使布局失效 | 0 |
| 空闲持续帧调度/周期 timer | 0 |
| 参考负载呈现 | 贴合目标刷新率，漏刷新机会比例 ≤0.5%，无连续三周期丢失，无 ≥50ms 长间隔 |

20 目标只是运行管理微基准，不能代替真实复杂页面。较多目标压力和首次播放分别采样，不与稳定样本混成平均值。
总成本仍需通过目标刷新门槛；不能将大量分配归入框架后宣称页面已达标。

## 呈现测量

平台实际呈现时间戳是帧率证据；属性变化、RAF、合成 Processed/Rendered 分别用于定位，不能当作显示器 present。
参考测试固定刷新模式，记录实际周期、起止、采样误差和重复呈现；可变刷新模式另列，不能混算。
漏刷新比例为漏掉的刷新机会数/应有刷新机会数，正常 VSync 等待不作为 CPU 工作。
短动效统计多次独立动作的帧间隔分布和有效样本，不将等待或动画间隔混入帧率，也不只报平均 FPS。

记录帧间隔 P50/P95/P99、连续丢帧、首帧等待、UI/布局/渲染时间、CPU、分配、GC 和结束后的运行/终态资源数量。
性能探针不得额外请求帧或 commit 改变被测节奏；探针自身开销及无法观测的层次在报告中说明。
30FPS 视频只能作为交互与视觉证据，不证明 60/120FPS；合成批次已绘制也不是屏幕呈现已完成。

## 原生场景

Release Gallery 包括 Popup/Dialog/Drawer、侧栏与正文联动、子菜单、Collapse/Expander/TreeView、Feedback 堆叠，
以及动画期间导航、快速反向、动态内容、换模板、卸载重挂载。真实 Gallery 内容规模与布局约束保持一致。
首次、预热、多进程重复和压力分别测量；记录主题、窗口大小、缩放、后端和产品差异，前后工作负载必须可比较。

同步页面构建、纹理上传、阴影和透明叠加参与整体预算；瓶颈由对应 owner 处理。
不以缩短时长、减少循环、删除阴影、改 Push 为 Overlay、取消限高或隐藏内容作为默认达标方法。

## 性能完成条件

运行管理预算、真实呈现、布局/输入合同与资源释放同时通过才可声明对应矩阵达标。
Headless/受控时钟证明逻辑与几何，不能证明原生帧率；属性中间帧和终点正确也不能替代呈现证据。
未通过的能力/环境明确保留为未验证，不能由另一机器或另一后端的结果覆盖。
