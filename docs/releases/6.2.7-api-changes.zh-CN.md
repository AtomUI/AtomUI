# AtomUI 6.2.7 迁移指南

[English](6.2.7-api-changes.md)

6.2.7 修正启动配置的执行边界及应用资源宿主。`AppBuilder.UseAtomUI` 公开签名和 Avalonia 最低依赖版本（12.1.4）保持不变；
Release 产品包仍提供 net8.0 和 net10.0。

## 变化速查

| 范围 | 6.2.6 | 6.2.7 |
| --- | --- | --- |
| `UseAtomUI(configure)` | 登记时立即执行配置，早于平台初始化 | 只登记配置；平台 setup 完成后，在 UI 线程、Application 构造前执行 |
| 配置异常 | 从 `UseAtomUI` 调用抛出 | 在平台 setup 阶段原样抛出，通常位于 `StartWithClassicDesktopLifetime` 调用内 |
| 间接构造 AvaloniaObject | 可能早于原生后端创建 Dispatcher，破坏定时器到期时间基准 | 发生在平台已建立 Dispatcher 之后 |
| 框架资源 | 主题资源依赖子 Style 次序；显式 Application.Resources 可能移除语言 Provider | 主题与语言共用根 Styles.Resources 宿主，Initialize 前可用 |
| 全局资源覆盖 | 较晚的独立 Style.Resources 可能替换 AtomUI 默认资源 | 有意的同键全局覆盖放入 Application.Resources |
| 生成式注册组 | 包含 6.2.6 程序集标识 | 包含 6.2.7 程序集标识；需要重编译生成式消费方 |

## 配置及异常时机

正常入口保持原样：

```csharp
AppBuilder.Configure<GalleryApplication>()
          .UseAtomUIPlatformDetect()
          .WithAtomUIDefaultOptions()
          .UseAtomUI(GalleryApplication.Configure)
          .StartWithClassicDesktopLifetime(args);
```

配置回调仍可调用 `builder.UseGalleryBase(Module.Configure)`。普通模块配置可以间接构造继承 AvaloniaObject 的
数据仓库。此时 Application 尚未构造、AtomUI 内核尚未提交；依赖已提交应用资源的工作仍放在 initializer 或主窗体工厂。

`UseAtomUI` 后续语句不能依赖配置回调已经执行的副作用。相关配置应留在回调内，或放到合适的后续生命周期入口。
捕获启动错误时包围完整启动调用：

```csharp
try
{
    BuildAvaloniaApp().StartWithClassicDesktopLifetime(args);
}
catch (Exception exception)
{
    LogException(exception);
    throw;
}
```

每个 Application 实例执行一次配置；生成的 `RegisterServices` 挂接仍在 `Application.Initialize()` 前提交 AtomUI。
设计模式和 Browser/WASI 保留 Attach 中的同步回退。

## 应用资源与混合主题

AtomUI 资源仍在 `Application.Initialize()` 前可用。编译型 App.axaml 可以同时声明 FluentTheme 与显式的
Application.Resources 根字典，不再替换 AtomUI 窗口装饰或断开语言资源。完整接入见
[框架主题集成指南](../guides/theming/framework-theme-integration.md)。

框架资源现在位于 `Application.Styles.Resources.MergedDictionaries`。Application.Resources、根
Styles.Resources 的直接条目及已有应用合并字典继续优先；这些应用字典之间的相对顺序不变。
框架资源优先于子 Style/Styles 条目中的资源。

**迁移：**原来通过独立 `Style.Resources` 对 AtomUI 做全局同键覆盖的应用，应把该资源字典移入
Application.Resources，保持原有资源键和值类型。例如，已有完整 WindowDrawnDecorations 定制主题的资源文件
可以保持原内容，在应用资源层合并：

```xml
<Application.Resources>
    <ResourceDictionary>
        <ResourceDictionary.MergedDictionaries>
            <ResourceInclude Source="avares://MyApp/Themes/WindowOverrides.axaml" />
        </ResourceDictionary.MergedDictionaries>
    </ResourceDictionary>
</Application.Resources>
```

将 MyApp 与 URI 换为实际程序集和资源文件。普通 Style Setter、局部资源、显式 ControlTheme 与 Semantic Part Style
仍遵守各自的匹配、作用域及属性优先级契约。删除旧接入中加载 App.axaml 后移动 FluentTheme 或迁移语言 Provider
的兼容代码；FluentTheme 只注册一次。不要替换根 Application.Styles.Resources 或重排 AtomUI 框架前缀。

这是运行时资源优先级变化，即使没有删除 C# public 成员也需要迁移。定制应用须在最终宿主中检查共享的
Window/Popup/ScrollViewer 资源、主题与语言切换及应用显式覆盖。

## 生成式注册标识

现有生成器将包程序集版本计入公开 `ControlPackageGroup_*` 名称。版本提升会改变这些标识，即使注册 API 签名不变。
请同步升级 AtomUI 包和 Generator，重新编译应用及消费生成式注册元数据的自定义控件包，再重新发布裁剪/NativeAOT
应用。不要混用旧的预编译注册元数据与新版本包，也不要直接引用生成式组类型名。

该标识变化属于二进制兼容性变化。相对 6.2.6 的包 API 校验应如实报告，不能使用兼容性抑制隐藏。本次启动修复不引入
新的 SDK、目标框架或包布局契约。

本发布按这些生成式标识与 6.2.6 有意二进制不兼容处理，不声明与该基线的包 API 兼容；比对诊断如实保留，
不增加 ApiCompat suppression。消费方必须按上述步骤重新构建。

## 包校验结果

相对 6.2.6 的包 API 校验报告 10 条有意的 `CP0001` 诊断：`AtomUI.Controls`、`AtomUI.Desktop.Controls`、
`AtomUI.Toolkits.GalleryBase`、`AtomUI.Desktop.Controls.DataGrid` 与 `AtomUI.Desktop.Controls.ColorPicker`
中生成的 `ControlPackageGroup_*` 标识在两个目标框架上均发生变化。这些就是上文所述的二进制破坏，不得抑制。
相对 6.2.6 的包布局校验对全部 20 个包无差异，6.2.7 不改变 `tools/`、`buildTransitive/`、`build/` 或目标框架条目。

完整执行顺序见[启动生命周期](../architecture/systems/startup/lifecycle.md)，独立进程验收入口见
[启动验证](../architecture/systems/startup/verification.md)。
