#### macOS 剩余长帧分段复查

在同一个 Release Gallery 构建和同一份可记录 Metal 阶段的 Avalonia 原生库上，按原生 AppKit 时钟 → AtomUI 时钟 → AtomUI 时钟 → 原生 AppKit 时钟顺序复测。每方向每轮 6 次，均保留 Avalonia 的渲染线程代理及原目标窗口。两个时钟的回调间隔 P95 为 16.69–16.72 ms。原生时钟实测 ≥25 ms 的呈现间隔为 1/467，AtomUI 时钟为 2/464。两种实现都出现长帧，批次间可见一个刷新周期量级的首帧变化，本次数据没有分离出 AtomUI 时钟交接的稳定开销。

原生时钟下 Modal 关闭的 50 ms 长帧对应取帧至提交约 38.4 ms，AtomUI 时钟下另一笔 83.33 ms 对应约 73.2 ms。后者的 drawable 获取等待约 0.04 ms，从提交到 Metal 完成约 4.0 ms，期间仍有正常显示回调。另采样一次 33.33 ms 长帧，渲染线程持有 drawable 约 14.5 ms，线程样本落在 Skia 字形绘制和 Metal 会话收尾。该堆栈只代表观察到的执行位置。
