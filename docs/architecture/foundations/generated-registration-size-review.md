# 控件注册生成物体积评估

本文评估控件包生成物从源码生成、编译期依赖探测、应用链接到运行时包提交的体积。结论适用于共用注册契约的内置、可选、移动端、商业及第三方控件包。
这是对现有生成源码、托管程序集和架构契约的只读评估，优化后的产物、内存和裁剪结果待验。
实施顺序及旧生成入口的退役范围以[控件注册生成与启动清单优化架构](control-registration-optimization.md)为准。

## 1. 生成源码的体积分布

桌面主控件包的官方 TypeMap 样本 `GeneratedTypeMapRegistration.g.cs` 共 **3,271,350 B**、**27,357 行**，最长物理行 **609,336 B**。
统计按实际生成内容分段，包含 UTF-8 源码及换行。

| 内容 | 大小 | 占比 | 用途 |
| --- | ---: | ---: | --- |
| 两份启动清单字面量 | 1,218,040 B | 37.23% | 程序集属性供构建期读取，包定义供运行时校验和解码 |
| 1299 条 TypeMap 特性 | 420,619 B | 12.86% | 表示具体 Group、键、候选代理及其独立保留条件 |
| 控件代理 | 387,055 B | 11.83% | 单项控件接线、平台防护、Token 与语义描述符及资源工厂引用 |
| 注册与资产工厂 | 987,709 B | 30.19% | AXAML 或延迟主题工厂、导出和 owner 的真实类型引用、Schema 指纹及惰性描述符 |
| `CandidateKeys` 与 `Collect` | 64,400 B | 1.97% | 支持旧入口直接收集片段。在有启动清单的官方 TypeMap 路径中有待消除的重复 |
| 非裁剪分派桶及 `ResolveFragment` | 146,100 B | 4.47% | 无裁剪时由键定位单项代理，裁剪时走实际外部映射 |
| `ContainsAsset` 与 `ContainsFragment` | 43,844 B | 1.34% | 资产候选、平台条件和选中片段的检查 |
| 其余 | 3,583 B | 0.11% | Group、包入口、方法边界及注释等 |

同一轮现有文件样本中，Common 为 81,735 B，ColorPicker 为 152,651 B，DataGrid 为 182,947 B，GalleryBase 为 154,105 B。
桌面主包的独立 .NET 8 条件注册样本 `GeneratedConditionalRegistration.g.cs` 为 2,110,892 B，含 1 条包记录、322 条片段记录和
1299 条条件记录。它属于另一后端的输出，体积单独评估。

源码职责见[控件注册生成器](../../modules/generator/control-registration.md)、[官方 TypeMap 输出](../../../src/AtomUI.Generator/Registration/TypeMapRegistrationWriter.cs)和
[条件记录输出](../../../src/AtomUI.Generator/Registration/ConditionalRegistrationWriter.cs)。

## 2. 现有托管产物与运行时的分布

- 现有未裁剪 `AtomUI.Desktop.Controls.dll` 的 PE 元数据中，这份清单在 `#Blob` 有一份 609,020 B 的 ASCII 文本，
  在 `#US` 有一份 1,218,040 B 的 UTF-16 字符数据。Gallery Desktop 的 `#US` 还有一份同样的 UTF-16 内容。
  在这两个托管产物中，可定位的单包清单文本合计 **3,045,100 B**。该数字描述文件内容。
- Gallery Desktop 启动镜像聚合 27 份清单，托管程序集里的拼接字符串为 1,689,946 B。Browser 样本聚合 28 份，为 1,701,188 B。
  应用启动会拆分并保留用于比较的包数据。实际堆保留量、原生发布和 Browser 压缩传输大小均需分别取证。
- 启动镜像包含 593 条资源 owner 索引记录，仅 7 条是同时有直接查询路径的字符串键。索引仍承担未启用包诊断。
  优先处理整份清单副本。更改查询索引前须验证 miss 路径的零额外分配与三类键的诊断。

因此，[启动清单去冗余方案](../systems/startup/package-manifest-optimization.md)的镜像阶段主要改善应用镜像及常驻校验数据。
它不改变截图里控件包的两份清单字面量。包内字符串表阶段才会缩小这一段生成源码，以及编译后的两处相同清单。

## 3. 按风险评估优化

| 优先级 | 优化候选 | 预期收益与约束 |
| --- | --- | --- |
| P0 | 分隔大型生成文件，对清单字面量使用编译期常量分段 | 处理极长物理行和 IDE 分析负担。保持原属性、类型、成员、顺序与字符串值。只用编译期拼接。布局变更的收益以编辑器和生成物指标记录，编译和内存收益另测 |
| P1 | 同一次生成只构造并编码一次清单 | 当前有控件片段的路径在生成程序集属性和运行时定义时分别构造、编码同一清单。复用一次的结果，要求生成内容逐字节相同。收益归构建期，不计为产物和运行时内存收益 |
| P1 | 官方 TypeMap 退役旧无清单入口及其 `Collect` 与 `CandidateKeys` | 样本少约 64.4 kB 源码。源码调用链与样本托管 IL 中，现代 `Definition` 挂接 `ResolveFragment` 与 `ContainsFragment`，未发现对旧 `Collect` 的引用。删除前核对包局部扩展、生成 ABI 及各入口实际调用，保留 .NET 8 的固定 collector 模板 |
| P1 | 将重复的 TypeMap 源码限定名改为精确类型的文件内别名 | 仅用完整 Group 使用别名，对样本的文本模拟可少 86,923 B。需验证别名冲突及实际绑定。保留每个 Attribute、闭合 Group、候选类型、条件类型和 key |
| P1 | 通用清单字符串表与无损流式校验 | 依照启动清单方案，保持相等判定和所有逻辑字段。按实际收益入表的离线模型中，桌面主包两份字面量合计可少 737,160 字符。字段、算法和九包证据见[二进制结构](../systems/startup/package-manifest-optimization.md#4-包清单的二进制结构)，最终收益以候选产物和堆数据计算 |
| P2 | 减少分派重复与包索引的临时副本 | 衡量同一控件多个 key 指向同一代理产生的重复分派，以及平台资产筛选后的数组复制。保留平台检查、未知 key 语义、首次 JIT 粒度、slot 顺序和追加的对象身份。凭分段数据立项，逐项验证 |
| P2 | 检查资产工厂中的可共享纯数据，以及包内运行时文本能否改存二进制 | 资产工厂的 `typeof` 和具体工厂调用参与真实链接闭包。仅允许共享已证明等价的纯数据。二进制载荷方案需要证明参考程序集、实时 IDE 编译、预编译 NuGet 和各裁剪后端的读取边界及精确比较均等价 |
| 独立评估 | 精简 .NET 8 条件记录重复的完整身份 | 另建版本化 ABI 变更，逐个覆盖所有读写方。影响 ILLink8、ILC8 和现代桥接的绑定、规范 JSON、摘要以及模板校验。这份评估不给出缩减候选条件或修改现有 ABI 的实施授权 |

先独立验证 P0 和 P1 的输出等价，清单阶段沿既有方案执行。发布和性能采样在批准的变更稳定后合并进行；P2 和 ABI 研究等待已定位的剩余成本。
常量共享是否缩减编译后的重复存储须看 PE 验收，源码一处声明不代表编译后各元数据流只存一份。

## 4. 裁剪契约与否决条件

- **官方 TypeMap。** Group、现有 key 组成、独立保留条件与 proxy 绑定相同。闭合具体 accessor 保留原调用形态。运行时查询仍依照有效的
  `TryGetValue` 契约。保留 AssetId、ThemeVariant、真实资源类型和每个 `typeof` 依赖。[官方 TypeMap 契约](aot-typemap-registration.md)
- **Browser 及 Mono 路径。** Mark 后的选择仍由官方标记结果驱动，并保持 Sweep 前转换。helper 的可达性、完整程序集身份和固定 accessor
  ABI 不变。实际发布证明仅已选代理参与转换，未用 proxy 及工厂被删除。[Browser 链接架构](aot-browser-linking.md)
- **.NET 8 及混合消费。** 条件记录中每条依赖、规范 thunk、collector 模板、执行顺序以及桥接原包到转换产物的身份都须保持。
  原生、托管及 Browser 已支持的混合消费分别对照实际产物。[.NET 8 条件后端](aot-net8-conditional-backends.md) · [条件记录 ABI](../../reference/aot/conditional-registration-contract.md)
- **运行时与资源。** 同一批正向与负向场景覆盖控件、Token-only、Identity-only、Semantic Style-only、多目标/共享主题、
  平台 guard、间接引用、可选包缺失和包追加失败。保持 slot、资源覆盖优先级、对象惰性、提交与回滚。[注册与资源契约](control-registration-contracts.md) ·
  [启动生命周期](../systems/startup/lifecycle.md) · [主题惰性物化](../systems/theming/lazy-materialization.md)

统一索引或通用工厂表不得引入全包类型根。不得以字符串替换 linker 需要的真实 CLR 引用，不得合并独立条件或退回全量注册。
如果出现裁剪集合差异，同一项变更停在该阶段。只有按实际支持的发布路径验证已用类型和工厂保留、未用项排除，且运行行为和诊断一致，才能放行。

## 5. 取证和交付口径

1. 固定 SDK、后端、平台、项目引用和构建配置。保留基线生成属性、逐条件映射、工厂和依赖边。候选按真实程序集和类型身份逐项对照，含排序、键和方法体契约。
2. 复用现有裁剪正反例和真实预编译包消费。比较 actual selected 集合、未选排除集合与混合 ABI 中间产物；运行首窗、模板、主题切换和资源查询。
   缺失适用后端的发布或运行证据时只保留已取证范围的结论。
3. 分别报告生成 C# 字节及最长行、构建/IDE 分析时间、PE 及 NativeAOT/Browser 发布字节、启动分段、分配及常驻堆。
   采用[既有裁剪放行与体积口径](aot-and-trimming.md#8-验证与交付门槛)和[启动验收线](../systems/startup/verification.md)。
4. 每一项变更可独立撤回。失败时首先保住逻辑与裁剪等价，再决定是否保留已验证的体积优化。当前仅有采样、代码路径及文档审查证据。
