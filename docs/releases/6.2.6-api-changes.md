# AtomUI 6.2.6 API Change Examples

This document describes the startup and theme API changes released in AtomUI 6.2.6, relative to AtomUI 6.2.5.
These source and binary compatibility changes require applications and generated consumers to migrate before rebuilding.

Chinese version: [AtomUI 6.2.6 API 变更示例](6.2.6-api-changes.zh-CN.md).

See the [startup architecture](../architecture/systems/startup/overview.md) for the design and the
[startup guide](../guides/startup/overview.md) for examples.

## Quick reference

| Area | 6.2.5 | 6.2.6 migration |
| --- | --- | --- |
| AtomUI entry point | `Application.UseAtomUI(Action<IAtomUIBuilder>)` in `App.Initialize()` | `AppBuilder.UseAtomUI(Action<IAtomUIBuilder>)` in `BuildAvaloniaApp()` |
| Application hookup | None | Mark the application class `partial` so the generator emits `RegisterServices`, or call `ApplicationStartup.Attach(this)` manually |
| Configuration callback | Ran after the application object existed | Runs before platform initialization; only declare packages and settings, and move committed work into `AddInitializer` |
| Startup Splash | `AtomUI.Desktop.Controls.Extras` Splash, shown and closed manually | Framework-managed `AtomUI.Controls` Splash configured with `UseSplash`; loading moves to `UseMainWindow` |
| macOS rendering | OpenGL, then Metal, then Software | Metal, then OpenGL, then Software; override `AvaloniaNativePlatformOptions` to keep OpenGL |
| `IThemeManagerBuilder` | No compiled-theme package member | Add `AddCompiledThemePackage(CompiledThemePackage)` to custom implementations |
| `ILocalizationBuilder` | No module-data member | Add `AddModuleData(string, string)` to custom implementations |
| Generated registration groups | `ControlPackageGroup_*` names contain the 6.2.5 assembly identity | Names contain the 6.2.6 identity; upgrade packages together and rebuild compiled consumers |
| Theme source identities | `AtomUI.Core.BuiltInThemes` and `avares://AtomUI.Core/...` | `AtomUI.Core` and logical paths such as `AtomUI.Core/Assets/Themes/...` |
| Startup package manifest | Version 1 | Version 2; version 1 manifests are rejected with a rebuild message |
| Avalonia dependency | 12.1.3 | 12.1.4 minimum; update pinned Avalonia packages before upgrading AtomUI |
| Package layout | No compiled-theme build target, no Avalonia assemblies in `tools/net10.0` | Adds `buildTransitive/AtomUI.CompiledThemes.targets` and the Avalonia task dependencies; font packages now ship the registration payload |

## Breaking changes

### The entry point moves from `Application.UseAtomUI` to `AppBuilder.UseAtomUI`

`Application.UseAtomUI(Action<IAtomUIBuilder>?)` is removed. Declare the configuration on the `AppBuilder` chain:

```csharp
// 6.2.5: App.axaml.cs
public override void Initialize()
{
    AvaloniaXamlLoader.Load(this);
    this.UseAtomUI(builder =>
    {
        builder.WithInitialTheme(IThemeManager.DEFAULT_THEME_ID);
        builder.UseDesktopControls();
    });
}
```

```csharp
// Now: Program.cs
public static AppBuilder BuildAvaloniaApp() =>
    AppBuilder.Configure<App>()
              .UseAtomUIPlatformDetect()
              .WithAtomUIDefaultOptions()
              .UseAtomUI(builder =>
              {
                  builder.WithInitialTheme(IThemeManager.DEFAULT_THEME_ID);
                  builder.UseDesktopControls();
              });

// Now: App.axaml.cs
public partial class App : Application
{
    public override void Initialize() => AvaloniaXamlLoader.Load(this);
}
```

AtomUI is committed before `Initialize()`, so `App.axaml` can reference AtomUI resources directly. `GetThemeManager()`,
`GetLocalizer()` and `GetLanguageManager()` are unchanged.

### The application class must be hooked

Declare the application class `partial`; the AtomUI generator emits a `RegisterServices` override that calls
`ApplicationStartup.Attach(this)`. When the class cannot be partial, write the override yourself:

```csharp
public override void RegisterServices()
{
    base.RegisterServices();
    ApplicationStartup.Attach(this);
}
```

A handwritten `RegisterServices` override that does not call `Attach` reports the new compile error `ATOMUIGEN039`. A
class that is neither hooked nor partial fails after `Initialize()` with an `InvalidOperationException` that explains the
fix. Do not create controls or access themes in the application constructor.

### The configuration callback runs before platform initialization

The configuration callback now runs on the main thread before Avalonia's platform initialization. It must not access
`FontManager`, `Application.Current` or `TopLevel`, and must not create bitmaps or controls. `UseAlibabaSansFont()` and
`UseAlibabaPuHuiTiFont()` now register their font collections when AtomUI is committed. Move code that needs a
committed AtomUI into `builder.AddInitializer(themeManager => …)`.

### Splash moves to `AtomUI.Controls`; the Extras Splash is removed

The startup Splash is now managed by the framework, and the Extras Splash implementation is removed:

```csharp
using AtomUI.Controls;

builder.UseSplash(SplashMode.Auto, splash => splash
    .WithLogo(new Uri("avares://MyApp/Assets/logo.png"))
    .WithTitle("My App"));
```

- The Splash appears before AtomUI is committed and hides and closes automatically after the main window's first rendered
  batch. Manual closing and the minimum display duration are gone.
- Application-owned loading during startup (previously done while updating a manually shown Splash) moves to
  `builder.UseMainWindow(async context => …)`, which reports progress through `context.Progress`.
- Customize the look with `WithControlTheme<TTheme>()`, using only Splash controls, basic Avalonia elements and global
  tokens.
- The new `AtomUI.Controls.Splash` is a `TemplatedControl`, not a `ContentControl`; in-page previews must merge
  `SplashDefaultTheme`.

`AtomUI.Desktop.Controls.Extras` no longer contains a Splash. The following public types are removed from that package:

- Control and service API: `Splash`, `SplashWindow`, `SplashStatus`, `SplashOptions`, `SplashService`, `ISplashService`
  and `SplashPseudoClass`, including the `Splash` static show/message/progress/status API and `Splash.DefaultService`.
- Generated token API: `SplashTokens`, `SplashTokenKey`, `SplashTokenKind`, `SplashTokenResourceExtension`,
  `SplashWindowTokens`, `SplashWindowTokenKey` and `SplashWindowTokenResourceExtension`.
- Generated Semantic Part styles: `SplashTitleStyle`, `SplashSubtitleStyle`, `SplashMessageStyle`, `SplashContentStyle`,
  `SplashFooterStyle`, `SplashLogoStyle`, `SplashSpinStyle`, `SplashDetailStyle` and `SplashProgressBarStyle`.
- Removing the Extras XAML also removes its `CompiledAvaloniaXaml.!XamlLoader` and `!AvaloniaResources` types; those are
  compiler-generated and not a consumer contract.

The new `AtomUI.Controls.Splash` is a `TemplatedControl` with no control-token or generated Semantic Part style types:
size, color and typography values live in `SplashDefaultTheme`, and appearance overrides go through
`WithControlTheme<TTheme>()`. Token-based customization of the old Extras Splash does not carry over.

`AtomUI.Desktop.Controls.Extras` currently has no controls. `UseDesktopExtras()` remains and registers an empty package.

### macOS now prefers Metal

On macOS, `WithAtomUIDefaultOptions()` changes the rendering order from OpenGL, Metal, Software to Metal, OpenGL,
Software. OpenGL was preferred to avoid Metal content jitter during live resize, which Avalonia 12.1.0 fixed. To keep
OpenGL, override after `WithAtomUIDefaultOptions()`:

```csharp
.WithAtomUIDefaultOptions()
.With(new AvaloniaNativePlatformOptions
{
    RenderingMode = [AvaloniaNativeRenderingMode.OpenGl, AvaloniaNativeRenderingMode.Metal, AvaloniaNativeRenderingMode.Software]
})
```

### `IThemeManagerBuilder` gains a member

`IThemeManagerBuilder` adds `AddCompiledThemePackage(CompiledThemePackage)`. Code that implements the interface must add
it.

### `ILocalizationBuilder` gains module-data registration

`ILocalizationBuilder` adds `AddModuleData(string moduleId, string data)`. Custom implementations must add the member and
register each generated localization module exactly once. Generated consumers should use the matching Generator and
Localization package versions so module data is verified before the localization registry is frozen.

Before:

```csharp
public sealed class CustomLocalizationBuilder : ILocalizationBuilder
{
    public void AddCatalog(LanguageCatalogDescriptor descriptor) { /* existing implementation */ }
    public void AddTranslationBundle(TranslationBundleDescriptor descriptor) { /* existing implementation */ }
    public void AddLanguageDefinition(LanguageDefinition definition) { /* existing implementation */ }
    public void ConfigureLanguages(LanguageTag defaultLanguage, IEnumerable<LanguageTag> supportedLanguages) { /* existing implementation */ }
}
```

After:

```csharp
public sealed class CustomLocalizationBuilder : ILocalizationBuilder
{
    public void AddModuleData(string moduleId, string data)
    {
        // Store and validate the generated module payload before freezing the registry.
    }

    // Keep the existing ILocalizationBuilder members.
}
```

### Theme source identities change (visible in diagnostics)

- The built-in theme registration identifier changes from `AtomUI.Core.BuiltInThemes` to `AtomUI.Core`.
- Built-in theme source identities change from URIs such as `avares://AtomUI.Core/Assets/Themes/DaybreakBlue.theme.xml`
  to logical paths such as `AtomUI.Core/Assets/Themes/DaybreakBlue.theme.xml`.

Update code that matches theme diagnostics by these strings.

### Generated registration group identities change

The public `AtomUI.Generated.*.ControlPackageGroup_*` type names change in `AtomUI.Controls`, `AtomUI.Desktop.Controls`,
`AtomUI.Toolkits.GalleryBase`, `AtomUI.Desktop.Controls.DataGrid`, `AtomUI.Desktop.Controls.ColorPicker` and
`AtomUI.Desktop.Controls.Extras`. The generator hashes the package assembly identity, which includes the package version,
into each group name, so a precompiled consumer cannot bind a 6.2.5 group type to the corresponding 6.2.6 type.

Upgrade all related AtomUI packages and the Generator together, then rebuild applications and custom control packages that
consume generated registration metadata. Republish trimmed or NativeAOT applications so linking uses the current groups.
Do not refer to the generated group names directly; use `UseAtomUI`, `UseDesktopControls()` and the other package
registration APIs instead. The `AtomUI.Fonts.AlibabaSans` and `AtomUI.Fonts.AlibabaPuHuiTi` packages now participate in
the same registration pipeline, so their generated identities follow the same rule.

## New APIs

Startup types use role names without the `AtomUI` prefix: `ApplicationStartup`, `IStartup`, `StartupState`,
`StartupProgressEventArgs`, `StartupProgress`, `MainWindowContext` and `StartupBuilderExtensions`.
These APIs have not been released in 6.2.5. Applications built against an earlier startup preview must update explicit
type references and rebuild with the matching Core and Generator.

- `AppBuilderExtensions.UseAtomUI(this AppBuilder, Action<IAtomUIBuilder>)` and `ApplicationStartup.Attach(Application)`.
- `Application.GetStartup()` and `IStartup`: `State` (`Preparing`, `Committed`, `Presenting`, `Ready`, `Failed`,
  `Canceled`), `Completion` and `ProgressChanged`.
- `UseMainWindow(Func<MainWindowContext, Task<Window>>)`, `MainWindowContext` and `StartupProgress`.
- `SplashMode`; in `AtomUI.Controls`: `UseSplash`, `SplashOptionsBuilder`, `Splash`, `SplashWindow`, `SplashProgressBar`,
  `SplashStatus` and `SplashDefaultTheme`.
- The `AtomUI-Startup` EventSource (disabled by default).
- Compiled theme package infrastructure: `CompiledThemePackage`, `CompiledThemeProgram`, `CompiledThemeBindingBuilder`,
  `CompiledThemeValueWriter`, `ThemeBuildOwnerAttribute` and `ThemeBuildTokenAttribute` in
  `AtomUI.Theme.Definitions.Compiled`, plus the generated `AtomUI.Generated.AtomUICore.GeneratedThemePackageRegistration`
  in `AtomUI.Core`. These types serve generated code. Do not call `GeneratedThemePackageRegistration.Register` yourself:
  Core registers its own package automatically, and a second call registers it twice.

## Startup package manifest version 2

Rebuild control packages and applications with the matching Generator/Core. Startup package manifests and application startup
images now use version 2, carrying exact owner/key defining assemblies, semantic property/target contracts and global resource-key
schema evidence. Version 1 is rejected with a rebuild message. Conditional registration, compiled-theme and language ABIs keep their
independent versions.

`Application.GetAtomUI()` returns the application's `IAtomUI` runtime. After initial commit, call
`LoadPackages(Action<IAtomUIBuilder>)` on the UI thread to append packages atomically. Initial application settings cannot be changed
through this entry. See [package authoring](../guides/startup/package-authoring.md) for rollback and lifecycle rules.

## Build and package layout additions

The registration packages add build assets; no consumer-visible file is removed.

### Avalonia dependency advances to 12.1.4

AtomUI packages now depend on Avalonia 12.1.4 (`Avalonia`, `Avalonia.Desktop`, `Avalonia.Wayland`, `Avalonia.X11` and the
other platform packages). The package manifest declares 12.1.4 as the minimum, so a solution pinned to 12.1.3 must move to
12.1.4 before it can consume AtomUI 6.2.6. The Wayland shared-clock adapter no longer checks the Avalonia assembly version;
it validates the dispatcher backend and clock structure instead.

- `buildTransitive/AtomUI.CompiledThemes.targets` ships in every registration package. Its
  `GenerateAtomUICompiledThemeInputs` target runs only when the project declares `AtomUIThemeDefinition` items, and it adds the
  generated `.atomuithemeinput` files as `AdditionalFiles` for the compiler. Projects without theme definitions see no new
  build step.
- `tools/net10.0` now carries the Avalonia implementation assemblies (`Avalonia.Base`, `Avalonia.Controls`, `Avalonia.Markup`,
  `Avalonia.Markup.Xaml`, `Avalonia.Dialogs`, `Avalonia.DesignerSupport`, `Avalonia.Metal`, `Avalonia.OpenGL`, `Avalonia.Vulkan`,
  `Avalonia.MicroCom`, `Avalonia.Remote.Protocol`, `Avalonia`, `MicroCom.Runtime`) because the compiled-theme build task loads
  Avalonia types in its isolated task process. The task process never loads consumer copies of these assemblies.
- `AtomUI.Fonts.AlibabaSans` and `AtomUI.Fonts.AlibabaPuHuiTi` now participate in the startup package registration pipeline and
  therefore ship the standard `buildTransitive` and `tools` payload. Reference them like any other AtomUI package.

### Package validation results

Package API validation against 6.2.5 reports 68 intentional diagnostics across 8 of 20 packages and both target frameworks:
2 `CP0002` for the removed `Application.UseAtomUI`, 4 `CP0006` for the two interface members, 12 `CP0001` for the generated
registration group identities and 50 `CP0001` for the removed Extras Splash types. These are documented source and binary
breaks, not a passing compatibility check, and they must not be suppressed. Package layout validation against 6.2.5 reports
only the additions listed above; they are acknowledged in `scripts/verification/package-layout-allowlist.json`.
