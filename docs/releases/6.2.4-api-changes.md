# AtomUI 6.2.4 API Change Examples

AtomUI 6.2.4 restores .NET 8 Release assets and changes TimePicker defaults, editing behavior and popup geometry. Despite the patch version, upgrading requires reviewing the contracts below and rebuilding consumers and custom control packages together.

Chinese version: [AtomUI 6.2.4 API 变更示例](6.2.4-api-changes.zh-CN.md).

## Quick reference

| Area | 6.2.3 | 6.2.4 migration |
| --- | --- | --- |
| TimePicker / RangeTimePicker confirmation | `IsNeedConfirm=False` by default | Default is `True`; configure `False` explicitly for commit on close/focus loss. |
| TimePicker clock | Default enum value `HourClock12` | Default is `HourClock24`; configure `HourClock12` explicitly when required. |
| Time-column scrolling | Scrolling updates the selection | Default browsing does not change the candidate; opt in with `IsChangeOnScroll=True`. |
| Time candidate submission | No-confirm row selection can confirm immediately | Row selection edits the candidate; review close, focus-loss, endpoint-switch and Now submission timing. |
| Time popup geometry | Standard columns 40 (the `PeriodHostWidth` token default is 50); seven rows | Standard columns 56, new item padding and eight rows; review custom layouts and token overrides. |
| Release frameworks | Product libraries contain only `net10.0` | Product libraries contain `net8.0` and `net10.0`; builds still require the .NET 10 tool host. |
| Source build tools | Separate Build.Tasks and TypeMap.Linker projects | Use `AtomUI.Toolchain` and its preparation targets; update source paths and direct custom task calls. |
| Registration groups | Version-specific public `ControlPackageGroup_*` identities | Rebuild consumers and republish trimming/AOT output; do not reference generated names directly. |

## 1. TimePicker defaults and candidate submission

Both TimePicker and RangeTimePicker now default to `IsNeedConfirm=True` and `ClockIdentifier=HourClock24`. Selecting a row edits the candidate. An ordinary close in confirmation mode discards an unconfirmed candidate; confirmation commits a valid candidate. With confirmation disabled, valid candidates commit on close or focus loss; switching the active endpoint also finalizes the previous endpoint in RangeTimePicker.

To retain individual previous modes, configure them explicitly:

```xml
<atom:TimePicker IsNeedConfirm="False"
                 ClockIdentifier="HourClock12"
                 IsChangeOnScroll="True" />
<atom:RangeTimePicker IsNeedConfirm="False"
                      ClockIdentifier="HourClock12"
                      IsChangeOnScroll="True" />
```

These settings do not restore every previous event timing. Review TwoWay bindings, selection handlers and Form observers that depend on an immediate submission while a popup remains open. The Now action explicitly commits in both confirmation modes, aligns the value to the configured minute/second increments, and closes an ordinary TimePicker popup. RangeTimePicker advances to the missing opposite endpoint while keeping the popup open, or closes a completed range; pinned popup operations retain the open state. Confirm, Enter and valid edited input follow the common submission rules.

`IsChangeOnScroll=False` is the new default: wheel/trackpad scrolling browses a column without selecting a candidate. Set it to `True` when scrolling should select a candidate. It does not bypass confirmation. Column focus scrolling is handled within the popup and does not move the surrounding page.

## 2. Time popup geometry and custom themes

TimePicker's presenter displays eight rows. The hour/minute/second columns loop with the selected row centered and no visible vertical scrollbar; the AM/PM column can show its scrollbar. Review custom popup sizing and templates that assume the previous seven-row geometry or scrollbar behavior.

| TimePicker token | Previous default | New default |
| --- | --- | --- |
| `ItemWidth` | `40` | `ControlHeightLG * 1.4` (56 in the standard theme) |
| `PeriodHostWidth` | `50` | `ItemWidth` |
| `ItemPadding` | Vertical `UniformlyPaddingXXS` | Left padding `(ItemWidth - ItemHeight) / 2`, other sides zero |

The standard item height remains 28, so standard padding changes from `(0,4,0,4)` to `(14,0,0,0)`. Use the existing named-token override mechanism where an application requires different dimensions; recalculate padding when changing column width. Token names, existing token enum values, Semantic Part identities and PART names remain intact. Shared DatePicker hosts retain their own sizing and submission policies.

## 3. Restored .NET 8 packages and AOT routing

Release product packages now contain `lib/net8.0` and `lib/net10.0`; Debug product builds still target `net10.0`. AtomUI.Toolchain itself runs on .NET 10. A .NET 8 application does not gain a .NET 10 deployment dependency, but an SDK8-only build environment is insufficient for the supplied tools.

The application target framework selects dependency analysis automatically:

- .NET 8 uses the compatibility backend with official ILLink8 or the admitted ILC8 adapter.
- .NET 10 and later select the matching official TypeMap engine. Actual framework API and tool capabilities must pass validation; an unknown combination does not fall back to the .NET 8 backend.
- `AtomUIEnableNet8ManagedRegistration`, `AtomUIEnableNet8NativeRegistration` and `AtomUIEnableConditionalRegistrationBridge` are unsupported prerelease routing overrides, not released 6.2.3 switches. Remove such routing overrides from custom build scripts and use the application's real target and publish properties.

.NET 8 managed trimming currently binds to ILLink 8.0.27 on the .NET 10 host. Native8 is admitted for SDK10.0.300, runtime/ILC8.0.27, full trimming, an osx-arm64 tool host and osx-arm64/osx-x64 whole-program executables. Windows/Linux Native8 consumers and net8 Browser are not admitted by this release.

Modern applications automatically convert supported net8-only generated inputs before official analysis. Current mixed-input admission requires SDK10.0.300 and full trimming, covering the documented net10/osx-arm64 managed and NativeAOT combinations and net10-browser/browser-wasm. NativeAOT additionally requires runtime10.0.8 and a single-module executable. Browser requires `WasmEnableWebcil=False`; bridged managed ReadyToRun/single-file paths are not admitted. See [framework routing](../modules/toolchain/framework-routing.md) and [.NET 8 backends](../architecture/foundations/aot-net8-conditional-backends.md) for the precise limits.

Upgrade related AtomUI packages, Generator and third-party generated control packages together. Rebuild precompiled consumers and republish trimmed/AOT applications. Public `ControlPackageGroup_*` names derive from the versioned assembly identity and change again in 6.2.4; application code must not bind to their generated names. A documented migration requirement does not constitute binary compatibility with 6.2.3, and ApiCompat diagnostics for removed generated groups must not be suppressed.

The actual 6.2.3 baseline comparison detects one removed generated group in each of `AtomUI.Controls`, `AtomUI.Desktop.Controls`, `AtomUI.Toolkits.GalleryBase`, `AtomUI.Desktop.Controls.DataGrid`, `AtomUI.Desktop.Controls.ColorPicker` and `AtomUI.Desktop.Controls.Extras`. Other released package API comparisons pass. These six identity changes are retained as explicit incompatibility diagnostics, not suppressed; this release requires a rebuild instead of claiming 6.2.3 binary compatibility. Package layout is audited independently against the same baseline.

## 4. Source builds and custom task integrations

Replace direct references to `src/AtomUI.Build.Tasks/AtomUI.Build.Tasks.csproj` and `src/AtomUI.TypeMap.Linker/AtomUI.TypeMap.Linker.csproj` with the single Toolchain project:

```sh
# Ordinary build worker
dotnet build src/AtomUI.Toolchain/AtomUI.Toolchain.csproj
# Worker and managed publish backends
dotnet build src/AtomUI.Toolchain/AtomUI.Toolchain.csproj -t:BuildManagedToolchain -c Release
# Complete maintainer package-tool preparation, including the ILC8 managed bundle
dotnet build src/AtomUI.Toolchain/AtomUI.Toolchain.csproj -t:BuildToolchain -c Release
```

Repository output moves under `.artifacts/bin/<Configuration>/toolchain/tasks`, `illink8` and `illink10`, each with its net10 host subdirectory. Normal installed NuGet consumers retain `tools/net10.0/AtomUI.Build.Tasks.dll` and do not build compiler source. Point custom `AtomUIBuildTasksAssembly` overrides to `toolchain/tasks/net10.0/AtomUI.Build.Tasks.dll`, keeping its deps.json, runtimeconfig.json and Microsoft.Build.Framework.dll beside it. Remove the old `AtomUITypeMapBackendProject` preparation hook in favor of the Toolchain build entry points. `pack --no-build` consumes tools that have already been prepared.

Packages ship additional framework/net8/bridge targets, the unified `AtomUI.Toolchain.Tasks.targets` declarations and version-isolated backend tools. Let package-specific targets import these; do not copy only the older subset of buildTransitive files into a custom integration.

Direct calls to `ValidateRegistrationToolchainTask` must now supply the application's `TargetFrameworkIdentifier` and `TargetFrameworkVersion`, such as `.NETCoreApp` and `v10.0`. The provided targets supply these automatically. Source callers filter application TFM/RID properties at the tool build/restore boundary; directly building Toolchain with application `TargetFrameworks` or runtime identifiers is rejected.

## 5. ColorPicker confirmation is opt-in

ColorPicker and GradientColorPicker keep `IsNeedConfirm=False` by default. Enable it explicitly to use Confirm/Cancel:

```xml
<atom:ColorPicker IsNeedConfirm="True" Value="{Binding Color}" />
<atom:GradientColorPicker IsNeedConfirm="True" Value="{Binding Gradient}" />
```

In this mode, edits and clearing remain drafts until confirmed; cancellation or ordinary dismissal discards them. Explicit confirmation takes precedence over the solid picker's `ValueSyncStrategy`. Add Confirm/Cancel text to custom language catalogs when using this mode. Existing `ColorPickerLangResourceKind.EmptyColorText=0` remains unchanged; new members are appended. Existing Semantic Parts and Token identities remain intact.
