# AtomUI 6.2.12 migration guide

[简体中文](6.2.12-api-changes.zh-CN.md)

This guide covers upgrading from 6.2.11. Avalonia remains 12.1.4; Release runtime packages continue to target
net8.0 and net10.0 with the existing SDK requirements. See the [Changelog](../../CHANGELOG.md) for release highlights.

## Quick reference

| Area | 6.2.11 | 6.2.12 / migration |
| --- | --- | --- |
| Component popup motion | Defaults and configuration differ by component | Consistent component defaults; configure `OpenMotion`/`CloseMotion` on the owner |
| Popup closure | Callers may assume `Close()` immediately removes the host | Leave motion can continue; wait for actual `Closed`, or disable motion |
| ComboBox empty source | No empty indicator without an effective filter | Empty indicator enabled by default; set `IsShowEmptyIndicator="False"` to hide it |
| DataGrid selection | Ordinary clicks can change selection despite `SelectIndicator` | Indicator mode preserves selection; choose `SelectTriggerType="Cell"` for cell-driven selection |
| Generated registration groups | Names encode the 6.2.11 assembly identity | Names encode 6.2.12; upgrade the package set and rebuild generated consumers |

## Component defaults and physical closure

Selector and picker popups use Slide motion; dropdowns, menus, navigation submenus, tooltips and popovers use
their component-specific Slide/Zoom defaults. Configuration lives on the component that owns the popup:
`AbstractSelect`, `InfoPickerInput`, `AbstractAutoComplete`, `AbstractColorPicker`, ComboBox, DropdownButton,
SplitButton, FlyoutHost, Flyout, ContextMenu, MenuItem and ToolTip. Concrete controls inherit their family contract.
DataGrid filter configuration belongs to its actual Flyout, rather than a new grid-wide motion property.

The properties are nullable `AbstractMotion` values. Application Styles, bindings and local values override theme
defaults. Explicit null disables that direction; clearing the override restores the theme default. Direct Popup
instances continue to have no default motion. Existing explicit motion definitions remain supported.

To keep a component's popup unanimated:

```xml
<atom:ComboBox OpenMotion="{x:Null}" CloseMotion="{x:Null}" />
```

Alternatively, set the existing `IsMotionEnabled="False"` to disable both directions on the component. Disabling
motion or the global `EnableMotion` token settles playback to the latest requested state.

`Close()` requests closure; with leave motion enabled, the physical host can remain until playback completes.
Move work that requires host removal to the actual Popup/ContextMenu `Closed` notification. In UI tests, advance
the rendering clock and wait for closure with a bounded timeout before clicking content behind the old popup.
Do not inspect internal host-state properties or replace state-based waiting with a fixed sleep.

## ComboBox empty content

ComboBox now shows its empty indicator for both an empty source and a filter with no visible matches.
`IsShowEmptyIndicator` defaults to true. To retain the previous empty-source display:

```xml
<atom:ComboBox IsShowEmptyIndicator="False" />
```

Use `EmptyIndicator`, `EmptyIndicatorTemplate` and `EmptyIndicatorPadding` for custom content. A template-only
configuration can render null content, provided its `IDataTemplate.Match` accepts that content. The default theme
provides shared padding and a small built-in Empty illustration when both content and template are null.
Filtering and selection semantics remain unchanged. The existing `popup.empty` part and
`ComboBoxPopupEmptyStyle` remain the declarative styling entry point; no code-behind node lookup is required.

## DataGrid indicator-driven selection

`SelectTriggerType` continues to default to `SelectIndicator`. Clicking an ordinary cell or blank space inside a
selection cell now preserves the selected rows; clicking the checkbox/radio indicator changes selection.
Current-cell movement, focus and editing remain available. Applications that expect ordinary cell clicks to select
rows must opt into the existing Cell mode:

```xml
<atom:DataGrid SelectTriggerType="Cell" />
```

Cell mode retains ordinary click, Ctrl and Shift selection behavior. Remove compensation handlers that manually
undo cell-driven selection when using indicator mode.

## Generated registration identities

Generated `AtomUI.Generated.*.ControlPackageGroup_*` type names include the assembly identity and change with
6.2.12. Upgrade related AtomUI packages and any explicit Generator reference together, clean and rebuild custom
control packages and applications, then republish trimmed/NativeAOT applications. Replacing DLLs without rebuilding
generated consumers is insufficient. Do not reference generated group names directly or mix compiled 6.2.11
registration metadata with 6.2.12 packages. This follows the [6.2.11 migration precedent](6.2.11-api-changes.md).

## Compatible fixes

Empty restores its image when reattached and retains the last complete SVG while resources are temporarily
unavailable. Retired popup/template resources are released without retaining owners through motion definitions.
Windows borderless topmost fullscreen rendering is repaired without changing the configured rendering backend.
DatePicker and TimePicker again display right-side add-on templates, icons and Form feedback through their shared input theme.
These fixes require no new application configuration.

## Package validation

All 21 release packages were compared with the published 6.2.11 packages. The historical API comparison reports
10 `CP0001` diagnostics: one versioned registration group in each of Controls, Desktop.Controls, GalleryBase,
DataGrid and ColorPicker, across net8.0 and net10.0. The other 16 packages pass; there are no other API incompatibilities
or unresolved-reference diagnostics.

The historical API gate therefore fails for the documented registration identities. No suppression is added,
and this release does not claim binary compatibility with 6.2.11. Following the 6.2.11 publication strategy,
the normal release pack uses no historical API baseline and succeeds for all 21 packages, including target-framework
validation. All 21 package layouts match 6.2.11 without an allowlist change. The runtime behavior changes above
remain part of the manual migration audit, since an assembly API comparison cannot detect them.
