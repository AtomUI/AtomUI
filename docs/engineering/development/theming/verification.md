# 主题验收与兼容性规范

> 本文定义验收要求。检查结果必须来自实际执行，不能以设计文档更新代替产品验证。

本文的适用范围、规范用语与事实边界见[全局规范入口](overview.md)。

本文拥有主题研发的兼容、例外和交付证据要求，消费路径见[控件消费规范](consumption.md)。测试去留与执行范围继续由已有全局工程规范拥有。

跨模块设计的现行实现与目标差异统一见[主题实现与验证边界](../../../architecture/systems/theming/verification.md)；该文档维护机制状态，本文维护验收方法和证据要求。

### TH-12：兼容性、例外与验收证据

性质：现行兼容/验证约束＋新增统一主题门禁。

- Token名称/类型/单位/阶段、资源key、identity、Part契约、样式优先级、默认和状态行为、计算及配置协议均属于需审查的合同。
- 变更明确选择兼容修复、版本化演进或弃用迁移；不能用“清理写死值”隐藏公开行为变化。
- 新建或触及的相关路径不得新增违规；涉及的既有断链必须修复，或在超出授权/兼容范围时报告阻塞及具体后续决策，不能当作已经完成。
- 合法常量/平台边界/Reserved是分类，不是豁免。真正例外必须在对应正式文档或交付评审中说明规则、技术原因、范围、等价保障与复核条件；不得由作者或agent自行永久豁免，不建立宽泛忽略列表。
- 文档、schema、模板、自绘及Gallery示例表达同一合同；按当前测试生命周期保留最小充分长期保障，临时验证执行后清理。
- 优化与重构必须通过下述视觉一致性硬门槛。主题可定制能力提升不能替代既有外观兼容验收。

检查：兼容影响审查、例外理由、逐项证据、临时产物清理与最终受影响模块验证。

## 视觉一致性硬门槛

**相同环境、相同配置和相同状态下，优化与重构前后控件不得有视觉差异。** 默认主题、默认参数及既有已支持的定制配置都属于兼容基线；不能只验证新品牌更好看或默认颜色相同。

### 基线与覆盖

- 每个纳入范围Control在修改前建立可重复的基线；内部frame、文字/图标、自绘及弹层按实际公开owner归属。共享机制影响的全部消费者也要比较，代表用例不能代替最终逐控件覆盖。
- 基线记录源码commit及未提交差异、实际可执行文件/依赖版本、OS/渲染Host、DPI/缩放、字体、ClientSize、主题/算法/配置、数据和资源、语言/方向、滚动位置、焦点与状态。前后使用相同条件；各平台分别与自己的基线比较。
- 按适用性覆盖Light/Dark、普通/Compact、S/M/L/Custom、方向/variant，以及正常、hover、pressed、focus、disabled、checked/selected、校验、loading和展开等视觉分支；覆盖实际Native/Overlay及已有/新开host。无该能力的Control不虚造状态。
- 静态画面先稳定布局和资源；动态画面使用相同时间原点与采样时刻，比较运动过程和终态。不能通过关动画、隐藏内容/滚动条、移除高度/裁剪条件或重建页面避开差异。
- 静态配置与输入停止后，控件必须保持稳定。采样窗口须覆盖实际Transition时长和本次可疑周期，持续检查真实渲染帧、布局及相关有效属性，不能只取三张相等帧就排除后续闪烁。Loading等有意循环动效按其明确合同验收，不要求画面静止，也不能关闭动效避开问题。

### 脚本化执行

- 视觉验证使用可重复运行的脚本或测试宿主：自动创建真实控件、加载配置/数据、驱动状态、等待布局及渲染稳定，捕获实际渲染帧并输出像素、几何和断言结果。不使用Computer Use、桌面识图或坐标点击操作推进验收。
- 优先复用已有Skia合成器渲染测试；不能使用无真实绘制的HeadlessDrawing结果证明像素一致。原生窗口、Native/Overlay、字体及平台专项使用相应后端的自驱动宿主，脚本自动完成场景与采样；Headless/Skia通过不能代替原生后端通过。
- 静态采样采用有界稳定条件，不能以任意长sleep掩盖更新错误；先验证同版本A/A零差异，再以仅改变1 DIP间距的临时场景证明比较流程能检错，恢复后应重新零差异。该正对照不修改产品基线。
- 状态准备可用公开API；输入路由、命中、焦点、滚轮等交互验收须使用对应宿主的可脚本化输入事件，并断言事件到达及实际结果，不能将直接设值当成真实交互证据。缺少相应后端驱动时保留未验证边界，不回退到桌面手工操作并宣称脚本通过。
- 实际查看脚本生成的关键画面和差异图属于证据审查；不以人工操作应用代替可重放的场景步骤。只保留文本结果，媒体及临时验证代码按下述清理规则处理。
- 高频反复切换字号、颜色或主题的性能采样默认使用离屏宿主，避免在用户桌面制造闪动。确需原生呈现的专项应独立安排和记录。性能驱动的主动变化与产品无输入时的闪烁分别判定；保留配置/状态操作顺序，停止驱动后用同一实例观察，不能把连续切换场景的截图或性能通过当作画面稳定证据。

### 判定与差异处置

- 同时核对实际尺寸/位置/间距、文字度量和换行、颜色/透明度、描边/圆角、阴影、图标/箭头、自绘几何、裁剪/滚动条、焦点及状态效果；动效还核对时长、easing和运动轨迹。
- 使用同坐标、同尺寸的前后截图/叠加/差异图，并核对布局与实际属性来源；不得缩放、移动对齐或遮住控件区域以消除差异。必须查看实际证据，Token值、测试成功或截图文件存在均不能代替视觉判断。
- 可重复静态画面以零差异为目标，不设置允许若干百分比像素变化的通用豁免。采样不稳定时先固定条件并用同版本A/A对照定位；仍需容差的环境噪声必须事先限定来源、区域及数值并审查，不能用字体/平台容差掩盖布局、颜色、描边或自绘变化。
- 任何未解释或未经批准的视觉差异都阻断该Control及受影响任务的验收。禁止直接覆盖基线、修改期望截图或用“修复Bug/接入Token”自动豁免；原基线与新结果的差异须先定位根因。
- 新主题/新参数有意改变外观，单独验证其目标渲染；若修复以前未生效的配置会改变已有输入的表现，先列明具体配置、区域、前后差异及兼容影响并取得明确审查结论，不能混入无视觉差异的重构。

### 证据与交付

每批同时提交“原外观无回归”和“目标定制生效”两类文本结论，记录覆盖矩阵、基线来源、实际观察、差异及审查结果、未验证Host。没有前证或覆盖缺口时报告证据不足，不报告视觉一致性通过。

截图、录屏、叠加/差异图和派生取证二进制只在仓库外系统临时目录生成、查看及比较，不进入项目、commit、报告附件或编码文本。记录不依赖媒体的实际数值和观察后清理；临时验证代码按既有测试生命周期处理。不为这项门槛建立永久全控件截图库或自动扩大全量测试范围。

## 逐Control主题合同摘要

复用现有overview/implementation/token/semantic-part文档，不另外建立永久消费白名单、逐测试登记库或运行时追踪数据库。仅记录该Control有意义的内容：

| 必须回答 | 落点 |
| --- | --- |
| Control identity、组合owner、内部对象及公开子Control的职责 | overview/implementation |
| 支持哪些主题维度、状态、尺寸、形态与平台边界 | overview |
| 每个Active Own的语义、默认依赖、消费者、适用分支与更新责任 | token |
| 真实视觉投射、自绘输入与缓存失效、优先级和生命周期 | implementation |
| 公开Part、生成Style、route、ContractType及支持的Setter效果 | semantic-part |
| 默认、Global/Own/Part定制及动态切换的实际用法 | Gallery与指南 |
| 有效验证与未覆盖项、兼容变化、测试去留 | 交付说明/changelog，按各自职责 |

没有Own的Control省略Own表；没有公开Part不造空Part文档。Global只记录必要语义示例，不复制完整支持清单。

## 执行门禁

| 层级 | 阻止什么 | 实施约束 |
| --- | --- | --- |
| 构建/生成期 | 类型/identity冲突、非法声明、明确Own依赖错误、Part/资产合同错误 | 复用现有Generator/Compiler；只将可以确定证明的违规设为构建错误 |
| 静态审查 | Shared误用、动态值静态化、代码写视觉值、可疑Custom selector等 | 正则/引用扫描只产出候选，结合owner和运行语义处置；禁止所有数字/颜色一律报错 |
| 模块运行验收 | 消费断链、错误优先级、派生错误、Part失配、缓存失效 | 精确filter/iterate指定模块；每个Active Own及适用分支、每条依赖边、每条独立route有证据 |
| 视觉一致性验收 | 相同输入下尺寸、排版、颜色、几何、状态或动效漂移 | 逐Control改动前基线与改动后比较；未解释/未经批准差异为零，不能以主题能力验证替代 |
| 专项验收 | 生命周期、跨根、平台渲染、故障恢复、性能及AOT | 按影响选择真实场景，不要求每次普通变更跑全部平台/全量回归 |
| 交付评审 | 合同不清、兼容性遗漏、证据不足、文档与示例漂移 | 未完成相关门槛不能报告该控件或机制已通过 |

Global按控件实际消费语义选有检错能力的代表；Active Own不能只抽几个代表。有关联的状态用最小充分组合覆盖，不机械生成所有维度笛卡尔积。

所有控件都做A→B→A时，应验证已有实例及相关状态，不能以重建页面清除残留。UI必须保留原始尺寸、内容、滚动和裁剪条件；必要的环境噪声处理遵守上述视觉一致性门槛，不能泛化为视觉差异豁免。

本规范不改写[测试价值与生命周期](../test-value-and-lifecycle.md)和[按影响验证](../../workflows/affected-verification.md)：临时验证实际执行并清理，长期测试证明独立价值，本地最终只验证实际改动模块，不自行运行change/full。
