# AtomUI 6.2.9 迁移指南

[English](6.2.9-api-changes.md)

6.2.9 恢复 Splash 卡片阴影，并将普惠体字体包纳入正式 NuGet 发布。
Avalonia 仍为 12.1.4，Release 产品包继续提供 net8.0 和 net10.0。

## 快速对照

| 范围 | 6.2.8 | 6.2.9 / 迁移方式 |
| --- | --- | --- |
| 生成式注册组 | 公开 `ControlPackageGroup_*` 名称包含 6.2.8 程序集标识 | 名称包含 6.2.9；同步升级相关包并重建预编译消费方 |
| 普惠体包 | 存在源码项目，但未进入发布清单 | 正式发布 `AtomUI.Fonts.AlibabaPuHuiTi`；显式引用并注册字体 |
| Splash | 卡片阴影可能被裁剪，并与动画内容共用绘制开销 | 保留完整阴影并独立缓存；继续支持 Card 外观定制 |
| 既有包契约 | net8.0/net10.0 产品程序集及既有构建资产 | 保留既有目标框架、包 ID 与构建资产路径 |

## 重建生成式注册消费方

生成器将包含版本的包程序集标识散列到公开的 `AtomUI.Generated.*.ControlPackageGroup_*` 名称中。
6.2.9 升版会改变这些生成式名称，即使受支持的注册方法签名没有变化。
仅替换运行时 DLL，不会更新已编译消费方对这些注册组的引用。

1. 同步将相关 AtomUI 包及显式引用的 Generator 升级到 6.2.9。
2. 清理并重建消费生成式注册元数据的应用与自定义控件包。
3. 重新发布裁剪与 NativeAOT 应用，使依赖分析使用新的注册组。

继续使用受支持的 `UseAtomUI` 和包配置入口，不要直接引用生成式组名，也不要混用 6.2.8 预编译注册元数据与
6.2.9 包集合。这是有意的二进制不兼容；历史包 API 比较必须报告该差异，不得用抑制隐藏或声称二进制兼容。

## 使用普惠体包

包内包含现有阿里巴巴普惠体 3.0 Regular 字体。引用 `AtomUI.Fonts.AlibabaPuHuiTi` 6.2.9 后，在 AtomUI Builder
中调用 `UseAlibabaPuHuiTiFont()`，或在 AppBuilder 配置阶段调用 `WithAlibabaPuHuiTiFont()`。
注册本身不会修改默认字体族；需要时用 `AlibabaPuHuiTiFontConstants.FontFamily` 配置目标字族。

本次不包含字体子集化、额外字重、字体集合 URI 或内部字族名变更。既有包继续执行目标框架和构建资产校验。
仅此显式标记的未发布包，在 NuGet 确认公共包索引不存在后，才省略历史基线。包索引存在后恢复普通基线校验，
缺少指定历史版本或网络错误不会被当作首次发布。

## Splash 外观定制

既有针对模板 `Border#Card` 的样式继续控制背景、圆角和阴影。默认主题在卡片后方独立缓存阴影，并保留卡片内容裁剪。
不透明回退仍保持方角且不显示阴影。本次没有移除 Splash 公开方法、属性或 Token。

## 包验证结果

与 6.2.8 包比较，仅报告 10 条 `CP0001`：`AtomUI.Controls`、`AtomUI.Desktop.Controls`、
`AtomUI.Toolkits.GalleryBase`、`AtomUI.Desktop.Controls.DataGrid` 和 `AtomUI.Desktop.Controls.ColorPicker`
在 net8.0、net10.0 上的生成式注册组标识变化。没有额外 API 不兼容或引用无法解析的诊断。
历史 API 比较因这些已记录的二进制不兼容而失败；本次不增加抑制，也不声称与 6.2.8 二进制兼容。

20 个既有包的布局均与 6.2.8 一致。普惠体没有历史包，按显式首次发布规则处理；无需修改布局许可清单。
正式发布 workflow 可不指定历史 API 基线来发布这项已记录的二进制变更；上述独立历史比较仍属于发布证据，
包身份、目标框架和构建资产的绝对契约校验照常执行。
