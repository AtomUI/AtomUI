# AtomUI 6.2.14 migration guide

[简体中文](6.2.14-api-changes.zh-CN.md)

This guide covers upgrading from 6.2.13. This release moves the platform-neutral parts of Skeleton, Space, Empty,
Result and related controls into the shared `AtomUI.Controls` assembly, which brings three intentional API incompatible
changes; in addition, the Empty `description` style part now follows Ant Design and changes one theme customization
contract. Applications that use these controls only from AXAML usually need no changes; a few C# patterns need
updating, and assemblies compiled against 6.2.13 must be rebuilt. See the [Changelog](../../CHANGELOG.md) for release
highlights.

## Quick reference

| Area | 6.2.13 | 6.2.14 / migration |
| --- | --- | --- |
| `AbstractSkeleton` | `AtomUI.Desktop.Controls`, Desktop assembly | `AtomUI.Controls`, shared assembly; add `using AtomUI.Controls`, mark shimmer blocks in custom templates |
| `SpaceItemsAlignment` | `AtomUI.Desktop.Controls` | `AtomUI.Controls`; add `using AtomUI.Controls` |
| `Empty.Description` | `string?` | `object?`; convert where the value is read |
| `Result.Icon` | `PathIcon?` | `object?`; convert where the value is read |
| Empty `description` Semantic Part | `TextBlock`, string descriptions only | `ContentPresenter`, text and custom content; set `x:SetterTargetType` to `ContentPresenter` |
| Generated registration groups | Names encode the 6.2.13 assembly identity | Names encode 6.2.14; upgrade the package set and rebuild generated consumers |

## Skeleton base class moves to the shared layer

`AbstractSkeleton` moves from `AtomUI.Desktop.Controls` (`AtomUI.Desktop.Controls.dll`) to `AtomUI.Controls`
(`AtomUI.Controls.dll`). The Desktop classes `Skeleton`, `SkeletonLine`, `SkeletonTitle`, `SkeletonParagraph` and the
rest keep their names and public members and now derive from the new shared bases.

**C# references**: code that only imports `AtomUI.Desktop.Controls` must add the new namespace:

```csharp
using AtomUI.Controls;          // AbstractSkeleton
using AtomUI.Desktop.Controls;  // Skeleton, SkeletonLine ...

public class MySkeleton : AbstractSkeleton { }
```

The `https://atomui.net` mapping in AXAML resolves the type as before. Because the namespace changed, type forwarding
cannot keep old binaries working; assemblies that derive from or reference `AbstractSkeleton` must be rebuilt.

**Custom templates**: old templates got their animation from the `PART_ActiveAnimationLayer` template part, which is
removed. The outermost skeleton of a group now paints one shimmer for all of its blocks; a template only marks each
`Border` that should shimmer with `IsShimmerBlock`:

```xml
<Border Name="PART_ContentLayer"
        atom:AbstractSkeleton.IsShimmerBlock="True"
        CornerRadius="{TemplateBinding CornerRadius}" />
```

An old template without the marker shows its background color without a shimmer.

**Animation entry points**: the protected `StartActiveAnimation()` / `StopActiveAnimation()` keep their signatures and
now ask the shimmer host to re-evaluate whether the shimmer runs. Derived classes can no longer force it on or off:
the shimmer runs only while the skeleton is visible, the application is active, `IsMotionEnabled` and `IsActive` are
true and `MotionDuration` is greater than zero (a composite skeleton also needs `IsLoading`). The new
`IsMotionEnabled` is bound to the global `EnableMotion` switch by default.

**Easing**: `MotionEasingCurve` is evaluated on the render thread. A custom `Easing` must be a pure function: `Ease`
writes no state and touches no UI-thread objects, and the instance is not modified after assignment. Avalonia's
built-in easings are unaffected.

**Default value**: for a standalone `SkeletonParagraph`, the default `LastLineWidth` changes from 1% to 100%; the
last line was almost invisible before. Set the property explicitly if a layout depended on the old default.

## `SpaceItemsAlignment` changes namespace

The enum moves from `AtomUI.Desktop.Controls` to `AtomUI.Controls`; its members and values are unchanged, and the
type of `Space.ItemsAlignment` changes with it. `Space` now derives from the shared base `AbstractSpace`; members such
as `ItemSpacing`, `Orientation` and `ItemsAlignment` move to the base and are still accessed through `Space`.

```csharp
using AtomUI.Controls;          // SpaceItemsAlignment
using AtomUI.Desktop.Controls;  // Space

space.ItemsAlignment = SpaceItemsAlignment.Center;
```

AXAML is unchanged. Compiled assemblies that reference the old enum type must be rebuilt.

## `Empty.Description` and `Result.Icon` become `object?`

To accept custom content, both properties and their `StyledProperty` fields widen to `object?`:

| Member | 6.2.13 | 6.2.14 |
| --- | --- | --- |
| `Empty.Description` / `DescriptionProperty` | `string?` | `object?` |
| `Result.Icon` / `IconProperty` | `PathIcon?` | `object?` |

Code that assigns a string or a `PathIcon` still compiles and renders the same. Code that uses the value it reads as
the old type needs a conversion:

```csharp
// 6.2.13
string? text = empty.Description;
PathIcon? icon = result.Icon;

// 6.2.14
var text = empty.Description as string;
var icon = result.Icon as PathIcon;
```

Compiled assemblies that reference the old signatures must be rebuilt. String and non-string descriptions are shown
by the same `description` node; see the next section for its style.

## Empty `description` Semantic Part becomes a content presenter

To follow Ant Design's `styles.description`, which styles the outer description node whether it holds text or custom
content, the `description` part changes from the description `TextBlock` to a `ContentPresenter` that holds both, and
its `ContractType` becomes `ContentPresenter`. `EmptyDescriptionStyle` now applies to custom content too; object
descriptions previously had no style entry.

```xml
<Style Selector="atom|Empty">
    <!-- 6.2.13: x:SetterTargetType="atom:TextBlock" -->
    <atom:EmptyDescriptionStyle x:SetterTargetType="ContentPresenter">
        <Setter Property="Foreground" Value="DarkSlateBlue" />
        <Setter Property="FontWeight" Value="Bold" />
    </atom:EmptyDescriptionStyle>
</Style>
```

- **No change needed**: the presenter shares the `TextBlock` / `TextElement` text properties, so `Foreground`, font
  settings, `TextAlignment`, `TextWrapping`, `TextTrimming`, `LineHeight`, `LetterSpacing`, `MaxLines` and `Margin`
  written the old way keep working and inherit to the description text.
- **Change needed**:
  - `TextBlock`-only properties that do not inherit (for example `TextDecorations`) no longer take effect on the part,
    and do not raise errors. Use custom content instead, such as a decorated `TextBlock` passed as `Description`.
  - Selectors on `TextBlock#Description` and code that looks the part up as a `TextBlock` were never public contract;
    use `EmptyDescriptionStyle`.

A `null` description renders as empty text, with the same layout as before.

## Generated registration identities

Generated `AtomUI.Generated.*.ControlPackageGroup_*` type names include the assembly identity and change with
6.2.14. Upgrade related AtomUI packages and any explicit Generator reference together, clean and rebuild custom
control packages and applications, then republish trimmed/NativeAOT applications. Do not reference generated group
names directly or mix compiled 6.2.13 registration metadata with 6.2.14 packages. This follows the
[6.2.13 migration guide](6.2.13-api-changes.md).

## Compatible changes

These changes need no migration but are visible in behavior or appearance:

- **Keyboard focus outline follows Ant Design**:
  - the global focus frame becomes a 3px light-primary outline, offset 1px outward and following the corner radius;
  - the shared `LineWidthFocus` token changes from `LineWidth * 2` to `LineWidth * 3`. Custom visuals that use it
    and must stay at 2px should use `LineWidthBold`;
  - applications that set `AdornerLayer.DefaultFocusAdorner` or a control's `FocusAdorner` themselves are
    unaffected.
- **Keyboard stops**:
  - Collapse and Expander keep a single stop chosen by `TriggerType`;
  - the ComboBox clear button is reachable from the keyboard, while its frame and drop-down arrow are no longer
    stops;
  - NumericUpDown can now be entered with Tab (it was skipped entirely before).
  - Automation scripts that rely on the old Tab order need updating.
- **New members**:
  - `CommonLangResourceKind.Clear`, appended at the end so existing member values are unchanged. Exhaustive
    `switch` statements over the enum may need a branch, and third-party language packs should translate it (it
    falls back to English "Clear").
  - `Space.IsWrap` and `Space.Justify`;
  - `Empty.Image` and `Empty.Title` with their template properties;
  - `AbstractSkeleton.IsMotionEnabled`.
