# AtomUI 6.2.14 migration guide

[简体中文](6.2.14-api-changes.zh-CN.md)

This guide covers upgrading from 6.2.13. This release requires Avalonia 12.1.6 and moves the platform-neutral parts of Skeleton, Space, Empty,
Result and related controls into the shared `AtomUI.Controls` assembly. It also changes the Empty description style
target, keyboard interaction, focus tokens, and default text watermark color. Update the usages described below and
rebuild affected assemblies. See the [Changelog](../../CHANGELOG.md) for release highlights.

## Quick reference

| Area | 6.2.13 | 6.2.14 / migration |
| --- | --- | --- |
| Avalonia dependency | 12.1.5 | 12.1.6 minimum; update pinned Avalonia packages before upgrading AtomUI |
| `AbstractSkeleton` | `AtomUI.Desktop.Controls`, Desktop assembly | `AtomUI.Controls`, shared assembly; add `using AtomUI.Controls`, mark shimmer blocks in custom templates |
| `SpaceItemsAlignment` | `AtomUI.Desktop.Controls` | `AtomUI.Controls`; add `using AtomUI.Controls` |
| `Card` property fields | Declared on `Card` | Declared on the shared base `AbstractCard`; rebuild compiled consumers |
| `Empty.Description` | `string?` | `object?`; convert where the value is read |
| `Result.Icon` | `PathIcon?` | `object?`; convert where the value is read |
| Empty `description` Semantic Part | `TextBlock`, string descriptions only | `ContentPresenter`, text and custom content; set `x:SetterTargetType` to `ContentPresenter` |
| Focus outline and Tab order | 2× line width, `FocusVisualMargin`; previous Tab stops | 3× line width, `FocusOutlineOffset`; update token overrides and keyboard scripts |
| Picker confirmation | Picker frame receives Tab; previous Escape and range behavior | Focus the input; update keyboard scripts for the new Enter, Escape and endpoint rules |
| Watermark and theme motion | Black text watermark; theme-triggered transitions use their durations | Set the watermark foreground explicitly for black; use an application-owned animation for an extended theme transition |
| Generated registration groups | Names encode the 6.2.13 assembly identity | Names encode 6.2.14; upgrade the package set and rebuild generated consumers |
| Package target frameworks | `lib/net8.0`, `lib/net10.0` | Adds `lib/net11.0`; existing frameworks unchanged, no action needed |

## Avalonia dependency advances to 12.1.6

AtomUI packages now depend on Avalonia 12.1.6 (`Avalonia`, `Avalonia.Desktop` and the platform packages). The package
manifest declares 12.1.6 as the minimum, so a solution pinned to 12.1.5 must move to 12.1.6 before it can consume
AtomUI 6.2.14:

```xml
<PackageVersion Include="Avalonia" Version="12.1.6" />
<PackageVersion Include="Avalonia.Desktop" Version="12.1.6" />
```

Update every explicitly referenced Avalonia package to the same version. Avalonia 12.1.6 is a fix release with no
removed public API. One upstream behavior change is visible to applications: `Window.IsActive` is already `true`
when `Activated` handlers run; it used to change after the event. AtomUI needs no code change for 12.1.6.

## Skeleton base class moves to the shared layer

`AbstractSkeleton` moves from `AtomUI.Desktop.Controls` (`AtomUI.Desktop.Controls.dll`) to `AtomUI.Controls`
(`AtomUI.Controls.dll`). The Desktop classes `Skeleton`, `SkeletonLine`, `SkeletonTitle`, `SkeletonParagraph` and the
rest keep their names and public members and now derive from the new shared bases.

**C# references**: code that only imports `AtomUI.Desktop.Controls` must add the new namespace:

```csharp
using AtomUI.Controls;          // AbstractSkeleton
using AtomUI.Desktop.Controls;  // Skeleton, SkeletonLine ...

public class MySkeleton : AbstractSkeleton { }
```

The `https://atomui.net` mapping in AXAML resolves the type as before. Because the namespace changed, type forwarding
cannot keep old binaries working; assemblies that derive from or reference `AbstractSkeleton` must be rebuilt.

**Custom templates**: old templates got their animation from the `PART_ActiveAnimationLayer` template part, which is
removed. The outermost skeleton of a group now paints one shimmer for all of its blocks; a template only marks each
`Border` that should shimmer with `IsShimmerBlock`:

```xml
<Border Name="PART_ContentLayer"
        atom:AbstractSkeleton.IsShimmerBlock="True"
        CornerRadius="{TemplateBinding CornerRadius}" />
```

An old template without the marker shows its background color without a shimmer.

**Animation entry points**: the protected `StartActiveAnimation()` / `StopActiveAnimation()` keep their signatures and
now ask the shimmer host to re-evaluate whether the shimmer runs. Derived classes can no longer force it on or off:
the shimmer runs only while the skeleton is visible, the application is active, `IsMotionEnabled` and `IsActive` are
true and `MotionDuration` is greater than zero (a composite skeleton also needs `IsLoading`). The new
`IsMotionEnabled` is bound to the global `EnableMotion` switch by default.

**Easing**: `MotionEasingCurve` is evaluated on the render thread. A custom `Easing` must be a pure function: `Ease`
writes no state and touches no UI-thread objects, and the instance is not modified after assignment. Avalonia's
built-in easings are unaffected.

**Default value**: for a standalone `SkeletonParagraph`, the default `LastLineWidth` changes from 1% to 100%; the
last line was almost invisible before. Set the property explicitly if a layout depended on the old default.

## `SpaceItemsAlignment` changes namespace

The enum moves from `AtomUI.Desktop.Controls` to `AtomUI.Controls`; its members and values are unchanged, and the
type of `Space.ItemsAlignment` changes with it. `Space` now derives from the shared base `AbstractSpace`; members such
as `ItemSpacing`, `Orientation` and `ItemsAlignment` move to the base and are still accessed through `Space`.

```csharp
using AtomUI.Controls;          // SpaceItemsAlignment
using AtomUI.Desktop.Controls;  // Space

space.ItemsAlignment = SpaceItemsAlignment.Center;
```

AXAML is unchanged. Compiled assemblies that reference the old enum type must be rebuilt.

## Card property fields move to `AbstractCard`

`Card` now derives from the shared base `AtomUI.Controls.AbstractCard`, which derives from
`HeaderedContentControl` as `Card` did before. `Extra`, `ExtraTemplate`, `Cover`, `CoverTemplate` and `IsLoading`,
together with their `StyledProperty` fields, are declared on the base. Source written as `Card.CoverProperty` or
`card.IsLoading` still compiles, and AXAML is unchanged. Assemblies compiled against 6.2.13 that reference these
fields through `Card` must be rebuilt.

## `Empty.Description` and `Result.Icon` become `object?`

To accept custom content, both properties and their `StyledProperty` fields widen to `object?`:

| Member | 6.2.13 | 6.2.14 |
| --- | --- | --- |
| `Empty.Description` / `DescriptionProperty` | `string?` | `object?` |
| `Result.Icon` / `IconProperty` | `PathIcon?` | `object?` |

Code that assigns a string or a `PathIcon` still compiles and renders the same. Code that uses the value it reads as
the old type needs a conversion:

```csharp
// 6.2.13
string? text = empty.Description;
PathIcon? icon = result.Icon;

// 6.2.14
var text = empty.Description as string;
var icon = result.Icon as PathIcon;
```

Compiled assemblies that reference the old signatures must be rebuilt. String and non-string descriptions are shown
by the same `description` node; see the next section for its style.

## Empty `description` Semantic Part becomes a content presenter

To follow Ant Design's `styles.description`, which styles the outer description node whether it holds text or custom
content, the `description` part changes from the description `TextBlock` to a `ContentPresenter` that holds both, and
its `ContractType` becomes `ContentPresenter`. `EmptyDescriptionStyle` now applies to custom content too; object
descriptions previously had no style entry.

```xml
<Style Selector="atom|Empty">
    <!-- 6.2.13: x:SetterTargetType="atom:TextBlock" -->
    <atom:EmptyDescriptionStyle x:SetterTargetType="ContentPresenter">
        <Setter Property="Foreground" Value="DarkSlateBlue" />
        <Setter Property="FontWeight" Value="Bold" />
    </atom:EmptyDescriptionStyle>
</Style>
```

- **No change needed**: the presenter shares the `TextBlock` / `TextElement` text properties, so `Foreground`, font
  settings, `TextAlignment`, `TextWrapping`, `TextTrimming`, `LineHeight`, `LetterSpacing`, `MaxLines` and `Margin`
  written the old way keep working and inherit to the description text.
- **Change needed**:
  - `TextBlock`-only properties that do not inherit (for example `TextDecorations`) no longer take effect on the part,
    and do not raise errors. Use custom content instead, such as a decorated `TextBlock` passed as `Description`.
  - Selectors on `TextBlock#Description` and code that looks the part up as a `TextBlock` were never public contract;
    use `EmptyDescriptionStyle`.

A `null` description renders as empty text, with the same layout as before.

## Generated registration identities

Generated `AtomUI.Generated.*.ControlPackageGroup_*` type names include the assembly identity and change with
6.2.14. Upgrade related AtomUI packages and any explicit Generator reference together, clean and rebuild custom
control packages and applications, then republish trimmed/NativeAOT applications. Do not reference generated group
names directly or mix compiled 6.2.13 registration metadata with 6.2.14 packages. This follows the
[6.2.13 migration guide](6.2.13-api-changes.md).

## Target frameworks and SDK

This change is additive and needs no migration.

- Release packages add `lib/net11.0` next to `lib/net8.0` and `lib/net10.0`. Applications targeting .NET 11 now
  resolve the net11.0 assets; net8.0 and net10.0 applications get the same assets as before.
- Consumers keep the existing SDK requirement. Building AtomUI from source requires .NET SDK 10.0.300 or later, and
  `global.json` now rolls forward to the latest installed major SDK. Packing the three Release frameworks requires
  SDK 11.
- The net8 trimming and NativeAOT backends, and the net8 package compatibility bridge, accept the official engines
  selected by the installed SDK instead of fixed SDK versions. Packages built before 6.2.14 whose registration
  holders have a static constructor still work with these backends.

The package layout gate acknowledges the new `lib/net11.0/*` entries in
`scripts/verification/package-layout-allowlist.json` (#538).

## Keyboard focus and picker interaction

- **Keyboard focus outline follows Ant Design**:
  - the global focus frame becomes a 3px light-primary outline, offset 1px outward and following the corner radius;
  - the shared `LineWidthFocus` token changes from `LineWidth * 2` to `LineWidth * 3`. Custom visuals that use it
    and must stay at 2px should use `LineWidthBold`;
  - replace an AdornerLayer `FocusVisualMargin` token override with `FocusOutlineOffset`, the uniform distance
    from the control to the outline in DIPs. Set it to 0 to remove the gap;
  - applications that set `AdornerLayer.DefaultFocusAdorner` or a control's `FocusAdorner` themselves are
    unaffected.
- **Keyboard stops**:
  - Collapse and Expander keep a single stop chosen by `TriggerType`;
  - the ComboBox clear button is reachable from the keyboard, while its frame and drop-down arrow are no longer
    stops;
  - NumericUpDown can now be entered with Tab (it was skipped entirely before).
  - TreeView receives Tab and uses one active node for keyboard navigation. Set `IsTabStop="False"` to retain the
    previous Tab order, or `Focusable="False"` to also disable direct focus.
  - Date and time pickers stop at the input (the start and end inputs of a range), then the clear button; the
    frame was the only stop before.
  - Automation scripts that rely on the old Tab order need updating.
- **Date and time picker keyboard follows Ant Design**:
  - focusing the input does not open the popup and typing does; DatePicker / RangeDatePicker now parse text that
    matches the display format;
  - Enter submits without the confirm button, Escape reverts (a TimePicker with `IsNeedConfirm=false` no longer
    commits on Escape), and focus leaving the picker commits or discards by the confirmation rule;
  - range pickers hand over to the other endpoint until both are confirmed in the open session; a RangeTimePicker
    with a complete range now moves to the end after the start is confirmed instead of closing;
  - while the popup is open, navigation keys in the input move the date panel's focused cell or step the time
    columns (an AtomUI addition).

## Watermark and theme motion

- Text watermarks use the owner's `ColorText` token by default. Set `Foreground="Black"` on the text glyph or
  provide an explicit brush to preserve a fixed color.
- Global-clock animations started during a theme commit or its first frame settle within that frame. Applications
  that need a prolonged theme-switch effect can start their own animation after that frame has been rendered.
  Animations already running when the theme commit begins keep their timing.

## Other changes

- **Date and time picker pointer interaction follows Ant Design** (Gitee IKUUCL):
  - clicking a time cell of a show-time DatePicker updates the candidate at once, and the confirm button commits
    the time the panel shows; a single picker used to commit the clock joined at the earlier date click;
  - when the pointer leaves the time cells the input returns to the candidate instead of showing `date 00:00:00`;
  - while the popup is open the candidate keeps the normal text color and only the hover preview uses
    `ColorTextTertiary`; the earlier whole-input dimming never took effect.
- **New members**:
  - `CommonLangResourceKind.Clear`, appended at the end so existing member values are unchanged. Exhaustive
    `switch` statements over the enum may need a branch, and third-party language packs should translate it (it
    falls back to English "Clear").
  - `Space.IsWrap` and `Space.Justify`;
  - `Empty.Image` and `Empty.Title` with their template properties;
  - `AbstractSkeleton.IsMotionEnabled`;
  - the picker input pseudo-class `:previewing` (`InfoPickerPseudoClass.Previewing`), set while the input shows a
    hover preview, so custom themes can color the preview text.

## Package validation

All 21 release packages were compared with the published 6.2.13 packages across net8.0 and net10.0. The historical
API comparison reports 105 diagnostics in five packages, all covered by the sections above:

- Controls (10): `Empty.Description` and `Result.Icon` signatures, plus the versioned registration group.
- Desktop.Controls (89): `AbstractSkeleton` and `SpaceItemsAlignment` leaving the assembly, Skeleton, Space and Card
  property fields moving to the shared bases, Skeleton types changing base class, `Space.HandleChildrenChanged`
  becoming an override of the base method, the removed `FocusVisualMargin` token key, plus the registration group.
- GalleryBase, DataGrid and ColorPicker (2 each): the versioned registration group.

The other 16 packages pass, with no unresolved-reference diagnostics. No suppression is added, and this release does
not claim binary compatibility with 6.2.13. Following the 6.2.13 publication strategy, the normal release pack uses no
historical API baseline and succeeds for all 21 packages, with net8.0, net10.0 and net11.0 target-framework
validation. All 21 package layouts match 6.2.13 once the acknowledged `lib/net11.0/*` entries are applied; the
package manifests declare Avalonia 12.1.6. Runtime
behavior changes remain part of the manual migration audit, since an assembly API comparison cannot detect them.
