# 主题验收与兼容性规范

> 本文定义验收要求。检查结果必须来自实际执行，不能以设计文档更新代替产品验证。

本文的适用范围、规范用语与事实边界见[全局规范入口](overview.md)。

本文拥有主题研发的兼容、例外和交付证据要求，消费路径见[控件消费规范](consumption.md)。测试去留与执行范围继续由已有全局工程规范拥有。

跨模块设计的现行实现与目标差异统一见[主题实现与验证边界](../../../architecture/systems/theming/verification.md)；该文档维护机制状态，本文维护验收方法和证据要求。

### TH-12：兼容性、例外与验收证据

性质：现行兼容/验证约束＋新增统一主题门禁。

- Token名称/类型/单位/阶段、资源key、identity、Part契约、样式优先级、默认和状态行为、计算及配置协议均属于需审查的合同。
- 变更明确选择兼容修复、版本化演进或弃用迁移；不能用“清理写死值”隐藏公开行为变化。
- 新建或触及的相关路径不得新增违规；涉及的既有断链必须修复，或在超出授权/兼容范围时报告阻塞及具体后续决策，不能当作已经完成。
- 合法常量/平台边界/Reserved是分类，不是豁免。真正例外必须在对应正式文档或交付评审中说明规则、技术原因、范围、等价保障与复核条件；不得由作者或agent自行永久豁免，不建立宽泛忽略列表。
- 文档、schema、模板、自绘及Gallery示例表达同一合同；按当前测试生命周期保留最小充分长期保障，临时验证执行后清理。

检查：兼容影响审查、例外理由、逐项证据、临时产物清理与最终受影响模块验证。

## 逐Control主题合同摘要

复用现有overview/implementation/token/semantic-part文档，不另外建立永久消费白名单、逐测试登记库或运行时追踪数据库。仅记录该Control有意义的内容：

| 必须回答 | 落点 |
| --- | --- |
| Control identity、组合owner、内部对象及公开子Control的职责 | overview/implementation |
| 支持哪些主题维度、状态、尺寸、形态与平台边界 | overview |
| 每个Active Own的语义、默认依赖、消费者、适用分支与更新责任 | token |
| 真实视觉投射、自绘输入与缓存失效、优先级和生命周期 | implementation |
| 公开Part、生成Style、route、ContractType及支持的Setter效果 | semantic-part |
| 默认、Global/Own/Part定制及动态切换的实际用法 | Gallery与指南 |
| 有效验证与未覆盖项、兼容变化、测试去留 | 交付说明/changelog，按各自职责 |

没有Own的Control省略Own表；没有公开Part不造空Part文档。Global只记录必要语义示例，不复制完整支持清单。

## 执行门禁

| 层级 | 阻止什么 | 实施约束 |
| --- | --- | --- |
| 构建/生成期 | 类型/identity冲突、非法声明、明确Own依赖错误、Part/资产合同错误 | 复用现有Generator/Compiler；只将可以确定证明的违规设为构建错误 |
| 静态审查 | Shared误用、动态值静态化、代码写视觉值、可疑Custom selector等 | 正则/引用扫描只产出候选，结合owner和运行语义处置；禁止所有数字/颜色一律报错 |
| 模块运行验收 | 消费断链、错误优先级、派生错误、Part失配、缓存失效 | 精确filter/iterate指定模块；每个Active Own及适用分支、每条依赖边、每条独立route有证据 |
| 专项验收 | 生命周期、跨根、平台渲染、故障恢复、性能及AOT | 按影响选择真实场景，不要求每次普通变更跑全部平台/全量回归 |
| 交付评审 | 合同不清、兼容性遗漏、证据不足、文档与示例漂移 | 未完成相关门槛不能报告该控件或机制已通过 |

Global按控件实际消费语义选有检错能力的代表；Active Own不能只抽几个代表。有关联的状态用最小充分组合覆盖，不机械生成所有维度笛卡尔积。

所有控件都做A→B→A时，应验证已有实例及相关状态，不能以重建页面清除残留。UI必须保留原始尺寸、内容、滚动和裁剪条件；必要的像素证据使用预先说明的字体/平台容差。

本规范不改写[测试价值与生命周期](../test-value-and-lifecycle.md)和[按影响验证](../../workflows/affected-verification.md)：临时验证实际执行并清理，长期测试证明独立价值，本地最终只验证实际改动模块，不自行运行change/full。
