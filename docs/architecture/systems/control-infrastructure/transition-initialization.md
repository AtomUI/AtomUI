# 状态动效初始化架构设计

本文定义状态动效初始化的共享架构。共享能力归属 `AtomUI.Core/Animations`，控件拥有业务状态和初始几何，
ControlTheme 拥有状态外观与过渡声明。现有及新增控件复用同一初始化协议。

目录入口见 [Control 基础设施](overview.md)，模块入口见 [AtomUI.Core](../../../modules/core/overview.md)。
设计契约与源码实现分开维护：类型接入、当前差异和已执行的验证统一见
[状态动效初始化验证](transition-initialization-verification.md)，不能仅凭本文判断源码已经完成接入。

## 1. 设计定位与不变量

状态动效表达两个有效状态之间的变化。首次建立状态时直接提交正确的位置、尺寸和外观，不创建从默认状态到
初始状态的过渡运行实例。初始状态完整后开放后续过渡，开放动作本身不补播初始化动画。

初始化优化同时包含视觉和性能契约：

- 初次显示没有选中块飞入、零尺寸增长或默认缩放恢复等状态过渡。
- 初始化属性变化不启动对应的过渡运行实例，减少插值、逐帧失效和不必要的布局工作。
- 正常绑定、主题、测量、排列和渲染继续执行，控件直接显示有效状态，不延迟或隐藏整棵控件树。
- 共享机制的分配、属性覆盖和生命周期管理成本计入性能验收，不能只证明画面没有运动。
- 初始化结束后的真实状态变化保留原有时长、缓动和连续切换行为。

本机制不承诺取消正常布局，也不承诺不分配任何 Transition 声明对象。动画配置对象、过渡状态和正在执行的
动画实例属于不同成本，验证时分别记录。

## 2. 动效分类与适用范围

分类以一次动效的职责为准，不以整个控件或所用动画 API 为准。

| 动效职责 | 代表场景 | 初始化策略 |
| --- | --- | --- |
| 选择与定位反馈 | Switch 把手、Segmented 选中块、Tabs 指示条 | 首次有效几何直接提交，随后允许状态过渡 |
| 状态外观反馈 | checked、active、disabled 对应的颜色、边框、透明度、缩放 | 初始状态直接提交；存在挂载后初始化写入的目标接入共享机制 |
| 过程反馈 | ProgressBar 进度及 Active 效果、Spin 旋转、loading 指示 | 保留独立的过程动画语义 |
| 显式展示过程 | 弹层打开、消息出现、显式 CountUp、应用声明的入场动画 | 遵循所属能力的播放与取消契约 |

同一控件可以包含多类动效。Switch 的把手定位参与状态初始化，loading 旋转继续按过程反馈运行。
对同一目标的整个 `Transitions` 进行抑制前，必须确认集合内过渡都服从状态初始化契约。
混合承载需要持续运行的过程过渡时，先建立明确的动画目标或执行边界，不能整体关闭该对象的过渡。

完全在挂载前完成状态投影、且所有支持的初始化与复用顺序均不产生初始过渡的目标，可以直接复用 Avalonia
已有行为。通用协议不要求给每个控件创建会话；省略会话必须有初始化和复用验证支撑。

## 3. 模型与职责

### 3.1 核心模型

| 模型 | 含义 | 所有者 |
| --- | --- | --- |
| 业务状态 | 当前选择、checked、活动项等有效值 | 控件既有 selection / value model |
| 状态基线 | 当前业务状态对应的完整外观、位置、尺寸与可见性 | 具体控件及其布局逻辑 |
| 动画目标 | 实际拥有 `Transitions` 或显式状态动画的对象 | 根控件、内部部件或模板节点 |
| 初始化会话 | 管理一组明确目标在当前生命周期中的初始化许可 | 当前 owner 的共享协作对象 |
| 目标登记 | owner、目标身份、当前挂载 / 模板代次及完成事实的关联 | 初始化会话或模板接入行为 |
| 过渡抑制作用域 | 暂时覆盖目标有效 `Transitions` 的可释放句柄 | 对应目标登记或短期操作 |
| 最终目标值 | 本次状态变化的终点，区别于动画中的当前呈现值 | 原状态 / 几何算法 |

状态基线可以是合法空状态，例如无选择且不绘制指示条。空状态不能作为从原点或零尺寸移动的来源；首次生成
有效指示器时，仍需直接提交它自己的完整几何。

### 3.2 模块边界

| 边界 | 负责 | 不负责 |
| --- | --- | --- |
| `AtomUI.Core/Animations` | 抑制作用域、初始化会话、目标登记和模板接入协议 | 选择模型、控件坐标算法、具体主题与 Token |
| `AtomUI.Controls` 及各 Control 包 | 提交业务状态和完整基线、确认有效性、提供生命周期入口 | 复制反射开关、延迟启用任务或另一套过渡执行器 |
| ControlTheme | 过渡属性、时长、缓动、Token、`IsMotionEnabled` 及外观投影 | 判断几何是否有效、推断绑定加载完成 |
| Motion / 过程反馈能力 | 显式动画自身的播放、取消和释放 | 自动接管所有状态初始化 |

共享层不缓存第二份选中项或几何结果，不持有进程级控件注册表，不反向引用具体控件包。

## 4. 共享内部协作契约

### 4.1 过渡抑制作用域

`TransitionSuppressionScope` 表达针对单个 `Animatable` 的临时抑制。底层使用公开属性系统的可撤销覆盖：

```csharp
var suppression = target.SetValue(
    Animatable.TransitionsProperty,
    null,
    BindingPriority.Animation);

// 当前操作或初始化完成时，释放自身覆盖。
suppression?.Dispose();
```

覆盖期间有效集合为空；底层的本地值、主题 Setter 和绑定继续保留。释放后由属性系统重新解析最新有效值，
不能保存旧集合再写回，也不能用 `ClearValue` 撤销其他调用者的值。

作用域必须满足：

- 同一句柄重复释放安全，释放只撤销该句柄拥有的覆盖。
- 嵌套作用域支持交错释放，仍存在抑制作用域时不能恢复过渡。
- 被覆盖的绑定或样式在抑制期间更新后，恢复最新集合，绑定继续有效。
- 在初始化完成前获取作用域；不先启动动画，再以停止或零时长模拟节省开销。
- 释放与获取在所属 UI 线程完成；短期操作使用 `using` / `try/finally` 保证异常路径恢复。

该覆盖只管理 `Transitions`。直接 `Animation` / Motion 调用需使用同一初始化许可决定是否启动，过程反馈另行管理。
作用域不提供对第三方直接改写同一最高优先级运行帧的抢占协议；此类自定义执行器须协调所有权并单独验证。

### 4.2 初始化会话

`TransitionInitializationSession` 是 owner 持有的内部协作对象，复用上述作用域管理明确登记的状态动画目标。
以下名称表达内部设计职责，不构成应用可消费的公共 API。

| 协作操作 | 契约 |
| --- | --- |
| 创建会话 / 登记目标 | 在目标挂载和初始状态写入前建立抑制，登记目标真实 owner 与生命周期 |
| 提交初始基线 | owner 已完成当前代次的全部初始写入；会话核对目标归属、加载及完成事实 |
| 核对开放条件 | 条件全部满足后释放对应抑制；重复核对不重复释放或重新安装过渡 |
| 使登记失效 | 挂载、模板或 owner 边界改变时废弃旧代次，旧完成通知不能开放新目标 |
| 查询状态动画许可 | 显式状态动画在任务和运行实例创建前检查当前目标是否允许启动 |
| 释放目标登记 | 清理旧部件、订阅及 owner 引用，不改变其他目标的状态 |

每个目标独立完成。某个目标尚无有效几何，不应阻止其他独立且已完成初始化的目标开放过渡。
`IsMotionEnabled` 继续表示是否允许动效；初始化完成事实与该开关分开，开关变化不重播初始状态。
不能仅因当前 motion 关闭而丢失初始化所有权，否则初始化期间重新开启会漏过抑制。

会话状态保存为内部普通运行状态，不作为 Token，不要求主题订阅动态 Ready 属性或伪类。
共享层优先复用控件已有生命周期入口；只有模板接入等确有必要的地方使用对象级订阅，并明确释放边界。
挂载 / 模板代次表达目标所有权的有效范围，可复用已有模板身份和生命周期状态，不要求每个控件新增一组版本字段。

## 5. 生命周期与完成条件

### 5.1 状态转换

```text
登记目标，初始化中，持有抑制
    → 写入绑定、外观和完整初始几何
    → 当前 owner / 模板 / 挂载有效，目标加载及自身初始同步完成
    → owner 确认基线完整
    → 就绪，释放初始化抑制

detach / 模板替换 / owner 替换
    → 旧登记失效
    → 可复用目标在下次挂载前重新进入初始化
```

创建会话和重新进入初始化必须幂等。同一目标的多层继承调用不能重复创建初始化作用域或提前开放过渡。
普通重复排列不重新进入初始化，不按每帧更新附加属性或构造会话。

### 5.2 完成条件

完成基线必须同时满足：

1. 目标属于当前 owner、当前模板和当前挂载代次。
2. owner 及参与同步的目标已达到所需加载阶段，各自的初始化写入已经完成。
3. 当前状态所需的所有属性都已提交，不能写完位置、尚未写尺寸时开放。
4. 几何型目标已排列，坐标转换成功，值有限，尺寸满足所属控件的有效条件。

`Loaded` 只作为生命周期条件和重新核对入口。会话不能在任意 Loaded 处理器内自动认定基线完成。
自有控件或部件在 `OnLoaded` 中还有状态同步时，必须在这些同步结束后确认；父控件的完成通知不能代替子部件
自身完成。普通模板节点由所属 owner 确认完整状态。

抑制作用域也可用于非 Visual 的 `Animatable`。这类目标没有自身 Loaded / Arrange 条件，使用明确 owner 的加载、
对象关联及初始写入完成事实；由 owner 管理创建、替换和释放，不为对象虚构视觉树生命周期。

Loaded 与有效排列的先后不固定：先得到有效几何时保持抑制，等待当前加载同步完成；先加载时保持抑制，
等待正常布局得到有效几何。等待由已有生命周期或布局入口推进，不排队补播，不轮询，不强制全树布局。

### 5.3 生命周期边界

| 场景 | 处理契约 |
| --- | --- |
| 首次创建 | 构造或模板构建阶段开始抑制，直接建立当前状态 |
| 逻辑初始化早于视觉挂载 | 抑制跨越两阶段，不能依赖只执行一次的 `OnInitialized` 维持关闭状态 |
| detach / 回收 | 废弃旧完成事实，取消旧状态动画任务；可复用目标在重新挂载前保持初始化抑制 |
| 重新挂载 / 容器换 owner | 使用当前业务状态直接建立新基线，不沿用旧几何或旧初始化许可 |
| 模板替换 | 根目标在模板变更时进入初始化，新节点在构建时开始抑制；旧节点移除后释放旧登记和引用 |
| 集合为空 / 目标未实现 | 保持原有合法空状态；没有有效来源的首次指示器直接定位 |
| 初始化后异步更新有效值 | 按正常状态变化处理，不以启动时间窗口猜测数据是否仍属于初始化 |
| motion 关闭再开启 | 遵守当前开关，不把已经提交的状态重新当作一次动画请求 |

失效与清理必须先阻止旧登记继续生效。保留供复用的目标可以持有其初始化抑制；已废弃目标释放订阅和外部
引用，使其可回收。清理旧模板不能使旧部件重新可见或开放新模板目标的过渡。

## 6. ControlTheme 与模板接入

### 6.1 过渡声明

Transitions 继续放在 ControlTheme 的 style Setter 内，按原有 `IsMotionEnabled` 等真实业务条件声明。
不直接写入 ControlTemplate 内容，不为所有主题追加动态初始化 Ready selector。

初始化期间共享层仅临时覆盖有效集合，不把时长、缓动、TemplateBinding 或样式绑定迁移到控件代码。
代码中的可撤销覆盖属于生命周期操作；外观声明与绑定仍遵守 [控件研发规范](../../../engineering/development/control-development-guidelines.md)。

### 6.2 动画目标登记

| 目标来源 | 接入方式 | 必须守住的时序 |
| --- | --- | --- |
| 根控件 | 构造阶段在会话中登记自身 | 早于首次挂载及挂载后的状态写入 |
| 自有内部部件 | 部件构造阶段建立抑制，再关联 owner 的基线协议 | 部件自身状态和父 owner 几何均完整后开放 |
| 普通模板节点 | 固定附加行为在模板构建时立即建立抑制，模板关系建立后关联 owner | 早于节点挂载；不能等 `OnApplyTemplate` 拿到节点后才首次关闭 |
| 代码创建节点 | 创建后、加入视觉树和写入初始状态前登记 | 与其创建、移除及复用路径成对 |
| Content 子树 / 独立弹层 | 由真实 owner 显式接入自身拥有的目标 | 不通过父控件递归扫描或跨 owner 禁用 |

模板接入行为的内部声明形式为：

```xml
<Border Name="PART_StateIndicator"
        atom:TransitionInitialization.Mode="Owner" />
```

`Initialization` 默认不参与，`Owner` 表示由所属初始化会话确认基线。该属性是固定接入声明，不是动态就绪值，
不继承、不驱动 Ready selector，也不由应用额外配置。声明节点自身构建时立即抑制；`TemplatedParent` 建立后
使用实际模板 owner 关联会话。跨模板或代码创建的目标采用明确 owner 关联，不搜索任意祖先或应用全树。

附加行为必须支持先建立局部抑制、后关联 owner 的顺序，并在重挂载 / owner 替换时重新关联。
未找到有效 owner 时保持初始化状态并提供可诊断信息，不能猜测完成、静默开放或不断排队重试。
该行为与上表的会话类型均为内部架构契约；实际源码可用性以验证文档为准。

## 7. 新控件接入与运行期操作

### 7.1 新控件的最小接入契约

每个状态动效目标必须回答三件事：真实目标是什么、完整基线是什么、在哪个确定入口提交完成。
存在挂载后初始写入时，登记目标、提交基线和失效清理由同一共享会话协议管理。
不新增统一基类要求，不为该能力新增源生成器，不在各控件中复制初始化开关流程。

代表性基线如下：

| 控件 / 目标 | 基线 owner | 完整基线 |
| --- | --- | --- |
| ToggleSwitch 根 / SwitchKnob | `AbstractToggleSwitch` 与把手自身同步 | 把手移动矩形、内容偏移、轨道状态及把手绘制宽度 |
| Segmented 选中块 | `AbstractSegmented` | 当前容器转换到 owner 坐标后的完整位置、尺寸及可见性 |
| TabControl 指示条 | `TabControl` | 当前容器和 presenter 有效，当前 placement 的长度、厚度及 transform |
| TabStrip 指示条 | `TabStrip` | 与独立 TabStrip 当前选择一致的指示条完整几何 |
| 一般状态外观目标 | 当前状态投影 owner | 初始伪类 / 属性 / 主题投影和该目标自身初始同步全部完成 |

控件文档只维护其真实目标、基线及入口，通过链接复用本架构；不复制共享抑制和生命周期规则。
对应入口见 [ToggleSwitch](../../../controls/desktop/data-entry/toggle-switch/overview.md)、
[Segmented](../../../controls/desktop/data-display/segmented/overview.md)、
[TabControl](../../../controls/desktop/navigation/tab-control/overview.md)、
[TabStrip](../../../controls/desktop/navigation/tab-strip/overview.md)。

### 7.2 初始化与运行期直接提交分离

初始化完成事实在当前生命周期内保持稳定。正常布局、滚动和拖动校准不能反复重启整个初始化会话。
需要无过渡写入的单次运行期操作使用独立的短期 `TransitionSuppressionScope`，操作结束后立即释放。

几何更新保留以下规则：

- 相同最终目标不重复写入、不重启或取消已经运行的过渡；比较 base target，不比较当前插值值。
- 没有有效来源几何的首次指示器直接提交；合法空状态不伪造来源。
- 选择变化与纯布局校准沿用控件自己的区分规则，不把布局事件转成选择请求。
- pointer、keyboard、binding 和 Form 引起的正常有效状态变化使用相同过渡语义。

### 7.3 显式状态动画

波纹或直接调用 Animation / Motion 的状态反馈在创建任务、取消源、Dispatcher 操作和动画实例之前检查许可。
初始化不排队等待完成后补播。已允许的异步状态反馈仍需持有当前目标身份和生命周期，执行时重新核对，
在 detach、模板替换或请求被替代时取消并释放。过程反馈不使用该状态许可关闭自身动画。

## 8. 资源、性能与 AOT 边界

### 8.1 资源所有权

| 获取 | 所有者 | 释放 / 失效边界 |
| --- | --- | --- |
| 初始化过渡覆盖 | 当前目标登记 | 完整基线且加载同步完成；废弃目标时清理 |
| 短期过渡覆盖 | 当前操作 | `using` / `finally`，包括异常和提前返回 |
| 模板 owner / 生命周期订阅 | 模板接入行为或会话 | 目标移除、owner 替换或模板登记废弃 |
| 模板目标引用 | 当前 owner 会话 | 旧模板移除、detach 清理或目标归属改变 |
| 异步状态反馈任务 | 当前请求 owner | 执行完成、被替代、detach 或模板替换 |

注册和抑制成本按实际目标数计，不能按视觉子树大小计。独立目标无需互相订阅就绪属性。
初始化完成后释放临时覆盖及一次性资源；为复用保留的会话只持有必要的登记和状态。
普通 hover、指针移动、逐帧插值和重复排列不创建作用域、不查找全局表、不更新 Ready selector。

### 8.2 成本与平台约束

共享层不新增轮询、计时器、额外动画时钟、固定延时、反复 Dispatcher 投递或强制布局。
模板接入附加值和必要订阅仍有成本，必须与省下的过渡成本一起计量，不能宣称机制零开销。

实现使用强类型公开属性、可释放值覆盖和静态 AXAML。库内初始化不调用框架私有过渡开关，不反射字段或方法，
不依赖私有动画状态查询。诊断探针可以在专项验证中观察运行实例，但不进入发布运行时。
共享协议不引入程序集扫描、字符串反射绑定或新的资源宿主。完整约束见
[AOT 编程规范](../../../engineering/development/aot-programming-guidelines.md)。

## 9. 兼容性与定制边界

初始化管理改变状态过渡开始生效的时机，保留公共 / protected API、默认选择、binding mode / priority、Form
事件、输入行为、Template Part、Semantic Part、ControlTheme key、Token、尺寸和命中区域。
完成初始化不生成额外选择事件、动画完成事件或向业务绑定写回默认值。

明确登记为状态目标的 `Transitions` 在初始化期间整体受抑制，包括应用为该目标设置的自定义过渡。
它们的声明、集合内容和绑定不被改写；结束后恢复最新有效集合，后续正常变化仍可使用自定义过渡。
自定义入场动画或过程过渡需要独立执行边界，不能依赖状态目标的初始化过渡实现入场。

替换模板的定制路径遵守相同首帧契约。AtomUI 管理明确登记的自有目标；应用新增且不属于库 owner 的目标由
其自定义模板 / 控件负责，不由共享层扫描接管。内部接入附加行为不提升为应用公共定制 API。
现有公开反射扩展的 API 兼容处置独立于库内接入，不因内部停止依赖而自动删除或更改公开签名。

## 10. 验证不变量与验收

正确性要求覆盖目标运行状态及实际呈现几何，不能只断言就绪标志或等待最终截图：

- 直接构造、提前逻辑初始化、编译 AXAML / 绑定初值和非首项选中，首幅有效画面均使用正确完整状态。
- 抑制从目标挂载前开始，初始写入不创建对应的过渡运行实例；所有真实动画目标都在覆盖范围内。
- Loaded 与有效排列的两种顺序、父子部件加载顺序和延迟容器均不提前开放过渡。
- 空状态、首次有效指示器、集合清空再填充、detach / reattach、容器复用及模板替换均没有伪造来源过渡。
- 第一次真实切换立即允许原有动画，快速切换接续当前呈现值，相同目标的重复布局不重启动画。
- 自定义过渡、本地值、动态绑定、motion 开关和抑制期间换集合后恢复正确；嵌套和交错释放保持抑制契约。
- 旧代次通知和异步状态反馈不能开放或修改新目标；异常路径、清理和 owner 释放无悬挂引用。
- ProgressBar、Spin、loading 和显式展示动画保持各自行为；原有布局、命中和输入契约保留。

性能验收分别记录初始化会话 / 作用域成本、Transition 配置分配、过渡状态与运行实例、UI 线程分配和额外布局 / 渲染失效。
既测代表性控件，也测真实 Gallery ShowCase；冷启动至少使用十个独立进程样本，重复加载报告 mean / median / P95，
前后使用相同配置和采样策略，并单独检查初始化结束后的 hover、状态切换和复用开销。
保留原始加载条件，不能靠删减模板、内容或正常动效获得节省。只有净成本证据支持时才报告性能收益。

NativeAOT 以真实发布并运行的产物验证模板行为、属性覆盖和恢复；平台结论按实际宿主分别报告。
具体矩阵、已执行证据和未覆盖范围由 [状态动效初始化验证](transition-initialization-verification.md) 维护。
用例去留遵循 [测试价值与生命周期](../../../engineering/development/test-value-and-lifecycle.md)，执行范围遵循
[按改动影响选择验证](../../../engineering/workflows/affected-verification.md)。
