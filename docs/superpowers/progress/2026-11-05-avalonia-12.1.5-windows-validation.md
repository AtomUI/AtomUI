## 源码确认的时钟与性能影响

| 上游实际变化 | AtomUI 消费路径与判断 |
| --- | --- |
| `Avalonia.Base/Threading/Dispatcher.cs` 在替换后端前保存 Now，替换后计算 `_clockOffset = oldNow - impl.Now`；`Dispatcher.Timers.cs` 改成 `_impl.Now + _clockOffset`，提交截止值时减去 offset | 维护逻辑时钟连续性，同时将 timer 的绝对截止值换算到新后端时间域。既影响初始化前已有 timer，也影响初始化后新建 timer。不是提高显示器刷新率的改动；需原生 Win32 延迟初始化对照。 |
| AtomUI 删除的 `TryShareManagedClock` 原实现先要求后端精确等于 `ManagedDispatcherImpl` | Windows `Win32Platform.Initialize` 安装 `Win32DispatcherImpl`，旧 hook 在这里原本就不生效。删除它没有移除原生 Win32 的时钟调整；共享 Dispatcher 修正仍可能改善原生调度。 |
| `Win32DispatcherImpl.cs`、`Win32Platform.cs`、`Win32PlatformOptions.cs`、`SleepLoopRenderTimer.cs`、`UiThreadRenderTimer.cs` 的两个 tag diff 为空 | Win32 后端自身仍以 Stopwatch 提供 Now、以 `due - Now` 设置 OS timer。默认渲染 timer 的选择没有被本次升级重写。不能据此推断实际帧率无回归。 |
| `Animation/IterationCount.cs` 仅把前后缀比较改为 Ordinal；Animation 其他实现、MediaContext、Composition 生产代码未变化 | AtomUI Motion 仍通过 `GlobalClockReflection` 取得全局 clock；`MotionFrameDriver` 仍沿用现有 render pulse/空提交保活路径。Windows 不安装 Wayland 专用 `MotionFrameTiming.Clock`，不得把 Wayland 呈现预测当作 Windows 能力。 |
| Skia 四个 Geometry 文件提前求 path Bounds，stroke cache 先创建新 path 再释放旧 path | 避免 UI/render 线程共享时触发惰性 bounds 初始化，并在创建失败时保留旧缓存；Icon、裁剪、边框/阴影几何间接受影响。源码不支持“整体页面加速百分比”结论。 |

## Windows 与共享控件影响

| 真实源码差异 | AtomUI 影响与验证边界 |

| Win32 OLE wrapper 接受组合 TYMED；WinScreen 修正显示器名称查询参数；GetDpiForMonitor HRESULT long→int | 复制/拖放、屏幕名称、DPI 间接受影响。Screen 的名称修正不是几何算法变化；x64 单屏结果不能覆盖 x86、混合 DPI 或跨应用介质互操作。 |
| ComboBox 限制 disabled-item 导航遍历次数、capture lost 清 pressed；Button Space release 要求 IsPressed | AtomUI 继承这些路径；新增临时用例验证空/单项/全禁用 wrap、无 press 的 release、正常点击、失焦取消。 |

| VirtualizingStackPanel 回收阈值由 anchorU 改 viewportUStart；LayoutManager 不再对移入其他 root 的对象发旧 root arrange invalidation | ListView/Select/Cascader 等继承虚拟化面板；窗口/弹层重挂接间接受影响。现有 ListView、布局、Popup 生命周期用例定向覆盖，实际大列表复杂滚动仍非穷举。 |
| 菜单 delayed open/close 捕获 Closed generation | AtomUI 部分自建 hover 路径、部分回调基类，因此只可判为部分继承。菜单已有交互测试纳入本轮。 |

| compiled/reflection indexer 识别 Item[]/Item[key] 通知；AvaloniaList 非泛型 Contains/IndexOf 不再强转 T；asset resolver 改 ConcurrentDictionary | 临时实际 AXAML 验证两种绑定和两种通知。集合与资源消费源码确认，无证据将其说成某个 Gallery 页面已经加速。 |
| query activator 从 Visual 扩展到 StyledElement；多个 automation peer 改 SetCurrentValue；密码 peer 屏蔽 Value | AtomUI breakpoint 本来就是 Control；不宣称依赖新增非 Visual query。继承的 automation/binding 路径可达，UIA 密码值暴露尚须原生客户端专项。 |

排除依据：Avalonia 自带 Calendar/DatePicker/TimePicker/AutoComplete/Page/PipsPager 与其 ColorPicker 控件实现没有替代 AtomUI 自建控件；AtomUI 不加载上游 Fluent/Simple 主题。Android/iOS/Browser/macOS/X11/Wayland/AT-SPI 后端变化不作为 Windows 验收项。构建与上游测试变化分别按发行依赖/解释生产 diff 处理，不能当作 Windows 产品改动。

现有 Windows style/background/margin/sizing/shadow-hit-test hooks 的职责未被上述变化等价替代；上游外部 WndProc hook 调用顺序与 custom-caption 路由未变化，本轮没有删除或改写这些 hook。

## 同机时钟和性能 A/B

基于官方两个版本的独立原生 Windows 进程，保持 .NET 10.0.8、相同参数与工作负载，进程统一关闭 tiered compilation。实际后端两侧均为 `Avalonia.Win32.Win32DispatcherImpl`，运行时 InformationalVersion 分别与两个源码 commit 一致。

时钟用例每侧每种模式独立启动一次，采集 125 ticks / 124 个间隔。普通模式不主动提前访问 Dispatcher；触发模式先访问 Dispatcher、等待 400ms、排入 80ms timer，然后安装原生后端，再启动后续 16ms timer。初始化本身耗时与 timer 到期时间分开登记：两侧 Setup 完成时，原 80ms 截止值已经分别过期 149.03 / 155.00ms，因此不得将其首次触发时间误写成精确 80ms。

| --- | ---: | ---: | --- |
| 普通初始化后 16ms timer：间隔 P50 / P95 / P99 | 30.23 / 31.99 / 32.60ms | 30.68 / 32.15 / 40.43ms | 单轮消息 timer 基线，受 Windows timer 粒度/调度影响，不是动画帧率。 |
| 提前访问 Dispatcher 后，后续 16ms timer：P50 / P95 / P99 | 513.74 / 531.04 / 537.46ms | 30.61 / 34.72 / 45.23ms | 旧版持续叠加后端起点差；新版消除该触发条件造成的持续迟滞。 |

该触发模式在原生 Windows 也成立，不能把 Dispatcher 修复说成只影响 Managed/Wayland。普通动画性能另以 20 个可见目标、正常初始化的多进程交错样本测量，避免将刻意引入的初始化延迟混作普通性能收益。回调时间不是屏幕 present；不以 Headless/属性回调/截图宣称 60/120 FPS。

## 清理、结论与剩余项

13 个本次临时验证用例及其 AXAML/helper 已删除，常驻测试净新增 0。清理后用相同 Desktop 模块 OR filter（移除临时 Audit 条件、增加 `--no-restore`，仍真实构建）最终通过 **412/412，0 skip，测试执行 13 秒**；Core 7/7 与 DataGrid 10/10 的产品/测试输入未变，复用本轮已取得证据，没有无理由重复运行。

已核验并删除系统临时目录中的两个独立宿主、原始 JSON、25 个画面及 contact sheets、探针二进制、源码 archive 和基线构建副本；临时目录不存在，相关进程不存在。未保留 TRX/dump/专用媒体。最终 `git diff --check` 通过；工作树仅新增本 Markdown 记录，产品源码无变更，评估阶段未创建 commit，未运行全量回归。

当前可支持的判断：源码影响面有明确消费追踪，Windows 构建与所选逻辑测试通过；延迟初始化触发的原生 Dispatcher timer 迟滞在新版消失；20 个并行动效的回调节奏和完成时间未见退化。尚不能认证 Windows 全平台、全部控件及整体 CPU/GPU 性能无回归。

原生触摸/笔、跨应用 OLE、原生 UIA、x86、混合 DPI/多屏、正式屏幕 present/ETW、Windows NativeAOT 尚未由上述证据覆盖，不得归为已全部正常。
