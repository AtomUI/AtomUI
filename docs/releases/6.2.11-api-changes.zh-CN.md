# AtomUI 6.2.11 迁移指南

[English](6.2.11-api-changes.md)

6.2.11 新增经数据源提交的 DataGrid 编辑，并修复滚动、行重排、冻结列布局及脱离后的订阅。
同时调整 FloatButtonGroup 交互语义，并替换 Gallery 打包工具链。Avalonia 仍为 12.1.4；Release 运行时包继续面向
net8.0 和 net10.0，SDK 要求保持原有配置。

## 速查表

| 范围 | 6.2.10 | 6.2.11 / 迁移动作 |
| --- | --- | --- |
| FloatButtonGroup 状态 | 本地值/绑定的 IsOpen 可能阻止 trigger 更新状态 | 交互写回 current value；使用 TwoWay 绑定，去掉重复手动切换 |
| FloatButtonGroup 事件 | Clicked、Opened、Closed 已声明但不触发 | 事件现在触发；检查原先不会执行的处理器 |
| DataGridFieldSchema | 构造函数以可选 displayAccessor 结尾 | 追加 isEditable；重新编译二进制消费方并显式启用可写字段 |
| 本地字段与 descriptor | 构造函数/Field(...) 以 propertyChangedName 结尾 | 追加 setter/fromScalar；重新编译消费方，为编辑字段提供 setter |
| 生成的注册组 | 类型名包含 6.2.10 程序集身份 | 类型名包含 6.2.11；同步升级相关包并重编译生成式消费方 |
| Gallery 打包 | 外部 AtomUITools 及 EnsureAppImageLauncher.ps1 | 使用仓库内 AppImage/DMG/zip 脚本，迁移自定义打包调用 |

## FloatButtonGroup 状态与事件

trigger 交互现在以 current value 语义回写 `IsOpen`，即使属性已有本地值或绑定也会更新。
单次设置 `IsOpen="True"` 不再将 click 模式的 group 固定为打开；禁用 group 会忽略 trigger 交互。

使用已有的 TwoWay 状态契约：

```xml
<atom:FloatButtonGroup Trigger="Click"
                      IsOpen="{Binding IsMenuOpen, Mode=TwoWay}"
                      Opened="HandleMenuOpened"
                      Closed="HandleMenuClosed" />
```

请删除为补偿旧行为而再次切换 `IsOpen` 的事件逻辑。`Clicked` 现在报告 trigger 点击，`Opened`/`Closed` 报告实际状态变化，
包括程序设置引起的变化。旧版本中从未执行的处理器升级后可能开始执行，不应重复切换状态或重复提交业务动作。

## DataGrid 编辑与二进制签名

`DataGridFieldSchema`、`DataGridLocalField<T,TValue>` 和 descriptor 的两个泛型 `Field<TValue>` 重载追加可选参数，
会改变 IL 方法签名。省略新参数的源码调用仍能编译，但旧二进制消费方必须重新构建，不能只替换包 DLL。

单元格与整行编辑经 `IDataGridEditableSource` 提交。schema 未标记 `IsEditable=true` 的字段保持只读；只设置列的
`IsReadOnly=false` 不能让源字段变为可写。本地字段配置 setter 后会自动将 schema 标记为可编辑：

```csharp
var nameField = new DataGridFieldId("name");
var descriptor = DataGridLocalSourceDescriptor.For<Row>(
    static row => DataGridRowKey.FromInt64(row.Id))
    .Field(nameField, static row => row.Name, StringComparer.Ordinal,
        setter: static (row, value) => row.Name = value);
var source = DataGridLocalSource.Create(rows, descriptor);
```

自定义源需在 `DataGridFieldSchema` 中以 `isEditable: true` 标记可写字段，并实现已有的 `CommitAsync` 契约。
可编辑列应设置对应 `FieldId`。内置标量转换不适用于字段类型时，提供 `fromScalar`。转换无效时保留编辑器；
整行“保存”一次提交可编辑字段，“取消”丢弃待提交值，不直接修改数据项。

## 生成的注册身份

`AtomUI.Generated.*.ControlPackageGroup_*` 类型名包含程序集身份，因此在 6.2.11 中再次变化。
请同步升级相关 AtomUI 包和显式引用的 Generator，清理并重新编译自定义控件包与应用，重新发布裁剪/NativeAOT 应用。
不要直接引用生成组名，也不要将已编译的 6.2.10 注册元数据与 6.2.11 包混用。

## Gallery 打包调用

已移除的 `controlgallery/AtomUIGallery.Desktop/scripts/EnsureAppImageLauncher.ps1` 不再是入口。
自定义流水线应先经 `PublishToLocal.ps1` 发布，再使用 `controlgallery/AtomUIGallery.Desktop/scripts/packaging/` 下的脚本：

- `New-GalleryZip.ps1`：Windows zip。
- `New-GalleryAppImage.ps1`：Linux AppImage，包含启动器和图标准备。
- `New-GalleryDmg.ps1`：macOS app bundle/DMG 与签名。

在 Linux 主机上发布到 `$publishRoot` 后的调用示例：

```powershell
& ./controlgallery/AtomUIGallery.Desktop/scripts/packaging/New-GalleryAppImage.ps1 `
    -ConfigPath "$publishRoot/config/InstallerConfig.xml" `
    -PackagesPath "$publishRoot/packages" `
    -OutputPath "$artifactRoot" -Runtime linux-x64 -BuildStamp 1101
```

一次发布的所有平台应使用同一个 `BuildStamp`，CI 中必须提供。依赖旧文件名的下载脚本应核对新命名方式，
例如 `AtomUIGallery-6.2.11.1101-win-x64.zip`。macOS 正式打包需提供签名身份并启用 `-RequireSignature`。
Windows、Linux、macOS 安装包需在各自匹配的主机上构建，脚本中的平台限制是有意设计。
详见 [Gallery 发布流程](../engineering/workflows/gallery-aot-release-workflow.md)。

## 兼容性修复与 Mono 支持边界

DataGrid 主动行移动现在保持视口位置，不再跟随旧首行；普通外部数据失效继续保持内容锚点。
右冻结列的缩放手柄调整其自身列。使用这些修复不需要新增控件配置。

TypeMap 物化后端扩展到受支持且实际执行链接的 iOS/Android Mono 应用，包括 iOS partial linking。
Browser full-trim 条件以及未裁剪/copy 模式的原行为保留，未增加桌面 SDK 或 TFM 要求。
平台主机、签名及部署验证与普通库构建分开进行。

## 包验证

已对全部 21 个 Release 包与 NuGet 发布的 6.2.10 基线进行比较，net8.0 与 net10.0 合计报告 18 项诊断，
没有无法解析引用的诊断：

| 诊断 | 数量 | 原因 |
| --- | --- | --- |
| `CP0001` | 10 | Controls、Desktop.Controls、GalleryBase、DataGrid、ColorPicker 的版本化注册组 |
| `CP0002` | 8 | DataGridFieldSchema 构造函数、DataGridLocalField 构造函数及 descriptor 的两个 Field 重载 |

其余 16 个包无 API 差异。历史 API 门禁按预期对这些已记录的二进制变化失败；未添加 suppression，本版不声明
与 6.2.10 的二进制兼容性。沿用 6.2.10 的发布策略，正式打包不设置历史 API 基线，同时保留上述比较作为发版证据。
全部 21 个包的布局与 6.2.10 一致，没有修改布局 allowlist；常规 Release 打包及目标框架校验均通过。
