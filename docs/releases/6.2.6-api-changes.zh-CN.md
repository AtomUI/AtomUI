# AtomUI 6.2.6 API 变更示例

本文说明 AtomUI 6.2.6 相对于 AtomUI 6.2.5 发布的启动与主题 API 变更。这些源代码和二进制兼容性变更要求应用和生成式消费方完成迁移后再重新构建。

英文版本见 [AtomUI 6.2.6 API Change Examples](6.2.6-api-changes.md)。

设计见[启动系统架构](../architecture/systems/startup/overview.md)，接入示例见[启动指南](../guides/startup/overview.md)。

## 快速对照

| 区域 | 6.2.5 | 6.2.6 迁移 |
| --- | --- | --- |
| AtomUI 入口 | `App.Initialize()` 中调用 `Application.UseAtomUI(Action<IAtomUIBuilder>)` | 在 `BuildAvaloniaApp()` 中调用 `AppBuilder.UseAtomUI(Action<IAtomUIBuilder>)` |
| 应用类挂接 | 无 | 应用类声明为 `partial`，由生成器生成 `RegisterServices`；或手写 `ApplicationStartup.Attach(this)` |
| 配置回调时机 | 应用对象已创建后执行 | 平台初始化之前执行；只声明包与设置，需要内核就绪的代码移入 `AddInitializer` |
| 启动 Splash | `AtomUI.Desktop.Controls.Extras` Splash，手动显示和关闭 | 框架管理的 `AtomUI.Controls` Splash，用 `UseSplash` 配置；加载流程移入 `UseMainWindow` |
| macOS 渲染 | OpenGL、Metal、Software | Metal、OpenGL、Software；需要 OpenGL 时覆盖 `AvaloniaNativePlatformOptions` |
| `IThemeManagerBuilder` | 无编译主题包成员 | 自定义实现补 `AddCompiledThemePackage(CompiledThemePackage)` |
| `ILocalizationBuilder` | 无模块数据成员 | 自定义实现补 `AddModuleData(string, string)` |
| 生成注册组 | `ControlPackageGroup_*` 名称包含 6.2.5 程序集标识 | 名称包含 6.2.6 标识；同步升级相关包并重新编译消费方 |
| 主题来源标识 | `AtomUI.Core.BuiltInThemes` 与 `avares://AtomUI.Core/...` | `AtomUI.Core` 与 `AtomUI.Core/Assets/Themes/...` 等逻辑路径 |
| 启动包清单 | 版本 1 | 版本 2；版本 1 清单会报告重建错误 |
| Avalonia 依赖 | 12.1.3 | 最低 12.1.4；升级 AtomUI 前先更新固定版本的 Avalonia 包 |
| 包布局 | 无编译主题构建目标，`tools/net10.0` 无 Avalonia 程序集 | 新增 `buildTransitive/AtomUI.CompiledThemes.targets` 与 Avalonia 任务依赖；字体包开始携带注册载荷 |

## 破坏性变更

### 入口从 `Application.UseAtomUI` 移到 `AppBuilder.UseAtomUI`

`Application.UseAtomUI(Action<IAtomUIBuilder>?)` 已删除。配置改在 `AppBuilder` 链上声明：

```csharp
// 6.2.5：App.axaml.cs
public override void Initialize()
{
    AvaloniaXamlLoader.Load(this);
    this.UseAtomUI(builder =>
    {
        builder.WithInitialTheme(IThemeManager.DEFAULT_THEME_ID);
        builder.UseDesktopControls();
    });
}
```

```csharp
// 现在：Program.cs
public static AppBuilder BuildAvaloniaApp() =>
    AppBuilder.Configure<App>()
              .UseAtomUIPlatformDetect()
              .WithAtomUIDefaultOptions()
              .UseAtomUI(builder =>
              {
                  builder.WithInitialTheme(IThemeManager.DEFAULT_THEME_ID);
                  builder.UseDesktopControls();
              });

// 现在：App.axaml.cs
public partial class App : Application
{
    public override void Initialize() => AvaloniaXamlLoader.Load(this);
}
```

AtomUI 内核在 `Initialize()` 之前提交，`App.axaml` 可以直接引用 AtomUI 资源。`GetThemeManager()`、`GetLocalizer()`、
`GetLanguageManager()` 保持不变。

### 应用类必须挂接

应用类声明为 `partial` 即可，AtomUI 生成器生成 `RegisterServices` 重写并调用 `ApplicationStartup.Attach(this)`。不能声明为
partial 时手写：

```csharp
public override void RegisterServices()
{
    base.RegisterServices();
    ApplicationStartup.Attach(this);
}
```

手写了 `RegisterServices` 却没有调用 `Attach` 时报新的编译错误 `ATOMUIGEN039`；既没有挂接也不是 partial 时，启动在
`Initialize()` 之后抛出带修复说明的 `InvalidOperationException`。不要在应用构造函数中创建控件或访问主题。

### 配置回调在平台初始化之前执行

配置回调现在于主线程、Avalonia 平台初始化之前执行，回调中不能访问 `FontManager`、`Application.Current`、`TopLevel`，
也不能创建位图或控件。`UseAlibabaSansFont()`、`UseAlibabaPuHuiTiFont()` 的字体集合改为在内核提交时注册。需要在
内核就绪后执行的代码放进 `builder.AddInitializer(themeManager => …)`。

### Splash 迁入 `AtomUI.Controls`，Extras 中的 Splash 删除

启动 Splash 改由框架管理，Extras 中的 Splash 实现已删除：

```csharp
using AtomUI.Controls;

builder.UseSplash(SplashMode.Auto, splash => splash
    .WithLogo(new Uri("avares://MyApp/Assets/logo.png"))
    .WithTitle("My App"));
```

- Splash 在内核提交之前显示，主窗体首个渲染批次完成后自动隐藏并关闭，不再需要手动关闭，也不再有最短显示时长。
- 启动期间的应用自有加载（原先在 Splash 显示期间手动更新进度的流程）改用 `builder.UseMainWindow(async context => …)`，
  经 `context.Progress` 汇报进度。
- 外观定制改用 `WithControlTheme<TTheme>()`：只能使用 Splash 控件、Avalonia 基础元素与全局 Token。
- 新的 `AtomUI.Controls.Splash` 是 `TemplatedControl`，不再是 `ContentControl`；页面内预览需要合并 `SplashDefaultTheme`。

`AtomUI.Desktop.Controls.Extras` 中删除的公共类型：

- 控件与服务 API：`Splash`、`SplashWindow`、`SplashStatus`、`SplashOptions`、`SplashService`、`ISplashService`、
  `SplashPseudoClass`，以及 `Splash` 的静态显示/消息/进度/状态 API 与 `Splash.DefaultService`。
- 生成的 Token API：`SplashTokens`、`SplashTokenKey`、`SplashTokenKind`、`SplashTokenResourceExtension`、
  `SplashWindowTokens`、`SplashWindowTokenKey`、`SplashWindowTokenResourceExtension`。
- 生成的 Semantic Part 样式：`SplashTitleStyle`、`SplashSubtitleStyle`、`SplashMessageStyle`、`SplashContentStyle`、
  `SplashFooterStyle`、`SplashLogoStyle`、`SplashSpinStyle`、`SplashDetailStyle`、`SplashProgressBarStyle`。
- Extras XAML 删除后，其 `CompiledAvaloniaXaml.!XamlLoader` 与 `!AvaloniaResources` 类型也不再生成；它们由编译器生成，
  不属于消费方契约。

新的 `AtomUI.Controls.Splash` 没有控件 Token 与生成的 Semantic Part 样式类型：尺寸、颜色和排版值写在
`SplashDefaultTheme` 中，外观覆盖通过 `WithControlTheme<TTheme>()` 完成。旧 Extras Splash 基于 Token 的定制方式不能
直接沿用。

`AtomUI.Desktop.Controls.Extras` 暂无控件，`UseDesktopExtras()` 保留并只登记一个空包。

### macOS 默认渲染改为 Metal 优先

`WithAtomUIDefaultOptions()` 在 macOS 上的渲染顺序由 OpenGL、Metal、Software 改为 Metal、OpenGL、Software。原先选 OpenGL
是为了规避 Metal 在 live resize 时的内容抖动，该问题已由 Avalonia 12.1.0 修复。需要保留 OpenGL 时，在
`WithAtomUIDefaultOptions()` 之后覆盖：

```csharp
.WithAtomUIDefaultOptions()
.With(new AvaloniaNativePlatformOptions
{
    RenderingMode = [AvaloniaNativeRenderingMode.OpenGl, AvaloniaNativeRenderingMode.Metal, AvaloniaNativeRenderingMode.Software]
})
```

### `IThemeManagerBuilder` 新增成员

`IThemeManagerBuilder` 新增 `AddCompiledThemePackage(CompiledThemePackage)`。自行实现该接口的代码需要补齐该成员。

### `ILocalizationBuilder` 新增模块数据注册成员

`ILocalizationBuilder` 新增 `AddModuleData(string moduleId, string data)`。自定义实现必须补齐该成员，并保证每个生成的
本地化模块只注册一次。生成式消费方应使用匹配版本的 Generator 与 Localization 包，使模块数据在本地化 registry
冻结前完成校验。

之前：

```csharp
public sealed class CustomLocalizationBuilder : ILocalizationBuilder
{
    public void AddCatalog(LanguageCatalogDescriptor descriptor) { /* 原有实现 */ }
    public void AddTranslationBundle(TranslationBundleDescriptor descriptor) { /* 原有实现 */ }
    public void AddLanguageDefinition(LanguageDefinition definition) { /* 原有实现 */ }
    public void ConfigureLanguages(LanguageTag defaultLanguage, IEnumerable<LanguageTag> supportedLanguages) { /* 原有实现 */ }
}
```

之后：

```csharp
public sealed class CustomLocalizationBuilder : ILocalizationBuilder
{
    public void AddModuleData(string moduleId, string data)
    {
        // 在 registry 冻结前保存并校验生成的模块数据。
    }

    // 保留其余 ILocalizationBuilder 成员。
}
```

### 主题来源标识变化（诊断中可见）

- 内置主题的注册标识由 `AtomUI.Core.BuiltInThemes` 改为 `AtomUI.Core`。
- 内置主题的来源标识由 `avares://AtomUI.Core/Assets/Themes/DaybreakBlue.theme.xml` 形式的 URI 改为
  `AtomUI.Core/Assets/Themes/DaybreakBlue.theme.xml` 形式的逻辑路径。

按这些字符串匹配主题诊断的代码需要同步修改。

### 生成的注册组标识变化

`AtomUI.Controls`、`AtomUI.Desktop.Controls`、`AtomUI.Toolkits.GalleryBase`、`AtomUI.Desktop.Controls.DataGrid`、
`AtomUI.Desktop.Controls.ColorPicker` 与 `AtomUI.Desktop.Controls.Extras` 中公共的
`AtomUI.Generated.*.ControlPackageGroup_*` 类型名发生变化。生成器把包含包版本的包程序集标识哈希进组名，因此 6.2.5
预编译的消费方无法把旧组类型绑定到 6.2.6 的对应类型。

请同步升级所有相关 AtomUI 包与 Generator，再重新编译应用和消费生成注册元数据的自定义控件包；裁剪或 NativeAOT 应用
需要重新发布，使链接使用当前注册组。不要直接引用生成组名，改用 `UseAtomUI`、`UseDesktopControls()` 等包注册 API。
`AtomUI.Fonts.AlibabaSans` 与 `AtomUI.Fonts.AlibabaPuHuiTi` 现在也参与同一注册管线，其生成标识遵循相同规则。

## 新增 API

启动类型按职责命名，统一去掉 `AtomUI` 前缀：`ApplicationStartup`、`IStartup`、`StartupState`、
`StartupProgressEventArgs`、`StartupProgress`、`MainWindowContext`、`StartupBuilderExtensions`。
这些 API 尚未在 6.2.5 中发布；使用过早期启动预览版的应用需要更新显式类型引用，并使用匹配的 Core 与 Generator 重新构建。

- `AppBuilderExtensions.UseAtomUI(this AppBuilder, Action<IAtomUIBuilder>)`、`ApplicationStartup.Attach(Application)`。
- `Application.GetStartup()` 与 `IStartup`：`State`（`Preparing`、`Committed`、`Presenting`、`Ready`、`Failed`、
  `Canceled`）、`Completion`、`ProgressChanged`。
- `UseMainWindow(Func<MainWindowContext, Task<Window>>)`、`MainWindowContext`、`StartupProgress`。
- `SplashMode`；`AtomUI.Controls` 中的 `UseSplash`、`SplashOptionsBuilder`、`Splash`、`SplashWindow`、`SplashProgressBar`、
  `SplashStatus`、`SplashDefaultTheme`。
- `AtomUI-Startup` EventSource（默认关闭）。
- 编译主题包基础设施：`AtomUI.Theme.Definitions.Compiled` 命名空间中的 `CompiledThemePackage`、`CompiledThemeProgram`、
  `CompiledThemeBindingBuilder`、`CompiledThemeValueWriter`、`ThemeBuildOwnerAttribute`、`ThemeBuildTokenAttribute`，以及
  `AtomUI.Core` 生成的 `AtomUI.Generated.AtomUICore.GeneratedThemePackageRegistration`。这些类型供生成代码使用；不要
  自行调用 `GeneratedThemePackageRegistration.Register`，Core 已自动注册自身的主题包，重复调用会重复注册。

## 启动包清单版本 2

控件包与应用须使用匹配的 Generator/Core 重新构建。启动包清单和应用镜像现在使用版本 2，包含 owner/key 的精确
定义程序集、语义属性/目标和全局资源键 schema 证据。版本 1 会报告重建错误；条件注册、编译主题和语言 ABI 各自独立。

`Application.GetAtomUI()` 返回应用的 `IAtomUI` 运行时。初始提交后可在 UI 线程调用
`LoadPackages(Action<IAtomUIBuilder>)` 原子追加包；该入口不能修改初始应用设置。
回滚与生命周期规则见[控件包启动接入](../guides/startup/package-authoring.md)。

## 构建与包布局新增

注册包新增构建资产，没有删除任何消费方可见文件。

### Avalonia 依赖升级到 12.1.4

AtomUI 包现在依赖 Avalonia 12.1.4（`Avalonia`、`Avalonia.Desktop`、`Avalonia.Wayland`、`Avalonia.X11` 及其他平台包）。
包清单把 12.1.4 声明为最低版本，固定在 12.1.3 的解决方案必须先升级到 12.1.4 才能使用 AtomUI 6.2.6。Wayland 共享时钟
适配不再检查 Avalonia 程序集版本号，改为校验调度后端和时钟结构。

- 所有注册包都携带 `buildTransitive/AtomUI.CompiledThemes.targets`。其 `GenerateAtomUICompiledThemeInputs` 目标仅在项目
  声明了 `AtomUIThemeDefinition` 项时执行，并把生成的 `.atomuithemeinput` 文件作为 `AdditionalFiles` 交给编译器。未声明
  主题定义的项目不会多出构建步骤。
- `tools/net10.0` 新增编译主题构建任务在隔离进程中加载的 Avalonia 实现程序集（`Avalonia.Base`、`Avalonia.Controls`、
  `Avalonia.Markup`、`Avalonia.Markup.Xaml`、`Avalonia.Dialogs`、`Avalonia.DesignerSupport`、`Avalonia.Metal`、
  `Avalonia.OpenGL`、`Avalonia.Vulkan`、`Avalonia.MicroCom`、`Avalonia.Remote.Protocol`、`Avalonia`、`MicroCom.Runtime`）。
  任务进程不会加载消费方自己的同名程序集。
- `AtomUI.Fonts.AlibabaSans` 与 `AtomUI.Fonts.AlibabaPuHuiTi` 现在参与启动包注册管线，因此携带标准的 `buildTransitive`
  与 `tools` 载荷。按普通 AtomUI 包的方式引用即可。

### 包校验结果

以 6.2.5 为基线的包 API 校验在 20 个包中的 8 个、两个目标框架上共报告 68 个有意的诊断：2 个 `CP0002` 对应删除的
`Application.UseAtomUI`，4 个 `CP0006` 对应两个接口新增成员，12 个 `CP0001` 对应生成的注册组标识，50 个 `CP0001`
对应 Extras 中删除的 Splash 类型。这些是已记录的源代码与二进制破坏，不是通过兼容性校验，也不得用抑制文件消除。
包布局校验相对 6.2.5 只有上述新增项，已记录在 `scripts/verification/package-layout-allowlist.json`。
