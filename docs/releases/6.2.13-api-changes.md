# AtomUI 6.2.13 migration guide

[简体中文](6.2.13-api-changes.zh-CN.md)

This guide covers upgrading from 6.2.12. Avalonia advances to 12.1.5; Release runtime packages continue to target
net8.0 and net10.0 with the existing SDK requirements. See the [Changelog](../../CHANGELOG.md) for release highlights.

## Quick reference

| Area | 6.2.12 | 6.2.13 / migration |
| --- | --- | --- |
| Avalonia dependency | 12.1.4 | 12.1.5 minimum; update pinned Avalonia packages before upgrading AtomUI |
| Generated registration groups | Names encode the 6.2.12 assembly identity | Names encode 6.2.13; upgrade the package set and rebuild generated consumers |

## Avalonia dependency advances to 12.1.5

AtomUI packages now depend on Avalonia 12.1.5 (`Avalonia`, `Avalonia.Desktop` and the platform packages). The package
manifest declares 12.1.5 as the minimum, so a solution pinned to 12.1.4 must move to 12.1.5 before it can consume
AtomUI 6.2.13:

```xml
<PackageVersion Include="Avalonia" Version="12.1.5" />
<PackageVersion Include="Avalonia.Desktop" Version="12.1.5" />
```

Update every explicitly referenced Avalonia package to the same version. AtomUI 6.2.13 relies on fixes in 12.1.5:
the Wayland shared-clock compatibility path and the internal input text presenter that refreshed selection foreground
are removed. Input templates keep `PART_TextPresenter` and the `input` Semantic Part, which are now plain Avalonia
`TextPresenter` instances. Application-wide `TextPresenter` type selectors now also match these input nodes; scope
such styles if they were not meant for AtomUI inputs.

## Generated registration identities

Generated `AtomUI.Generated.*.ControlPackageGroup_*` type names include the assembly identity and change with
6.2.13. Upgrade related AtomUI packages and any explicit Generator reference together, clean and rebuild custom
control packages and applications, then republish trimmed/NativeAOT applications. Replacing DLLs without rebuilding
generated consumers is insufficient. Do not reference generated group names directly or mix compiled 6.2.12
registration metadata with 6.2.13 packages. This follows the [6.2.12 migration precedent](6.2.12-api-changes.md).

## Compatible changes

- DataGrid adds `DataGridSelectTriggerType.Row` as a new last enum value. The default stays `SelectIndicator`, and
  `Cell` keeps its semantics. Exhaustive `switch` statements over the enum may need a `Row` branch.
- `ListView` adds the protected helper `EnumerateSourceIndexes()` for derived selection logic.
- GalleryBase adds `GalleryShellOptions.CollapsedSidebarHeaderSpacing` (`double?`, default `null`). The collapsed
  sidebar now keeps a bottom spacing under the header action that follows `UniformlyMarginXXS` (4 by default).
  Products that added their own margin to the header action to work around the missing spacing should remove it, or
  the spacing doubles. Negative, NaN and infinite values throw `GalleryConfigurationException`.
- Masonry no longer animates existing items on relayout; new items still fade in and removed items still fade out.
  No API changes; `MotionDuration` now applies to the appear fade only.

These changes require no application migration.

## Package validation

All 21 release packages were compared with the published 6.2.12 packages. The historical API comparison reports
10 `CP0001` diagnostics: one versioned registration group in each of Controls, Desktop.Controls, GalleryBase,
DataGrid and ColorPicker, across net8.0 and net10.0. The other 16 packages pass; there are no other API incompatibilities
or unresolved-reference diagnostics.

The historical API gate therefore fails for the documented registration identities. No suppression is added,
and this release does not claim binary compatibility with 6.2.12. Following the 6.2.12 publication strategy,
the normal release pack uses no historical API baseline and succeeds for all 21 packages, including target-framework
validation. All 21 package layouts match 6.2.12 without an allowlist change; the package manifests declare Avalonia
12.1.5. The runtime behavior changes above remain part of the manual migration audit, since an assembly API comparison
cannot detect them.
