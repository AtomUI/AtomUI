# 编译主题包：验证与交付

> 本文维护验收契约及第 8 节的验证状态。记录只证明列明的源码、场景与平台范围，
> 不能外推为任意主题、第三方回调或全部平台的无泄漏证明。

## 1. 共同判据

编译包必须同时满足语义、生命周期、构建可复现、裁剪与性能要求。任何一个维度失败都不能仅凭首帧更快宣称完成。
首次验证范围先覆盖 Core 默认主题与 Gallery 四个颜色主题，再扩展真实跨包 Control 覆盖与动态作用域；
它们提供有限、可复查的基线，不代表第三方包已经自动获得支持。

维护者按[测试价值与生命周期](../../../../engineering/development/test-value-and-lifecycle.md)建立有效的实现前后证据。
新增探针默认临时，独立工程优先系统临时目录；需内部 API/Headless 时使用测试项目 Temporary 目录。
验证后删除探针和专用产物，在最终清理后的工作树执行所改模块的精确测试；不自行运行全量回归。
常驻保障优先复用共享契约测试；新增必须证明独立价值、全局运行必要性与合理成本。

## 2. 语义差分

对同一原始主题、相同实际注册集合与同一配置分别执行：

1. 动态 XML Reader/Binder + 运行期编译。
2. 生成的类型化注册/默认赋值 + 同一运行期编译。

以规范定义、独立 golden 值及旧路径运行证据共同裁定结果；两个入口使用同一运行时不等于结果相同就证明算法正确。
至少比较 Global Seed/Map/Alias、palette、Control Own/Global 差量、资源 key/CLR 类型和值、appearance、元数据及诊断。
比较同时验证成功值与失败的阶段，不能把任意两种失败都当作等价。

| 输入/行为 | 必须证明 |
|---|---|
| 默认、Dark、Compact、Dark+Compact、不同算法顺序 | 完整算法替换/次序/effect 与 runtime 相同 |
| Algorithms 未指定、显式空、未定义枚举 | 继承/默认/拒绝三者正确区分 |
| 根与多层局部 Inherit=false | 根保留所选定义，局部回到库默认；兄弟作用域互不污染 |
| Seed、Map、Alias 同时覆盖 | 写入阶段正确，派生值和最终显式覆盖都正确 |
| Control disabled/global/custom 与局部 Global 覆盖 | 只影响该控件；context variant 与其他控件不变 |
| 字体描述、Motion/Wave、运行时改色 | 动态输入参与正常合并与算法执行，不被静态默认值覆盖 |
| 精确 owner、同 Catalog/Id 不同 CLR 类型、未知 Control/Token | 冲突与未知条目失败，不因生成路径跳过验证 |
| 注册追加及 slot 重排 | 原控件不读到其他控件值，绑定代际正确 |
| app 覆盖、DynamicResource、variant、未知资源 key | 与现有查询/词法优先级一致 |
| 未访问控件、多个冷主题、只枚举菜单 | 不调用无关 evaluator，不构造静态资源；菜单主色保持定义语义 |
| evaluator 首查失败/之后重试 | 未查询前不额外执行；失败不写部分 cell 或异常成功缓存 |
| typed clone/freeze/thaw | 支持域的静态值不经 Format→Parse；嵌套可变数据不能反向改变快照 |

纯值默认要求类型与值精确相等。确需浮点容差的场景必须由算法契约预先定义边界并验证舍入后效果，不能为了让
类型化路径通过而放宽断言；缓存输入身份不能使用这种宽松容差。覆盖 Pow、Floor/Ceiling、整数溢出、非有限数及颜色
通道边界。颜色字面量 HSL/HSV→ARGB 转换应与动态解析结果一致。

## 3. 构建、ABI 与恶化输入

| 验证 | 预期 |
|---|---|
| XML 错误 namespace/重复 Id、token、DTD/外部实体/超限 | 构建诊断带逻辑来源与位置，无旧生成代码兜底 |
| 静态值 codec 不支持或不可访问构造 | 明确构建错误，不生成延迟字符串解析调用 |
| XML 不变但 schema、值契约或生成实现改变 | 增量失效，输出与身份更新 |
| 程序 ABI 不兼容 | 明确失败，不回读原 XML |
| 私有传输旧版本、损坏/截断、错误摘要/长度/索引 | 输入被拒绝；版本 4 接受声明与真实 codec 的规范值，不接受算法派生结果 |
| 相同输入重建、换工作目录、并行框架/配置构建 | 稳定逻辑身份与输出；无绝对路径泄露、串写或随机 hash |
| 生成中断与新错误覆盖旧正确输入 | 不编译/打包上一次残留产物 |
| 工程引用与真实 NuGet 消费 | 相同语义，必要元数据/工厂齐全；工具 DLL 不进入运行时 |
| XML 导出/资源保留策略 | 符合包声明，无静态错误自动回读 XML |

所有路径遵守容量限制；输入规模还要包含 package 数、静态数据展开倍数与 source map/诊断规模。
测试不能只统计 XML 原始长度而忽略生成数据、类型化对象和缓存 key 的体积。

## 4. 对象图与泄漏验证

内存验证以对象可达性和存活数量为主，RSS 只作辅助。不以“内存看起来稳定”替代引用链证据。
GC 测试隔离测量 helper 的栈/闭包，保持要模拟的长寿命源存活；否则测试可能因为连源一起释放而误报通过。

| 生命周期场景 | 不可省略的断言 |
|---|---|
| 两个 Application 使用同一编译包 | 不共享带 owner 的字典/主题/绑定；关闭 A 后 B 正常更新，A 及其视图可回收 |
| 超过各缓存 entry 与 byte 上限，连续不同配置 | source/binding/snapshot/control 计费生效，冷槽与已物化槽都覆盖 |
| 仅保留一个合法旧读取视图 | 只保留其所需版本；不能经 source→cache 保活其他已逐出的历史快照 |
| 应用关闭后旧视图首次查询冷槽 | 以冻结输入独立得到纯值；cache miss 不重建应用服务、不回填已关闭缓存、不挂资源 owner |
| 反复主题切换、scope attach/detach/reparent | 旧 scope/provider/桥/订阅数不单调增长，当前 scope 继续动态更新 |
| 包及 collectible ALC 生命周期 | 释放应用和全部合法旧视图后，Core 静态表不再持有包 Type/委托/实例 |
| 已物化 cold cell | 输入、临时 builder/source 可释放；无 parent snapshot 链 |
| 值中含数组/集合/外部对象 | 防御性复制/不可变性约束成立，缓存不能观察调用方后续修改 |
| 资源 owner 解绑 | DynamicResource 与 variant 订阅对称；当前宿主有效更新不被误删 |
| 重复失败或取消 | 不积累 Task/CTS/异常/source map/factory 闭包，重试正常 |
| 本机资源与池化缓冲 | 获取/释放计数配对；已发布值不引用已归还 buffer |

对于可能携带宿主的自定义值，验证明确支持范围与拒绝路径；不能宣称框架预算或 GC 测试覆盖了任意第三方私有对象图。
编译数据占用的二进制、mapped pages、托管解码结果与原生资源分别记录。

## 5. 事务、取消与故障注入

在真实注册/资源调用位置制造错误，保持原触发条件，不通过关闭动画、删除 scope、取消动态绑定或换成空资源规避。

- 提交前的全局/Control 默认赋值或运行时计算失败、ABI 不匹配和候选资源 factory 失败；活动查询状态仍来自旧 snapshot。
- 提交后的冷控件槽或延迟资产首次查询失败：保留当前已提交 snapshot，本次查询正常报告失败，不发布部分结果，
  后续按既有查询/资产契约重试。不能回退根主题，也不能把查询异常吞成 Publish warning。
- AddOwner/OwnerChanged/RemoveOwner、两个事件访问器及批量资源通知分别抛错；每个候选释放动作都被尝试，
  原始异常与清理错误有可审查结果，之后合法重试不被残留 owner 阻塞。
- Prepare→排队 Commit→Publish 内重入各时点关闭应用；终态只完成一次，迟到结果不挂回宿主或回填缓存。
- 两个等价等待者取消一个，以及全部等待者取消；区分调用方等待取消与共享生产完成/取消。
- 不响应取消的受控测试回调反复遇到等待超时：实际生产数与输入预算仍有界，不能提前释放配额后无限重试；
  回调实际退出后记录和引用可释放，关闭后的迟到结果不回填。
- 持续快速请求 A→B→C；旧 generation 不发布，最后合法请求生效，资源值与事件版本一致。
- Catalog reload 占执行门、随后用户切换/再次 reload；用户意图不丢失，reload 不混用旧目录与新来源。
- 编译包含未注册的显式 Control，且主题尚未被选中；Catalog 仍按严格要求拒绝，不能只在选中时才发现。
- CommitCore 前的准备与提交后的 Publish 通知分别注入错误：前者失败且活动状态未变；后者报告警告并继续通知，
  不伪装回滚或重复启动失败。该规则仅限 Publish 外部通知异常，不覆盖后续资源查询异常。

并发首查必须 single-flight，用户回调不处在缓存全局锁中；自身槽递归调用必须诊断而不无限递归/死锁。

## 6. 平台、裁剪与宿主

最小门包括普通 JIT、真实 NuGet 消费、net8 条件后端、现代 TypeMap、NativeAOT 和 Browser 真实裁剪/AOT。
当前平台支持事实由[AOT 架构](../../../foundations/aot-and-trimming.md)维护，文档目标不自动扩大支持平台。

验证至少使用：仅全局颜色的包、明确覆盖一个控件的包、不同程序集同名 owner、多个控件共享资产、未使用控件组。
对比真实链接后的保留集合、工厂集合和普通结果：仅全局主题不得保留所有控件；显式 Control 要求只能扩大到其真实
依赖；未注册包必须报错，不能由主题入口代为启用。

NativeAOT 产物要检查没有退化成 CoreCLR，并执行实际查询/切换。Browser 要检查输出与真实运行，不能用普通
编译或 headless 测试代替。启动后再次切换主题/语言、打开此前未查询控件。

macOS 至少核对首帧完整 chrome、应用名、标题栏主菜单、内置主题列表及切换；其他声明支持的平台覆盖对应
窗口/资源生命周期。UI 工具无法可靠识别当前产物时按 Gallery 本地调试规则记录限制，使用可复核人工证据。

## 7. 性能与复杂度验收

以相同主题、控件注册/裁剪集合、字体、语言、算法、功能和业务就绪状态比较动态 XML 与类型化声明两条路径。
Release JIT 与 NativeAOT 分开，冷进程与热切换分开，样本策略固定且保留原始数据，不删除不利样本。
至少记录中位数、尾部及范围，并注明设备、目标、代码身份和可用样本数；单次 smoke 不做收益百分比。

| 维度 | 指标 |
|---|---|
| 工作量 | XML 字节读取、Reader/Binder、静态 Format/Parse、FontFamily 构造及依赖内部解析、算法/evaluator、字典工厂、通知与缓存 hit/miss 次数 |
| 启动 | Main→完整 chrome 帧/可观测 compositor 批次、框架完成、Shell 就绪、最大 UI 连续占用 |
| 动态 | 根/局部切换、字体/主色变更、首次控件结果查询和首个新控件的延迟 |
| 分配/保留 | 临时与保留对象、key/source/binding/cell 字节估算、缓存驱逐、实际对象回收 |
| 产物 | 构建时间、增量构建、生成代码/数据大小、链接保留范围、首次 JIT 与静态初始化成本 |

必须单独证明：编译支持域的 XML Reader/名字与值 Binder 和静态字符串转换为零；实际 registry 的契约绑定仍单独计费；
此处零转换不包含已批准的 FontFamily 标准构造内部解析，其边界见[字体构造例外](compilation.md#32-支持的值生成)；
枚举元数据不物化主题；
全局可复用且无 Own 消费及控件局部 Global 重算需求时不恢复 builder；损坏产物及时失败。保留现有[资源查询热路径要求](../runtime.md#184-资源查询热路径)：已物化后的
TryGetResource 命中保持 0 B/op，资源通知遵守最小通知前沿，每个受影响 Provider/独立资源根至多通知一次。

收益判定同时考虑启动、动态交互和空间成本。算法执行成本仍属于运行时，不能将消除 XML 解析表述为省去了
派生计算，也不能用“生成代码更直接”替代测量。

## 8. 当前验证状态

本次范围已收敛为 XML 声明到强类型 C# 注册与默认赋值，构建期只执行校验、字面量解析和代码生成。
Core 默认 DaybreakBlue 与 Gallery 四款主题保留统一编译注册；派生算法只在运行时执行。
私有构建传输当前为版本 4，包含真实 Core codec 的规范值；运行时生成 ABI 保持 v1，并增补按控件分段入口。
