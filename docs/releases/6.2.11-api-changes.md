# AtomUI 6.2.11 migration guide

[简体中文](6.2.11-api-changes.zh-CN.md)

6.2.11 adds source-backed DataGrid editing and repairs scrolling, row reordering, frozen-column layout and detached
subscriptions. It also changes FloatButtonGroup interaction semantics and replaces the Gallery packaging toolchain.
Avalonia remains 12.1.4; Release runtime packages continue to target net8.0 and net10.0, with the existing SDK requirements.

## Quick reference

| Area | 6.2.10 | 6.2.11 / migration |
| --- | --- | --- |
| FloatButtonGroup state | A local/bound `IsOpen` could prevent trigger-driven state updates | Interactions update the current value; use a TwoWay binding and remove duplicate manual toggles |
| FloatButtonGroup events | `Clicked`, `Opened`, `Closed` were declared but not raised | Declared events now fire; review handlers that assumed they never ran |
| DataGridFieldSchema | Constructor ends in optional `displayAccessor` | Adds optional `isEditable`; rebuild binary consumers and opt writable fields in |
| Local field and descriptor | Constructors/`Field(...)` end in `propertyChangedName` | Add `setter`/`fromScalar`; rebuild consumers and provide a setter for editable fields |
| Generated registration groups | Names encode the 6.2.10 assembly identity | Names encode 6.2.11; upgrade the package set and rebuild generated consumers |
| Gallery packaging | External AtomUITools and `EnsureAppImageLauncher.ps1` | Repository-owned AppImage/DMG/zip scripts; migrate custom packaging invocations |

## FloatButtonGroup state and events

Trigger interactions now write `IsOpen` with current-value semantics, including when a local value or binding exists.
Setting `IsOpen="True"` once no longer pins a click-triggered group open. Disabled groups ignore trigger interactions.

Use the existing TwoWay state contract:

```xml
<atom:FloatButtonGroup Trigger="Click"
                      IsOpen="{Binding IsMenuOpen, Mode=TwoWay}"
                      Opened="HandleMenuOpened"
                      Closed="HandleMenuClosed" />
```

Remove event handlers that toggle `IsOpen` a second time to compensate for the old behavior. `Clicked` now reports
the trigger click; `Opened` and `Closed` report actual state transitions, including programmatic changes. Existing
handlers can therefore start running after upgrading and must not duplicate state changes or business actions.

## DataGrid editing and binary signatures

The optional parameters added to `DataGridFieldSchema`, `DataGridLocalField<T,TValue>` and both generic descriptor
`Field<TValue>` overloads change their IL signatures. Existing source calls that omit the new arguments still compile,
but previously compiled consumers need rebuilding; replacing package DLLs alone is insufficient.

Cell and row editing commit through `IDataGridEditableSource`. A field is read-only unless its schema has
`IsEditable=true`; setting only a column's `IsReadOnly=false` does not make the source field writable. A local field
with a setter marks its schema editable automatically:

```csharp
var nameField = new DataGridFieldId("name");
var descriptor = DataGridLocalSourceDescriptor.For<Row>(
    static row => DataGridRowKey.FromInt64(row.Id))
    .Field(nameField, static row => row.Name, StringComparer.Ordinal,
        setter: static (row, value) => row.Name = value);
var source = DataGridLocalSource.Create(rows, descriptor);
```

Custom sources must mark writable fields in `DataGridFieldSchema` with `isEditable: true` and implement the existing
`CommitAsync` contract. Bind each editable column to its `FieldId`. Supply `fromScalar` when the built-in scalar
conversion does not represent the field type. Invalid conversion keeps the editor open; row Save submits the editable
fields together, and Cancel discards pending editor values instead of directly changing the data item.

## Generated registration identities

Generated `AtomUI.Generated.*.ControlPackageGroup_*` names incorporate the assembly identity and therefore change
with 6.2.11. Upgrade related AtomUI packages and any explicit Generator reference together, clean and rebuild custom
control packages and applications, and republish trimmed/NativeAOT applications. Do not reference generated group
names directly or mix compiled 6.2.10 registration metadata with the 6.2.11 package set.

## Gallery packaging calls

The removed `controlgallery/AtomUIGallery.Desktop/scripts/EnsureAppImageLauncher.ps1` is no longer an entry point.
Custom workflows should publish through `PublishToLocal.ps1`, then use the appropriate script under
`controlgallery/AtomUIGallery.Desktop/scripts/packaging/`:

- `New-GalleryZip.ps1`: Windows zip.
- `New-GalleryAppImage.ps1`: Linux AppImage, including the launcher and icon setup.
- `New-GalleryDmg.ps1`: macOS app bundle/DMG and signing.

Example on a Linux build host, after publishing into `$publishRoot`:

```powershell
& ./controlgallery/AtomUIGallery.Desktop/scripts/packaging/New-GalleryAppImage.ps1 `
    -ConfigPath "$publishRoot/config/InstallerConfig.xml" `
    -PackagesPath "$publishRoot/packages" `
    -OutputPath "$artifactRoot" -Runtime linux-x64 -BuildStamp 1101
```

Use one `BuildStamp` for all platforms in a publication; CI requires it. Review download scripts against the new
artifact naming scheme, for example `AtomUIGallery-6.2.11.1101-win-x64.zip`. macOS release packaging requires an
explicit signing identity with `-RequireSignature`. Windows, Linux and macOS packages must be built on their matching
hosts; the script guards are intentional. See the [Gallery release workflow](../engineering/workflows/gallery-aot-release-workflow.md).

## Compatible fixes and supported Mono targets

DataGrid row movement now preserves the viewport position instead of following the old first row. Ordinary external
data invalidation continues to preserve the content anchor. Right-frozen column resize handles adjust their own column.
These corrections require no new control configuration.

The TypeMap materialization backend now also covers supported linked iOS/Android Mono applications, including iOS
partial linking. Browser full-trim conditions and ordinary non-trimmed/copy behavior remain; the change does not add
a desktop SDK or target-framework requirement. Platform-specific host, signing and deployment validation remains
separate from ordinary library builds.

## Package validation

All 21 release packages were compared against the published 6.2.10 packages. The comparison reports 18 diagnostics
across net8.0 and net10.0, with no unresolved-reference diagnostic:

| Diagnostic | Count | Cause |
| --- | --- | --- |
| `CP0001` | 10 | Versioned registration groups in Controls, Desktop.Controls, GalleryBase, DataGrid and ColorPicker |
| `CP0002` | 8 | DataGridFieldSchema constructor, DataGridLocalField constructor, and both descriptor Field overloads |

The other 16 packages report no API difference. The historical API gate correctly fails for the documented binary
changes; no suppression is added and this release does not claim binary compatibility with 6.2.10. As in 6.2.10,
the normal publication build uses no historical API baseline, while retaining this comparison as release evidence.
All 21 package layouts match 6.2.10, without a layout allowlist change; normal Release pack and target-framework
validation succeed for all 21 packages.
